## 3. 906 生成契约

每个样式使用四张独立源图，每次 `n=1`、平台档位 `1K`。小通知和普通通知虽然同为 21:9，仍分别使用各自的提示词和源图。三种样式全部制作时合计十二张；脚本每次只处理明确指定的一个尺寸。

| key | 成品尺寸 | 源图比例 |
| :---: | :---: | :---: |
| small | 970×160 | 21:9 |
| normal | 970×265 | 21:9 |
| large | 970×625 | 3:2 |
| floating | 975×500 | 2:1 |

支持 `legacy_full_bleed`、`dual_focus`、`scene_fusion` 三种样式，以及计划指定的 Flare 或 Sunburst。实际运行会核对网页对应选项，不静默切换模型。

文生图使用计划中的通用品类提示词，不携带品牌包。图生图使用完整应用元数据、官方 Logo 和五张不同的 Google Play 商店截图。六图按固定角色和顺序上传；清单、来源、尺寸、哈希或正文不一致时停止。仅抓取时间和缓存标记不同不会视为素材变更。

完整文案、Logo 与 CTA 由生成模型负责。四张源图收齐后调用 PushLab 原有 `aitak906 crop`，只做等比缩放、裁切和 PNG 保存；不在本地叠字或绘制按钮。`1K` 是平台档位，不承诺固定的源图像素尺寸。

## 4. 登录与控制方式

2026-11-03 的实际检查发现 aiTak 的应用登录信息位于当前页面会话中。将普通 `storageState` 加载到新浏览器后，仍会进入飞书授权页。因此当前实现保留一个持续运行的命名浏览器，由后续命令复用同一页面，不提取 aiTak Token，也不把会话存储改装成私有接口凭据。

运行前需要已有 Node、Playwright 和 Edge，以及当前账号可访问的 aiTak 页面；裁切另需可运行 PushLab `aitak906` 模块的 Python 环境。脚本不自动安装依赖或下载浏览器。可用 `AITAK_PLAYWRIGHT_MODULE`、`AITAK_BROWSER_EXECUTABLE` 指定本机现有路径。

使用流程：

1. 在 AI 仓库根目录运行 `node scripts/aitak-906-playwright.mjs login --headed`，本人在 Edge 中完成飞书登录和授权。
2. 出现“命名浏览器已就绪”后，保持该终端与浏览器运行。在另一终端运行 `inspect`，确认当前表单可读。
3. 用 `prepare` 指定计划、样式、尺寸和参考包。它会替换当前未提交表单，填写并回读全部参数，停在生成按钮前。`prepare` 会上传参考图，但不会触发生图。
4. 确认本张内容后，使用同样参数运行 `run --submit`，明确提交一张图片并等待结果。该命令会消耗平台额度。
5. 如等待中断，使用 `collect` 核对原任务，不再次运行生成。原卡片不在当前页面时，先通过网页历史打开对应话题。
6. 同一样式四图均下载后运行 `crop`。如需进入 PushLab 工作台，使用原有“导入源图”入口，按样式和 key 导入已下载的四张源图。

所有完整命令和可替换路径见[使用说明](../scripts/aitak-906-playwright.md)。公开说明使用路径占位符，使用者需要换成本机真实计划和参考包。

## 5. 重复提交与异常处理

点击生成前，脚本以排他方式创建该源图的提交记录，初始状态为 `uncertain`。取得网页上唯一的新任务号后记录为 `submitted`；下载完成并计算哈希后记录为 `downloaded`。

- 同一计划、样式和尺寸已有记录时拒绝再次提交，包括失败和结果不明的记录。
- 点击后没有拿到唯一任务号时保留 `uncertain`，需要人工核对平台历史，不自动补发。
- `collect` 根据原任务号读取当前页面卡片和下载结果；不点击生成、不自动重新发起任务。
- 锁仍由活动进程持有时停止。进程意外结束后，先核对 PID，再处理遗留锁；不要删除活动锁或提交记录。
- 计划内容发生变化会产生不同的运行目录；防重提不是跨计划、跨电脑的全局去重。已有任务未核对完前，不应通过修改计划或删除目录绕开记录。
- 手工点击网页生成不属于脚本提交记录管理范围。正式脚本任务统一使用 `run --submit`。

登录和授权由本人在浏览器完成。认证文件不输出到日志，也不提交、上传或同步；普通 Playwright 状态文件保存不等于跨进程免授权已验证。
