# IAA 广告变现入门到精通 · 学习文档

> 面向工具/实用类 App 的**应用内广告变现（In-App Advertising）**。
> 基于 `iaa-monetization-expert` v1.3.5，涵盖 AdMob、MAX、穿山甲、TopOn 等平台。
> 读完你应能：看懂变现数据看板、设计广告位、配置聚合瀑布流、诊断收益异常。

**数据来源：** `[1]` 穿山甲官方 · `[2]` 36氪 AppLovin · `[3]` TopOn 帮助中心。未标记为通用概念/公式。

---

## 0. 一张图理解整个生意

工具 App 靠广告赚钱。核心公式只有一个：

```
广告收益 = 展示次数 × eCPM / 1000
```

- **eCPM** = 每千次展示收益，变现健康度第一指标
- 两个杠杆：做大展示次数、抬高 eCPM，但都被**留存和体验**制约
- 核心命题：在收益和留存之间找让 **LTV 最大**的线

## 1. 拆解收益树

```
                          总收益
                            │
            ┌───────────────┴───────────────┐
           DAU                          人均收益
            │                               │
                            ┌────────────────┴────────────────┐
                      人均展示次数                            eCPM
                            │                                 │
        ┌──────────┬────────┴────────┬──────────┐    ┌────────┴────────┐
     请求渗透率  人均请求PV        填充率      展示率  广告主出价  CTR×CVR
```

**叶子定位法：** 收益涨跌必落在某片叶子上。诊断 = 自顶向下走树，找到动了的那片。

| 叶子 | 你能控吗 | 杠杆 |
|------|---------|------|
| DAU | ❌ 间接 | 投放/自然量/留存 |
| 请求渗透率 | ✅ 高 | SDK 初始化成功率、代码路径覆盖率 |
| 人均请求PV | ✅ 高 | 广告位数量、场景触发频率 |
| 填充率 | ✅ 高 | 瀑布流配置、底价、广告源质量 |
| 展示率 | ✅ 高 | 预加载、缓存管理、UI 遮挡 |
| eCPM（出价×CTR×CVR） | ⚠️ 部分 | 广告位设计、用户质量、季节/节点 |

## 2. 广告形式 — 工具 App 场景

| 形式 | eCPM 量级（相对） | 工具最佳场景 | 禁忌 |
|------|-----------------|-------------|------|
| **激励视频** | 最高 | 解锁额外次数、去水印、跳过等待 | 奖励无价值 = 零完成率 |
| **插屏** | 中 | 任务完成后（扫描完、转换完、清理完） | 启动时弹 = 卸载；操作中弹 = 打断 |
| **Banner** | 最低 | 底部常驻（计算器、转换器、文件列表） | 需要精确触控的页面 |
| **原生/信息流** | 中 | 有内容流的工具（天气、资讯） | 纯工具缺少内容库存 |

**频次原则：**
- 短平快产品 → 广告前置，高频
- 长留体验产品 → 广告后置，低频
- 开屏 eCPM 最高但可操控空间小 → 依赖用户质量，优化在投放端

## 3. 广告位设计 — 按 App 类型

| App 类型 | 主力广告位 | 辅助 | 禁止 |
|----------|-----------|------|------|
| 清理/优化 | 插屏（清理完成后） | Banner（结果页） | 扫描中插广告 |
| 文件管理 | Banner（文件列表） | 插屏（复制/移动完成） | 文件操作中插广告 |
| 计算器 | 底部 Banner | 插屏（按=号后） | 遮挡输入区 |
| 转换器 | 插屏（转换完成后） | Banner（结果页） | 遮挡输出结果 |
| 扫描/QR | 插屏（扫描完成后） | Banner（历史页） | 相机前插广告 |
| VPN | 激励视频（换高级节点） | 插屏（断开时） | 连接中插广告 |
| 天气 | Banner（预报页） | 原生（列表信息流） | 启动时插屏 |

**设计原则：**
1. 任务完成边界 — 插屏只在任务完成后，不在进行中
2. 可预测性 — 用户学会预期广告位置，随机 = 烦躁
3. 首session克制 — 首session尽量少插屏甚至不插屏
4. 高价值广告前置 — 首广告位和首激励视频 eCPM 最高，放在用户入口处
5. 退场广告 — 按返回键弹广告赚流失用户的钱，但加速流失 → 强留存产品慎用

## 5. 聚合：Waterfall vs Bidding

### Waterfall（瀑布流）

按 eCPM 从高到低串行请求，直到填充。

**结构（TopOn 参考）[3]：**

| 区间 | 配置 | 层数 |
|------|------|------|
| Bidding 并行池 | A/B/C/D竞价源 | 2-4 |
| Head（高价区） | 单网高价 | 2-4 |
| Mid（中等区） | 交叉排序，$70→$20 | 2-8 |
| Tail（兜底区） | 低价 + 无底价自动出价兜底 | 2-6 |

**分层管理：**
- 总量：T1 地区 30-40 层，T2 20-30 层，T3 10-20 层
- 目标：整体填充率 ≥90%，每层填充 ≥1%
- 如果某高价层填充 ≥10%，尝试提价或在上方加更高层
- 开屏例外：≤5 层，避免层级过多错过曝光窗口
- 新上线：先跑 2-3 天粗分层，≥2000 次展示/层后按实测 eCPM 调优

### In-App Bidding（竞价）

所有网络同时出价，最高价胜出。

**优势：** 零瀑布延迟、最优出清价、配置简单。
**劣势：** 需要网络支持（AdMob/Meta/Pangle/Unity/ironSource/AppLovin 已全支持），国内推进较慢。

**竞价底价警告 [3]：** 设底价 = 过滤低于底价的出价 → 直接降低竞价填充率与收益。爬坡期不设底价。

### Hybrid（推荐默认）

竞价池 + 瀑布流兜底：

```
[竞价池: AdMob | Meta | AppLovin | Pangle]
      ↓ 不填充
[瀑布流: ironSource | Unity | Mintegral]
      ↓
[兜底广告 / 无填充行为]
```

## 6. 核心聚合机制 [3]

### 排序价格 vs 底价

- **排序价格**：仅控制请求/展示优先级，不管填充。有底价权限时设为网络后台的底价；无权限时设合理估值并开自动价格。
- **自动价格**：按近 7 天平均 eCPM 自动调排序价（需 Report-API + ≥2000 累计展示）。

### 并行请求

- 同时发 N 条请求，非串行。2-3 条即可，**≤5 条**。
- 并行只影响请求，不影响展示顺序（高价仍先展示）。
- 过多 = 请求多展示少 → 平台判定利用率低 → 代码位降权。

### 兜底广告（错峰并行）

兜底源与瀑布流**并行**跑（非串行在最后）：瀑布填充了用瀑布的，没填充用兜底的。提升整体填充。

### 流量分组

按 geo/渠道/设备/系统版本/用户价值等维度分组，每组独立瀑布流。
- **默认分组不能关闭，必须有有效广告源** — 否则不匹配的流量全丢。
- 优先级：精确在前（"美国"组在"美洲"组上方）。

### 展示频次控制

两层独立控制：广告位级 × 广告源级（每小时/每天上限 + 间隔秒数）。
- 新上线时给 Meta/AdMob 设展示上限（防异常设备触发封号）。
- 源级间隔降低重复率。

## 7. 漏斗分析 — 最实用的诊断工具 [3]

```
应用启动 (SDK init)
   ↓ 获取策略到达率
获取策略 (fetch ad config)
   ↓
流量请求 (ad request)
   ↓ 流量填充率 = 填充 / 请求
流量填充 (fill)
   ↓
到达广告场景 (reach ad scenario)
   ↓ 广告Ready率
触发展示 (trigger show)
   ↓ 触发展示成功率
展示 (impression)
   ↓ 点击率
点击 (click)
```

| 漏点 | 可能原因 | 修法 |
|------|---------|------|
| 获取策略低 | SDK 初始化/配置拉取失败 | 加预加载逻辑，考虑全自动加载 |
| 填充率低 | 瀑布太浅 / 底价太高 / 网络故障 | 加无底价兜底层或 backup；排查逐源错误日志 |
| Ready率低但填充高 | 广告未预加载到位 | 在场景合适时机预加载 |
| Ready率低且填充低 | 瀑布配置问题 | 加兜底层，诊断无填充 |
| 场景到达率低 | 广告位埋太深 | 往主路径迁移 |
| 触发率低（激励视频） | 奖励不够吸引人 | 强化激励价值 |
| 展示成功率低 | 缓存过期/渲染失败/UI 遮挡 | 查错误日志、缓存有效期、UI 遮挡 |

**诊断恒等式：** 人均展示 = 人均请求 × 填充率 × 展示率。展示波动必落在三者之一。

## 8. eCPM 优化三节点 [1]

```
收益 = 广告请求 × 填充率 × 展示率 × 点击率 × 转化率 × 广告主出价
                                   ↑         ↑         ↑
                               展示率     点击率    转化率
```

### 节点一：展示率
- 广告位放主路径（一级页面 > 三四级页面）
- 预加载缓存（时机要对：首页→启动加载，结算页→开始操作后加载）
- 注意有效期：穿山甲开屏 3h / 其他 1h [1]，过期展示不计入收益

### 节点二：点击率
- 广告元素完整显示（icon/标题/描述/图片/logo/标识）
- 合理扩大广告尺寸（不侵占内容空间）
- 每个元素可点击，扩大点击区域

### 节点三：转化率
- SDK 初始化时允许 WiFi+4G/5G 直下载 [1]
- **Android：下载完成后自动弹安装提示 → 转化率可提升 3 倍以上 [1]**（性价比最高）
- 使用创意区域（Creative Area）缩短转化路径，点击即下载

## 9. 数据口径：API（结算） vs SDK（统计）[3]

**这是最容易犯的错：把两个口径混为一谈。**

| 口径 | 来源 | 用途 | 局限 |
|------|------|------|------|
| **API 数据**（收益API、eCPM API、展示API） | 各网络 Report-API 拉取 | **结算级**，对账唯一依据 | 次日延迟，部分网络不支持请求/填充 |
| **SDK 统计**（展示、点击、请求、填充率、DAU） | 聚合 SDK 客户端实时埋点 | **实时分析**，漏斗/分用户/频次 | 估算值，非结算数 |

**展示Gap = (SDK展示 − 展示API) / 展示API。0-15% 正常。>15% 排查 [3]：**
- 展示API > SDK展示 → 有旧版本/重复代码位在 SDK 外展示
- 展示API < SDK展示 → SDK 统计的展示被平台判定为无效（覆盖不足、时长不够等）

## 10. 常见收入问题诊断

### eCPM 下降 30%+

| 查什么 | 怎么查 |
|--------|--------|
| 地区结构变化 | 国家级 DAU 分布，低 eCPM 地区是否放量 |
| 季节性/节点 | 季末/618/双11 = 预算冲刺涨；1月/节后 = 跌 |
| 新版本 | 分版本对比 eCPM，确认是版本引入还是外部因素 |
| 代码位变化 | 是否新增代码位导致单代码位展示稀释 |
| 政策违规 | AdMob 政策中心是否有广告投放限制标记 |
| 用户质量 | 投放端用户构成变化（机型/年龄/地区/渠道） |

### 填充率低于 70%

| 查什么 | 怎么查 |
|--------|--------|
| 底价太高 | 降一档观察 1-2 天 |
| 网络故障 | 逐网络后台查投放量 |
| SDK 版本过旧 | 更新 adapter/SDK |
| 地区配置错误 | T4 地区设了 T1 底价 = 零填充 |
| 频次限制太紧 | 80% 请求被限 → 填充率虚低 |

### ARPDAU 持续下降

**前端（投放/用户侧）：**
- 同渠道不同日期的用户画像差异
- 通投渠道内部位置变化

**后端（产品/变现侧）：**
- 人均展示拆分（渗透率/人均展示/CTR/广告报错）
- eCPM（逐档逐源、分层保价）
- 版本对比（同渠道分版本 → 判断是否版本引入）

### 收益变动 — 自顶向下排查

按收益树自顶向下，每个叶子分前端和后端两面查：

| 叶子 | 前端问题 | 后端问题 |
|------|---------|---------|
| DAU | 买量降、自然量降、流失升 | — |
| 人均请求 | 用户质量/意愿变化 | 频次限制/场景/自动请求/retry 改动？增减广告位？ |
| 填充率 | 用户质量降 → 网络不竞投 | 提底价？去兜底层？某源限流/封禁？季节预算？ |
| 展示率 | 弱网/低端机用户增多 | 改客户端超时？加预加载（正常下降）？并行过多缓存未展示？瀑布太长？ |
| eCPM | 新用户/地区/质量构成变化 | 底价调整、整体展示量变化稀释 bid density |

## 11. 广告运营 SOP

### 产品引入流程

准备（需求表+参数申请+埋点方案并行）→ 广告设计（了解产品+出埋点方案）→ 参数申请 → 广告配置（后台建源，测试/正式区分）→ 出包验收（逐条验证）→ 上线

### 日常 Checklist

- 每日：聚合面板查填充率/eCPM/展示率
- 分广告位分 geo 看人均展示/eCPM
- 单日波动 >20% 排查 [3]
- 新版本上线后密切监控
- 周期性竞品广告设计调研
- 配置数据预警（推荐：App 级预估收益单日波动 >20%）

## 12. 常见误区

1. **只看 eCPM 不看 ARPDAU** — eCPM 涨但展示量跌可能净亏
2. **瀑布配置不更新** — 半年不调的底价是废的，至少周更
3. **广告网络太多** — SDK 体积膨胀、崩溃率上升，每个网要贡献足够收入
4. **忽略地区分布** — 全球平均 eCPM 没意义，T4 地区放量会伪装成 eCPM 下跌
5. **首 session 弹插屏** — D1 流失成本几乎永远大于那一次曝光收入
6. **不限频次** — 短期收益飙升 → 留存崩 → 收益崩
7. **混淆结算与统计口径** — 对账用 API 数据，分析用 SDK 数据
8. **ARPU 下降只看后端** — 可能是投放端用户构成变化
9. **忽视展示率** — 高填充低展示 → 降权 → 填充/eCPM 双跌
10. **不设默认流量分组** — catch-all 是兜底，关了 = 丢量
11. **并行请求太多** — 请求多展示少 → 降权
12. **竞价过早设底价** — 爬坡期不设，稳定后再说
13. **瀑布太长且串行无并行** — 加 2-3 条并行请求减少填充延迟
