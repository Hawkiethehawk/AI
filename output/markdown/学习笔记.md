## 一、核心公式

**收益 = 展示量 × eCPM / 1000**

展开后：

$$
\text{收益} = \text{广告请求} \times \text{填充率} \times \text{展示率} \times \text{点击率} \times \text{转化率} \times \text{广告主出价}
$$

**三大优化节点：展示率 → 点击率 → 转化率**（后面详述）

---

## 二、核心指标体系

### 收入指标

| 指标 | 公式 | 说明 |
|------|------|------|
| eCPM | (收入 / 展示量) × 1000 | 千次展示收益，核心健康指标 |
| ARPU | 收入 / DAU | 每用户平均收入 |
| ARPUDAU | 日收入 / DAU | 最可操作的日频指标 |
| LTV | ARPUDAU × 平均留存天数 | 用户生命周期价值 |

### 交付指标

| 指标 | 健康范围 |
|------|----------|
| 填充率 (Fill Rate) | ≥ 90% |
| 展示率 (Show Rate) | ≥ 85% |
| CTR (Banner) | 0.5–3% |
| CTR (插屏) | 3–10% |
| CTR (激励视频) | 10–30% |
| 填充耗时 (视频) | < 10s |
| 填充耗时 (图片) | < 2s |

### ARPU 完整拆解

$$
\text{ARPU} = \text{人均展示次数} \times \frac{\text{eCPM}}{1000}
$$

$$
\text{人均展示次数} = \text{广告请求渗透率} \times \text{人均请求PV} \times \text{填充率} \times \text{展示率}
$$

**广告请求渗透率**影响因素：SDK 初始化成功率、广告配置获取成功率、广告请求代码执行率

### eCPM 广告主侧拆解

$$
\text{eCPM} = \text{广告主出价} \times \text{CTR} \times \text{CVR} \times 1000
$$

| 因素 | 可控性 | 影响方式 |
|------|--------|----------|
| 广告主出价 | 不可控 | 取决于平台预算池和竞争（618/双11冲高） |
| CTR | 可控 | 广告位置、时机、格式设计、视觉突出度 |
| CVR | 部分可控 | 重度依赖平台；让广告内容更可见可理解 |

## 三、四种广告形式

### Banner
- eCPM: **$0.1–1.5**（最低）
- 适用：持久 UI 表面（底部栏、列表项之间）
- 工具场景：计算器/转换器/文件浏览器底部
- 刷新率：30–120s（过快刷新降低 eCPM）

### Interstitial（插屏）
- eCPM: **$2–8**（中等）
- 适用：页面切换、任务完成、自然断点
- 工具场景：扫描完成后、文件转换后、清理完成后
- **铁律：禁止在应用首屏弹出**（直接导致卸载）
- 频率上限：1次/3–5分钟，每会话最多3–4次

### Rewarded Video（激励视频）
- eCPM: **$5–20**（最高）
- 适用：解锁功能、去除时间限制、高级操作
- 工具场景：解锁额外转换次数、去除水印、跳过等待
- 关键：工具应用没有天然虚拟货币，需创造"合成价值"

### Native（原生广告）
- eCPM: **$1–6**（中等）
- 适用：内容流、列表、推荐
- 工具场景：有内容表面的工具（新闻/天气/推荐），纯工具类难以发挥

## 四、竞价模式

### Waterfall（瀑布流）
- 按 eCPM 排序串行请求
- Floor 设置：7天均值的 80–90%
- 分层：10–20 层 / 每广告位每 geo 3–4 个 tier
- Tier 间隔：约 20%
- 底价越高，填充率越低；底价设置后平台交付 eCPM 往往接近底价
- **每周至少调一次 floor**（配置6个月就过时）

### In-App Bidding（实时竞价）
- 所有网络同时竞价，最高价者胜出
- 零瀑布流延迟、最优出清价、配置更简单
- 局限：需要网络支持 bidding（AdMob/FAN/Pangle/AppLovin 等已支持）
- 国内：实时竞价推广缓慢，受限于平台间竞价协议和数据互通

### Hybrid（推荐默认方案）
```
[Bidding 池: AdMob | FAN | AppLovin | Pangle]
      ↓ 无填充
[Waterfall: ironSource | Unity Ads | Mintegral]
      ↓
[兜底广告 / 无填充行为]
```
- Bidding 池填充率 < 85% 时需要增加网络

### 预加载机制（自建聚合典型逻辑）
- 每条广告源自动缓存 2 条
- 缓存 30 分钟过期
- 单条广告源连续 6 次请求失败后跳过
- 总超时 8 秒
- 全部失败：暂停 30 秒后重试
- 兜底策略：预取最低层广告保底

## 五、变现优化三板斧

### 节点一：展示率

> 让每一次填充都变成有效展示

1. **前移广告位** — 一级页面 >> 三级页面
2. **按场景选择预加载时机**
   - 首页签到 → App 启动时加载
   - 游戏结算页 → 游戏开始后加载
   - 深层页面 → 用户靠近时加载
3. **注意广告有效期** — 穿山甲：开屏 3h，其他 1h；过期展示数据被系统过滤
4. **平衡预加载和展示率** — 过早预加载 → 展示率低 → 系统降权 → 填充率降

### 节点二：点击率

> 扩大尺寸和点击区域，不依赖误点

1. **完整显示广告元素** — icon + 标题 + 描述 + 图片 + logo + 广告标识
2. **所有元素可点击** — 50%+ 的点击来自非按钮元素
3. **扩大尺寸 + 扩大点击区域 + 减小背景板**
4. **不依赖误点** — CTR↑ + CVR↓ = eCPM 不变甚至下降；误点还损害留存

### 节点三：转化率

> 缩短从点击到下载/安装的路径

1. **允许 WiFi + 4G/5G 直接下载**
2. **下载完自动弹安装提示** — 转化率提升 **3倍**（穿山甲数据）
3. **使用创意区域** — 点击直接下载，跳过中间网页
4. **确保跳转链路通畅** — iOS 跳 AppStore / Android 正常下载

## 六、关键平台

### 穿山甲 (CSJ / Pangle-Domestic) [1]
- 字节跳动旗下，国内最大广告联盟
- **产品线**：基础变现 + GroMore（聚合/智能管家）+ 营销投放 + 内容联盟
- 广告有效期：开屏 3h / 其他 1h
- 预加载：每源缓存 2 条，30min 过期，6 次失败跳过
- 工具行业专属解决方案
- 来源：https://www.csjplatform.com/growthcenter/6101274400195d0046c2731d

### AppLovin MAX [2]
- IGA 市场份额 **28%** 全球第一（iOS **43%** 领先）
- **四大模块**：AppDiscovery（投放）+ ALX（交易）+ MAX（竞价）+ Adjust（归因）
- **AXON 2.0 AI 引擎** — 广告匹配效率提升 300%，ROAS 同比 +58%
- **Take rate 50–60%**（vs Unity 30–35%）
- 2025 年出售游戏业务，全面聚焦纯软件平台
- Q2 2025 收入 $12.59 亿（同比 +77%），EBITDA 利润率 81%
- 风险：浑水做空、电商客户流失率 23%、隐私政策收紧
- 来源：https://www.36kr.com/p/3480808267798659

### Google AdMob
- 最大需求池，Android 生态原生优势，内置 mediation

### Meta Audience Network (FAN)
- 高 eCPM，但 iOS ATT 影响严重

### 国内其他
- **优量汇**（腾讯）— 微信/QQ 生态
- **快手广告** — 下沉市场
- **百度联盟** — 搜索流量补充

### TopOn 聚合平台 [3]
- 聚合工具平台（非需求方），一个 SDK 对接 40+ 国内外联盟；自有 **TopOn ADX**（无需单独接 SDK/发版）
- **两套数据口径**：带 API 后缀 = 三方结算口径（次日、权威）；不带 API = SDK 实时统计（估算）。展示Gap = (统计展示−展示API)/展示API，15% 以内正常
- **排序价格 ≠ 底价**：排序价格只决定请求/展示优先级，不影响填充；底价在三方后台。无底价权限时设估算价 + 开自动价格（前7天均值，需≥2000展示生效）
- **兜底广告**：与瀑布流错峰并行，无填充时兜底，提升填充率
- **并行请求**：2–3 条（最多5），过多→请求不展示→代码位降权
- **流量分组**：按 geo/渠道/版本/用户价值等分组配不同 waterfall；默认分组是兜底不可关。T1 30–40层 / T2 20–30层 / T3 10–20层
- **头部竞价 S2S/C2S**：服务端/客户端竞价；竞价底价会降填充，爬坡期别设
- **瀑布流纪律**：整体填充≥90%，每层≥1%；首层≥10%可提底价；按收益占比 vs 展示占比调层
- **漏斗分析**：应用启动→获取策略→请求→填充→到达场景→展示→点击，逐节点转化率定位流失
- **A/B 测试**：看预估口径（API 不分组）；AABB 验证切量均匀；多广告位防辛普森悖论
- **破天花板**：交叉推广（自有产品互导/兜底）+ 直投广告（直客预算直接变现）
- 来源：https://help.toponad.net/cn

## 七、常见问题诊断

| 问题 | 排查方向 |
|------|----------|
| **eCPM 降 30%** | Geo 分布变化 / 节点效应（618、双11 后回落）/ 用户质量下降 / 版本更新 / 政策违规 |
| **填充率 < 70%** | Floor 过高（降 20% 观察 48h）/ 网络故障 / SDK 版本过旧 / Geo 配错 / 频次上限过紧 |
| **ARPU 持续降** | 前端：用户构成变化（机型/年龄/地区/来源）/ 通投渠道内部位置变化；后端：展示拆解 + 分版本对比 |
| **DAU 涨收入不涨** | 新用户 Geo 差 / 新用户 Session 短 / 广告疲劳 / Impression 天花板 |

### ARPU 下跌双侧排查框架

**前端（投放/用户侧）**：
- 用户质量/构成变化（同一渠道每日用户也有差异）
- 通投渠道内部位置变化（昨天抖音位获量，今天站内位获量）
- 用户与应用匹配度下降 → 买量端排查

**后端（产品/变现侧）**：
- 人均展示次数拆解（渗透率、分类型展示/点击、CTR、广告报错）
- 用户数据与广告数据关联（主流程漏斗、关键行为渗透率）
- eCPM（多档多源、分层保价填充率）
- 分版本对比排除产品迭代影响

## 九、关键原则

1. **永远关注 ARPUDAU，不是 eCPM 孤立值** — eCPM↑ 但展示量↓ = 总收入可能更低
2. **每周调 floor** — 配置 6 个月就过时
3. **不同 geo 不同配置** — eCPM 差距 > 3 倍就必须分开
4. **插屏禁首屏，频率 ≤ 1次/3分钟** — 首屏弹广告的留存代价远超收益
5. **展示率是沉默杀手** — 高填充低展示 → 平台降权 → 填充和 eCPM 双降
6. **高价值广告位前置** — 用户进入后首个广告位 eCPM 最高
7. **开屏 eCPM 不可深度优化** — 它反映用户质量，真正的优化杠杆在投放端
8. **预加载不是越早越好** — 过早预加载 → 用户不触发 → 展示率低 → 降权
