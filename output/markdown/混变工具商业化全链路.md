# 混变工具商业化全链路

## 0. 全链路骨架

**混变商业化的本质是一条单向链路，每一环的输出是下一环的输入：**

```
产品功能设计       → 定义可卖资产（广告位 + 付费点）
IAA + IAP 运营    → 把资产变成收入
广告投放          → 用可控成本买来能回收的用户
数据埋点          → 让每一步可测量、可诊断
```

核心判据只有一个：**LTV ≥ CAC**，其中 `LTV = IAA LTV + IAP LTV`。

全文围绕四个问题：
1. 资产怎么预埋进功能设计？
2. 资产怎么分别运营出价？（广告侧 + 订阅侧）
3. 用户花多少钱买回来才划算？
4. 断了怎么沿链路排查？

---

## 1. 链路起点：预埋变现节点

### 1.1 核心错误

最常见的死法：功能全做完了，才问"在哪加广告？在哪收费？"——变现变成产品体验的寄生层。

**正确做法：定义功能时同步定义它的变现属性。** 设计用户操作流程时，每个节点问三个问题：用户会不会接受广告？有没有动力付费跳过？如果都不行，有没有第三条路？

### 1.2 五层设计堆叠（从下往上建）

```
⑤ 体验平衡    ← 商业化有没有过度？同一会话不同时触发广告+付费
④ 付费引导    ← 什么时候弹 paywall？转化最高的是"用量撞墙"
③ 广告嵌入    ← 广告插在任务的"自然断点"，而非任务进行中
② 功能切分    ← 免费必给 / 广告解锁 / 付费专属
① 用户分层    ← 免费用 → 看广告 / 潜在付费 → 精准引导 / 已付费 → 零广告
```

第①层决定一切——不分层就嵌入广告，等于对已付费用户也塞广告。

### 1.3 功能切分：将产品拆成三个版本

```
免费必给  = 不给就卸载 → 留住人
广告解锁  = 看个广告也能忍 → 产生 IAA
付费专属  = 真愿意掏钱 → 产生 IAP
```

工具类首选**混合切分**：基础免费 + 部分广告解锁 + 少量付费专属 + 付费同时去广告。关键原则：免费部分必须够好，否则用户还没感知价值就走了。

## 2. IAA：把广告机会卖出最高价

### 2.1 收益树：诊断第一问——量降还是价降？

```
广告收入 = DAU × ARPDAU
ARPDAU = (请求渗透率 × 人均请求PV × 填充率 × 展示率) × eCPM/1000
```

### 2.2 广告链路与诊断

```
初始化 → 策略 → 请求 → 填充 → 到达场景 → Ready → 展示 → 点击
```

| 节点掉 | 方向 | 动作 |
|-------|------|------|
| 请求低 | 用户没到场景/频控过严 | 回看产品路径 |
| 填充低 | 底价高/广告源少/预算波动 | 拆平台/国家 |
| Ready低 | 预加载太晚/缓存失效 | 调加载时机 |
| 展示低 | show 失败/UI 遮挡 | 查展示回调 |
| 点击低 | 样式/位置问题 | 优化创意 |

### 2.3 调度进化路径

`并行(保填充) → 瀑布(保价格) → Hybrid 竞价+兜底`

基础链路（请求→ready→展示→口径）没拉通之前，别急着上复杂调度。

### 2.4 收入波动的两个方向

- **平台预算波动**：多产品/多广告位同时波动，节假日明显 → 扩广告源
- **用户质量下降**：同平台不同渠道 eCPM 差异大，新增变了收入就变 → 回买量端查渠道

> 开屏 eCPM 几乎不可操作，是所有广告位里最纯粹的用户质量信号。

## 3. IAP：把付费意愿变成续订收入

### 3.1 LTV 分解树

```
IAP LTV = 付费墙触达率 × 购买启动率 × 试用转付费率 × Σ(续订留存 × 净单价)
```

运营核心动作：沿这棵树找到"哪片叶子动了"。

### 3.2 三层口径（不可混用）

| 口径 | 用途 | 限制 |
|------|------|------|
| 客户端购买事件 | 实时漏斗/排障 | 可能重复、未校验 |
| 服务端订阅状态 | 权益/续费/退款 | 状态机复杂有延迟 |
| 商店结算收入 | 对账/净LTV | 滞后 |

路径：`purchase_success → 票据校验 → 权益发放 → 状态更新 → 结算确认`。别在第一步就下结论。

### 3.3 付费墙与订阅状态机

最有效的付费墙是**情境付费墙**（撞额度/点功能时弹出），前提是用户已积累使用价值。

```
未订阅 → 试用 → 有效 → 续费成功/失败 → 宽限期/过期 → 退款/取消
```

**主动流失**（用户取消）是产品价值问题；**被动流失**（扣款失败）是支付问题，可通过 billing retry/grace period 挽回。二者解法完全不同，混为一谈是最大诊断失误。

### 3.4 A/B 测试

主指标：净 LTV/MRR。过程指标：漏斗各节点。护栏：退款率、取消率、留存、投诉。订阅测试有长尾，D0 不是终点。

## 4. 投放：用可控成本买能回收的用户

### 4.1 判据与漏斗

```
投放成立 = LTV ≥ CAC
CAC = 花费 / 有效新增用户
ROAS = 已回收收入 / 投放花费
LTV = IAA LTV + IAP LTV - 退款/税费
```

漏斗：`预算 → 展示 → 点击 → 商店页 → 安装 → 激活 → 变现触点 → 收入 → 回收`

### 4.2 三个关键认知

1. **低 CPI ≠ 好投放**。低 CPI 可能来自低价值地区或误点素材。判断顺序：`CPI → 激活成本 → 收入 → 留存 → LTV → ROAS`
2. **平台算法吃什么就优化什么**。只回传 install → 找容易安装的人；回传收入事件 → 找能回收的人。至少分浅/中/深三层回传。
3. **投放和变现必须数据互通**。投放侧只看安装、变现侧只看收入 → 互相误判。最小 ROI 模型：每个用户的来源、成本、广告收入、订阅收入放进同一 cohort 算 LTV/CAC。

### 4.3 诊断

- ROAS 降 → 先拆成本还是 LTV 降
- 安装涨收入不涨 → 查渠道结构、素材是否引入低意图用户
- 短期 ROAS 很高 → 别急放大，确认归因窗口、小样本偏差、是否吃自然量

## 5. 数据埋点：让全链路可解释

### 5.1 唯一目标

**每次收入波动都能拆到用户、场景、广告、付费、渠道、版本中的某个具体原因。**

### 5.2 四类口径（不可混用）

| 口径 | 用途 | 不能当什么用 |
|------|------|------------|
| 客户端行为事件 | 漏斗/排障 | 收入结论 |
| 广告收入事件 | 近实时估算 | 结算收入 |
| 订阅/支付状态 | 权益/续费 | 实时指标 |
| 归因/成本 | ROI/渠道 | 财务对账 |

### 5.3 六类事件 + 三条漏斗

**六类事件：** 生命周期 → 核心任务 → 广告链路 → 付费链路 → 订阅状态 → 实验配置

**三条漏斗（按依赖关系从上到下）：**

```
核心任务漏斗：open → task_start → complete → result
    ↓ 决定上游流量
广告漏斗：scene_enter → request → load → show → impression → revenue
付费漏斗：paywall_show → click → purchase → entitlement → renewal
```

> 付费墙曝光下降，可能不是付费墙问题，而是核心任务完成率下降——用户根本没走到触发场景。

### 5.4 收入波动诊断 SOP

```
总收入下降
├─ IAA？ 场景到达 → 填充/展示 → eCPM
└─ IAP？ paywall 曝光 → 转化 → 续费/退款

ROI 下降 → 先拆 CAC 还是 LTV → 再拆归因窗口/延迟/渠道结构
```

## 7. 常见误区

- **产品：** 先做功能后变现；不分层；广告打断核心任务；Paywall 只标价格不说价值
- **IAA：** 只看 eCPM 不看量；SDK 统计当收入；预加载越早越好；变现和买量割裂
- **IAP：** 购买成功当收入；只追转化不看续费退款；不分主动/被动流失；试用期不送达价值
- **投放：** 低 CPI 崇拜；只用 install 优化；渠道命名混乱；SKAN 当实时归因
- **数据：** 事件越多越好；只埋成功不埋失败；没有 paywall_id/experiment_id；自然日和 cohort 混用

## 全文总结

混变工具的商业化不是四个独立模块，而是**一条单向链路**：产品功能设计预埋出可卖资产，IAA/IAP 把资产运营成收入，投放用可控成本买来能回收的用户，数据埋点让每一步可测量、可诊断。每一环的输出都是下一环的输入，**断在任何一环，后面全废**。

贯穿全文的判据只有一个：**LTV ≥ CAC**，其中 `LTV = IAA LTV + IAP LTV - 损耗`。所有设计、运营、投放动作，最终都要回到这个不等式上。

四个关键认知串起整条链路：

- **产品端**——变现属性必须在设计功能时同步定义，而非事后加塞。先用户分层，再功能切分（免费必给／广告解锁／付费专属），广告嵌在自然断点，paywall 卡在"用量撞墙"的情境，最后校验体验是否过度。
- **IAA 端**——诊断永远先分"量降还是价降"（收益树），再沿广告链路逐节点定位；开屏 eCPM 是最纯粹的用户质量信号。
- **IAP 端**——沿 LTV 分解树找动了的那片叶子；最致命的诊断失误是把**主动流失（产品价值问题）和被动流失（支付问题）**混为一谈，二者解法完全不同。
- **投放与数据端**——低 CPI ≠ 好投放，判断要走到 LTV／ROAS；投放与变现必须数据互通，否则互相误判。埋点的唯一目标，是让每次收入波动都能拆到用户／场景／广告／付费／渠道／版本中的某个具体原因，且四类口径绝不混用。

一句话收束全文：**把链路当成一个整体来设计和诊断**——预埋好资产、运营出最高价、买来能回收的人、用数据把全链路变得可解释，收入波动时才能沿链路一节一节排查，而不是头痛医头。
