# 广告投放 · 移动应用买量与增长回收 · 学习文档

> 面向工具类 App 商业化运营 / 增长运营同学：默认你已知道曝光、点击、安装、留存、ROI/ROAS 的基础含义，本文从“如何把买量当成商业化经营的一部分”开始讲。
> 本文不是广告平台开户教程，而是一条可从头读到尾的学习路径：先建立买量回收漏斗，再学会用事件、归因和 LTV 判断投放是否值得继续放大。
> 读完你应该能：拆解投放 ROI；理解 Google/Meta/TikTok/Apple Ads 的优化逻辑；和 IAA/IAP 变现数据对齐；识别归因和 SKAN 口径陷阱。

> **📌 数据来源标记（全文通用）：** [[1]](https://support.google.com/google-ads/answer/6247380?hl=en) = Google App campaigns · [[2]](https://developers.facebook.com/docs/app-ads/) = Meta App Ads · [[3]](https://ads.tiktok.com/business/en/products/performance) = TikTok Performance · [[4]](https://ads.apple.com/app-store) = Apple Ads · [[5]](https://support.appsflyer.com/hc/en-us/articles/207447163-Attribution-overview) = AppsFlyer Attribution · [[6]](https://help.adjust.com/en/article/attribution-methods) = Adjust Attribution · [[7]](https://help.adjust.com/en/article/skadnetwork) = Adjust SKAN。完整清单见文末「数据来源」。

## 0. 一句话理解

广告投放不是“买安装”，而是用可控成本买来一批未来能回收的用户。

```text
投放是否成立 = LTV ≥ CAC

LTV = 广告 LTV + IAP LTV - 退款 / 成本 / 税费等损耗
CAC = 花费 / 有效新增用户
ROAS = 已回收收入 / 投放花费
```

> 🧭 **贯穿全文的一句话**：买量运营的核心不是把 CPI 压低，而是在可归因、可回收、可放大的前提下，让 LTV/CAC 持续大于 1。

## 1. 买量回收漏斗：投放的主脊柱

```text
预算
→ 展示
→ 点击
→ 商店页访问
→ 安装
→ 首次打开
→ 激活 / 完成核心任务
→ 广告展示 / 付费墙曝光
→ IAA / IAP 收入
→ 留存与复购
→ 回收投放成本
```

每一段都有对应问题：

| 漏斗段 | 运营问题 | 主要责任方 |
|---|---|---|
| 预算 → 展示 | 能否拿到足够流量 | 投放平台 / 出价 |
| 展示 → 点击 | 素材是否吸引目标用户 | 素材 / 定向 |
| 点击 → 安装 | 商店页是否承接 | ASO / 商店素材 |
| 安装 → 激活 | 用户是否真的需要产品 | 产品 / onboarding |
| 激活 → 收入 | 变现路径是否顺 | 商业化 / 产品 |
| 收入 → 回收 | LTV 是否覆盖 CAC | 商业化 / 增长 |

Google App campaigns 会基于广告主提供的文本、素材、预算和出价，在 Google 多个资产中自动组合和优化投放 [[1]](https://support.google.com/google-ads/answer/6247380?hl=en)。这意味着运营不能只盯账户层点击率，还必须把安装后的事件和收入回传给系统。

---

## 2. 第一大坑：低 CPI 不等于好投放

低 CPI 可能来自低价值地区、低意图用户、误点素材、奖励流量或商店页不匹配。它只说明“安装便宜”，不说明“能回收”。

正确判断顺序：

```text
CPI → 激活成本 CPA → 付费/广告收入 → 留存 → LTV → ROAS
```

> ⚠️ 第一个大坑：用 CPI 做最终目标。工具产品尤其容易买到“装了就走”的用户；如果 D0 广告展示、D1 留存、付费墙触达都差，CPI 再低也可能亏。

---

## 3. 平台角色：不同平台买的不是同一种流量

### Google App campaigns

Google App campaigns 覆盖 Search、Google Play、YouTube、Discover、Display Network 等 Google 资产 [[1]](https://support.google.com/google-ads/answer/6247380?hl=en)。运营重点是：事件回传、价值出价、素材组合、国家和预算结构。

### Meta App Ads

Meta App Ads 面向应用安装和应用内互动，官方文档强调应用配置、SDK / 事件、深链、衡量和优化 [[2]](https://developers.facebook.com/docs/app-ads/)。运营重点是：事件质量、素材迭代、受众和再互动。

### TikTok Performance Ads

TikTok 官方把 performance marketing 定位为以 AI 自动化提升 ROI 的效果广告方案 [[3]](https://ads.tiktok.com/business/en/products/performance)。运营重点是：短视频素材、自动化投放、创意疲劳和转化信号。

### Apple Ads

Apple Ads 在 App Store 的 Today、Search、Search Results、Product Pages 等位置触达用户 [[4]](https://ads.apple.com/app-store)。运营重点是：关键词、搜索意图、商店页承接、ASA 与自然搜索的关系。

## 4. 事件回传：平台算法吃什么，就优化什么

如果只回传 install，平台会找“容易安装”的人；如果回传激活、广告收入、订阅收入，平台才有机会找“能回收”的人。

工具产品建议至少分三层事件：

```text
浅层：install / first_open / onboarding_complete
中层：核心任务完成 / 广告场景到达 / paywall_show
深层：ad_impression_value / trial_start / purchase / renewal
```

> 💡 事件不是越深越好。深层事件价值高但量少，浅层事件量大但不代表收入。投放优化通常需要“量足够的代理事件 + 收入事件校准”。

---

## 5. 归因：把用户、渠道、成本和收入接起来

MMP 的作用不是“给每个安装贴标签”这么简单，而是把点击、安装、深链、渠道参数、应用内事件和收入接成一条可分析链路。AppsFlyer 的归因链接通过参数承载媒体源、campaign、广告组、素材和深链等信息 [[5]](https://support.appsflyer.com/hc/en-us/articles/207447163-Attribution-overview)。Adjust 也把归因定义为将应用用户与带来安装的来源匹配，用于监测推广表现、再营销和优化素材 [[6]](https://help.adjust.com/en/article/attribution-methods)。

基础命名结构：

```text
media_source
campaign
adset / ad_group
creative
country
platform
optimization_event
```

> ⚠️ 命名不规范会直接毁掉后续分析。今天叫 `us_cleaner_pro`，明天叫 `USA-clean`，后天叫 `cleaner-ios-us`，最终 ROI 报表会变成手工清洗工程。

## 6. iOS 隐私与 SKAN：不是实时、不是设备级

iOS 隐私环境下，设备级归因受限，SKAdNetwork / SKAN 成为重要的隐私保护归因框架。Adjust 文档说明 SKAN 不共享设备级数据，且回调存在延迟 [[7]](https://help.adjust.com/en/article/skadnetwork)。

运营上要接受三件事：

1. **延迟**：不能用 SKAN 做分钟级优化。
2. **聚合**：不能像设备级归因那样追单用户路径。
3. **早期信号重要**：需要把 D0 / D1 的关键行为映射成可用于优化的价值信号。

适合工具产品的早期价值信号：

```text
完成首个核心任务
看到首个广告场景
产生首个广告展示收入
触发 paywall
启动试用 / 首购
D1 回访
```

## 7. 素材与商店页：买量不是只在广告后台发生

广告素材负责把人带来，商店页负责让人相信，产品首体验负责让人留下。

常见断点：

| 现象 | 可能问题 | 运营动作 |
|---|---|---|
| CTR 高，安装低 | 素材吸引但商店页不承接 | 改 icon、截图、标题、副标题 |
| 安装高，激活低 | 素材承诺与产品不一致 | 收紧素材卖点，优化 onboarding |
| 激活高，收入低 | 变现触点不顺 | 查广告场景和付费墙触达 |
| 收入高，留存低 | 过度变现或误导 | 降频、改付费墙承诺 |

> 💡 好素材不是“点击率最高”的素材，而是能带来高 LTV 用户的素材。

## 8. 投放诊断：从 ROI 反推

### 8.1 ROAS 下降

```text
ROAS 下降
├─ 成本上升？
│  ├─ CPM / CPC 上升
│  ├─ 竞争加剧
│  └─ 出价策略变化
└─ LTV 下降？
   ├─ 激活下降
   ├─ 广告展示下降
   ├─ eCPM 下降
   ├─ 付费转化下降
   └─ 留存下降
```

### 8.2 安装量上升但收入不涨

优先查：国家结构、渠道位置、素材是否引入低意图用户、产品版本是否变更、广告 / 付费埋点是否正常。

### 8.3 某渠道短期 ROAS 很高

不要马上放大。先确认：归因窗口是否一致、收入口径是否结算、是否有小样本偏差、是否牺牲留存、是否吃了自然量。

## 9. 与商业化协同：买量侧必须吃到 LTV 数据

IAA 产品要回传广告收入，IAP 产品要回传购买、试用、续费和退款；混合变现产品则两者都要回传。

最小可用 ROI 数据模型：

```text
用户 / 设备 / install_id
+ media_source / campaign / creative
+ cost
+ country / platform / app_version
+ ad revenue
+ purchase / subscription revenue
+ refund / churn
+ retention
= cohort LTV / CAC / ROAS
```

> ⚠️ 如果投放侧只看到安装，商业化侧只看到收入，两边都会误判：投放以为量便宜，商业化以为用户质量突然变差。

## 10. 日常 SOP

### 每日看

- 花费、安装、CPI、激活成本。
- D0 广告收入、D0 付费、paywall_show、核心任务完成。
- 分国家、平台、campaign、creative 的早期 ROAS。
- 异常：成本涨、安装降、激活降、收入回传断、归因异常。

### 每周看

- Cohort LTV 与回收周期。
- 素材疲劳：展示、CTR、CVR、CPA 的趋势。
- 渠道结构：哪些国家 / campaign 可放大，哪些只带量不回收。
- 商店页转化与素材卖点是否一致。
- SKAN / MMP / 平台报表差异是否在可解释范围。

### 放量前检查

- 归因链接命名规范。
- 关键事件和收入已回传。
- ROI 看板按 cohort 而不是按自然日混算。
- 有预算止损线。
- 留存和退款是护栏，不只看 D0 ROAS。

## 11. 常见误区

1. **低 CPI 崇拜。** 低成本安装不等于可回收用户。
2. **只用 install 优化。** 平台会找容易安装的人，而不是高价值用户。
3. **渠道命名混乱。** 后续 ROI 分析会失真。
4. **把平台归因当财务真相。** 归因服务于优化，财务要看结算和成本口径。
5. **忽视商店页。** 广告素材与商店页断裂，会造成点击到安装漏损。
6. **SKAN 当实时归因用。** SKAN 有延迟和聚合限制。
7. **放量只看 D0。** 工具产品的广告和订阅 LTV 都有后续留存贡献。
8. **投放和变现数据割裂。** 不回传收入就无法做价值优化。

## 附：一页速查表

```text
核心公式：
CAC = 花费 / 有效新增用户
LTV = IAA LTV + IAP LTV - 退款 / 税费 / 其他损耗
ROAS = 已回收收入 / 投放花费
投放成立：LTV ≥ CAC

买量漏斗：
预算 → 展示 → 点击 → 商店页 → 安装 → 首开 → 激活 → 变现触点 → 收入 → 留存回收

事件层级：
浅层：install / first_open / onboarding_complete
中层：core_task_complete / ad_scene_enter / paywall_show
深层：ad_revenue / trial_start / purchase / renewal / refund

诊断顺序：
ROAS → 成本 / LTV → 安装 / 激活 / 收入 / 留存 → 国家 / 渠道 / 素材 / 版本

放量前：
归因命名规范；收入回传正常；cohort 看板可用；止损线明确；留存和退款护栏已设。
```
