## 1. 核心理念：功能设计即变现设计

在 IAP 工具产品中，**功能定义 = 变现策略的物化**。每一个功能的免费/付费边界、触发时机、交互方式，本质上都是在回答一个问题：

> "这个功能在变现漏斗中扮演什么角色——拉新、留存、感知价值、还是促成付费？"

IAP 工具产品的核心命题不是"怎么收钱"，而是：

```
如何通过功能设计，让用户在免费使用中自然感知到"付费值得"
```

**与 IAA（广告变现）产品的根本差异：**

| 维度 | IAA 工具 | IAP 工具 |
|------|---------|---------|
| 变现对象 | 广告主（卖用户注意力） | 用户自己（卖功能价值） |
| 功能设计目标 | 最大化广告曝光机会 | 最大化付费价值感知 |
| 免费功能的角色 | 承载广告的"容器" | 培养信任的"样品间" |
| 核心转化事件 | 广告展示/点击 | 试用启动/付费 |
| 用户分群逻辑 | 按 eCPM 分层 | 按付费意愿分层 |

## 2. 功能架构三层模型

一个 IAP 工具产品的所有功能，按在变现漏斗中的角色，分为三层：

```
┌─────────────────────────────────────────────────────────┐
│                    转化层 (Conversion)                    │
│  付费墙 · 套餐选择 · 试用流程 · 购买恢复 · 续订管理        │
│  角色：把"想付费"变成"已付费"                              │
├─────────────────────────────────────────────────────────┤
│                    感知层 (Perception)                    │
│  功能预览/灰显 · 用量限制 · 结果对比 · 升级入口             │
│  角色：让用户"看见"付费后能获得什么                         │
├─────────────────────────────────────────────────────────┤
│                    钩子层 (Hook)                          │
│  核心免费功能 · 社交分享 · 内容/模板 · 新手引导             │
│  角色：让用户进来、留下、养成习惯                           │
└─────────────────────────────────────────────────────────┘
```

**设计原则：** 三层必须**首尾贯通**——钩子层引来的用户要能流到感知层，感知层的每个触点都要指向转化层。任何一层的断裂都会导致整个变现漏斗失效。

## 3. 钩子层（Hook Layer）—— 获客与留存

### 3.1 设计目标

让用户**进来 → 使用 → 留下来**。这是所有付费转化的土壤。没有足够大的 DAU，付费漏斗顶部太窄，再高的转化率也撑不起收入。

### 3.2 核心功能模块

#### 3.2.1 核心工具能力（免费且必须好用）

| 设计要素 | 说明 |
|----------|------|
| **功能边界** | 提供完整的核心能力，但不能覆盖所有高级场景。比如 OCR 扫描的"普通精度识别"免费，"高精度识别"付费。 |
| **品质标准** | 免费功能的质量不能差到让用户流失，但也不能好到让用户觉得"不需要付费"。这是一个精妙的平衡。 |
| **典型做法** | 扫描工具：免费可扫、基础编辑 → 付费解锁批量/高清/高级滤镜；PDF 工具：免费可阅读/基础标注 → 付费解锁编辑/合并/转换 |

**设计反例：** 免费功能太差 → 用户还没感知价值就走了，付费墙根本没机会出现。

**设计反例：** 免费功能太好 → "我为什么要付费？" → 转化率趋近于零。

#### 3.2.2 新手引导（Onboarding）

这是一个**被严重低估的变现杠杆**。引导流程承担两个变现任务：

| 任务 | 设计手段 |
|------|----------|
| **快速到达 aha-moment** | 引导用户在 30 秒内完成第一次核心操作（扫一张图、转换一个文件），让用户"看到"这个工具能为他做什么 |
| **预埋付费感知** | 在引导中展示高级功能的存在，但不强制弹付费墙。例如：在引导最后一步展示 Pro 功能一览（灰显 + 锁图标），然后让用户跳过 |

**两种引导策略：**

- **Soft onboarding（推荐）：** 引导流程流畅简短，付费墙可跳过。优势：用户先体验价值，后续情境转化质量更高。
- **Hard onboarding + 付费墙（高风险）：** 引导末尾强制弹付费墙。优势：首屏转化高；劣势：大量用户直接流失、退款率高、可能违反商店政策。

**设计建议：** 除非产品有极强的品牌认知（如知名工具的新版本），否则走 soft onboarding，把付费墙后移到"价值时刻"。

#### 3.2.3 社交分享钩子

| 设计要素 | 商业化逻辑 |
|----------|-----------|
| **水印** | 免费导出的文件带品牌水印。每一次分享都是一次免费获客。水印本身也是"去水印"这个付费卖点的广告。 |
| **分享奖励** | 分享后解锁额外免费次数（如"分享给好友，再免费扫 3 次"）。低成本获客 + 培养分享习惯。 |
| **模板/成果展示** | 用户用工具做出来的成果（如扫描件、设计图），鼓励分享 → UGC 传播。 |

**设计要点：** 水印的位置和透明度需要精心设计——太明显影响体验（导致用户流失），太隐蔽则失去获客和转化效果。通常是半透明、置于角落、覆盖面积 5-10%。

#### 3.2.4 内容/模板广场（可选，适用于特定工具类型）

适用于：扫描类、设计类、效率类、笔记类工具。

| 设计要素 | 商业化逻辑 |
|----------|-----------|
| **免费模板库** | 吸引用户每日浏览 → 提升 DAU 和 session 时长 → 扩大付费漏斗顶部 |
| **高级模板（付费）** | 免费浏览 + 付费下载/使用。黄金位置展示付费模板，用户看到"更好的选择"就在旁边 |
| **社区/UGC** | 用户上传模板/作品 → 内容生态 → 网络效应 → 更高的留存和转化 |

#### 3.2.5 钩子层的关键指标

| 指标 | 目标 | 为什么重要 |
|------|------|-----------|
| **DAU / MAU** | 持续增长 | 付费漏斗的顶部 |
| **D1/D7/D30 留存率** | 尽量高 | 用户留得越久，触发付费墙的机会越多 |
| **核心功能使用率** | 70%+ | 用户只有真正用了核心功能，才有可能感知到付费价值 |
| **分享率** | 尽量高 | 零成本获客，且分享者本身是高留存用户 |
| **引导完成率** | 80%+ | 如果引导环节流失严重，后面的一切变现设计都是空中楼阁 |

## 4. 感知层（Perception Layer）—— 让用户"看见"付费价值

这是 IAP 工具产品设计中**最核心、最考验产品功底**的一层。用户不会因为你弹了付费墙就付费——他们付费是因为**在使用中反复感知到"如果我付费，体验会更好"**。

### 4.1 设计目标

在用户每日的使用路径中，**悄无声息地埋下"值得付费"的念头**。不靠弹窗轰炸，靠产品设计自然引导。

### 4.2 核心功能模块

#### 4.2.1 功能预览 & 灰显（Grey-out）

这是感知层最重要的设计手段。

| 设计要素 | 具体实现 |
|----------|----------|
| **锁图标 + 灰显** | 付费功能在菜单/工具栏中可见但不可点击，带🔒图标。用户每次看到都在被提醒"还有一个更好的选择"。 |
| **效果预览** | 点击付费功能时，不直接弹付费墙，而是先展示效果预览。例如点击"智能增强"，先展示增强前后的对比（带水印/模糊处理），然后才引导付费。 |
| **一次性试用** | 给每个用户一次免费试用高级功能的机会（不是试用订阅，是试用某个具体功能）。用过一次后，下次点击才触发付费墙。 |

**心理机制：** 损失厌恶（Loss Aversion）。用户看到"我可以更好，但我得不到"，比根本看不到更难受，更倾向于付费消除这种"缺失感"。

**设计要点：**
- 灰显功能的**数量要恰到好处**：太多 → 用户觉得"什么都不给用"，体验差；太少 → 感知不到付费价值。
- 灰显功能的**位置要显眼**：如果藏在三级菜单里，用户根本看不到，等于没设计。
- 灰显功能的**命名要有吸引力**：不是"Pro 滤镜 3"，而是"杂志级增强"——用结果而非功能来命名。

#### 4.2.2 用量限制（Usage Cap / Freemium Gate）

| 限制维度 | 适用场景 | 设计要点 |
|----------|----------|---------|
| **按次数** | 扫描、转换、导出 | 每日免费 3-5 次。限制设在"用户刚尝到甜头但还没完成完整任务"的时刻。 |
| **按容量** | 云存储、文件管理 | 免费 2GB → 付费用 100GB。容量在"快满但还没满"时开始提醒。 |
| **按功能维度** | 所有工具 | 基础功能免费，高级功能付费。限制设在"用户最想要的"而非"最基础的"。 |
| **按时间** | VPN、学习工具 | 每日免费 30 分钟 → 付费无限。时间限制在"用户刚进入状态"的时刻。 |

**核心设计准则：限制设在"导出/保存"环节，而非"使用/创作"环节。**

> 让用户做完、看到了成果，在"拿走成果"时触发限制——这才是付费动机最强的时刻。

反面案例：用户刚要扫描，弹出"今日免费次数已用完" → 用户直接关闭 App，还没感知到价值就流失了。

#### 4.2.3 结果对比暗示（Before/After Comparison）

| 设计要素 | 具体实现 |
|----------|----------|
| **处理完成后展示对比** | 用免费版处理图片/文档后，在结果页旁边放一个"Pro 版效果"的对比滑块或分屏。视觉冲击力远超文字描述。 |
| **导出时的格式对比** | 选择导出格式时，Standard HD（免费）和 Ultra HD（Pro）并列展示，附预览缩略图。 |
| **批量处理的效率对比** | 用户一张一张处理时，在旁边提醒"Pro 可一键处理 100 张"。 |

**设计要点：** 对比要**视觉化**，不要纯文字。一张 "原图 vs Pro 增强" 的对比图，比一万字的文案更有效。

#### 4.2.4 操作流程中的升级入口

| 位置 | 设计 | 触发逻辑 |
|------|------|----------|
| **导出环节** | 格式选择器里，"无水印高清 PDF"标记为 Pro，与免费格式并列 | 每次导出都看到 |
| **分享环节** | 点击分享时，弹出"分享无水印版本（Pro）"选项 | 高频场景 |
| **结果页** | 完成扫描/转换后，底部常驻"升级 Pro 解锁更多"横幅 | 任务完成后的满足时刻 |
| **设置页** | "升级高级版"入口，但这是补充触点，不是主触点 | 用户主动寻找时 |

**核心原则：** 升级入口必须嵌入**用户的核心操作路径**中，而不是藏在"设置 → 关于 → 升级"的角落里。用户不会主动去找付费入口，但会在使用中被动遇到。

#### 4.2.5 感知层的关键指标

| 指标 | 为什么重要 |
|------|-----------|
| **付费功能曝光率** | 灰显/预览被多少用户看到了？曝光不足 → 漏斗没有输入 |
| **预览点击率** | 用户看到灰显功能后，有没有点进去看？低点击率 → 功能命名/位置不吸引人 |
| **限制触发率** | 多少用户触发了用量限制？太低 → 限制太松/用户根本没深度使用 |
| **升级入口点击率** | 操作流程中的升级入口被点击的比例 |
| **试用启动率（Trial Start Rate）** | 看到付费墙后，多少用户启动了试用？这是感知层→转化层的桥梁 |

## 5. 转化层（Conversion Layer）—— 临门一脚

### 5.1 设计目标

在用户付费意愿最高的时刻，提供**最顺畅的付款体验 + 最合理的价格结构 + 最强的信任背书**。

### 5.2 核心功能模块

#### 5.2.1 付费墙（Paywall）

付费墙不是一页价格表，而是一个**决策引导页面**。

**付费墙的五大构成要素：**

| 要素 | 设计要点 |
|------|----------|
| **1. 价值主张（Hero）** | 页面顶部的核心文案：一句话说清"Pro 能给你什么"。用结果语言，不用功能语言。"无限次高清扫描"代替"包含高级识别引擎"。 |
| **2. 套餐展示** | 通常提供 2-3 个套餐。年付是主推（C 位高亮 + "最受欢迎"标签 + 月均价格锚定），月付是低门槛入口，终身买断是高锚。 |
| **3. 功能对比表** | 不是罗列所有功能，而是突出免费版"做不到的 3-5 件事"。每一行都是一个痛点。 |
| **4. 社会证明** | 用户数、评分、评价摘录、"超过 100 万用户选择 Pro"。 |
| **5. 信任要素** | "可随时取消""隐私保护""恢复购买""7 天免费试用"。 |

**付费墙的三种触发类型：**

| 类型 | 触发时机 | 优势 | 劣势 |
|------|----------|------|------|
| **情境付费墙** | 用户触发功能限制/点击灰显功能时 | 转化质量高（用户已有明确需求） | 触达率取决于用户是否深度使用 |
| **Onboarding 付费墙** | 引导流程末尾 | 触达率接近 100% | 用户还没体验，转化质量低 |
| **常驻入口** | 设置页/首页的升级按钮 | 补充触点 | 触达率低 |

**设计建议：** 以情境付费墙为主力（占 70% 以上转化），onboarding 付费墙为辅助（soft/可跳过），常驻入口做补充。

#### 5.2.2 免费试用流程（Free Trial Flow）

| 设计要素 | 说明 |
|----------|------|
| **试用时长** | 3 天或 7 天。太短→没体验够；太长→延迟收入且用户容易忘记取消。需 A/B 确定最优值。 |
| **是否要信用卡** | 需要信用卡 → 试用启动率低，但转化率高（自动续订）；不需要 → 启动率高，但到期转化率低。也是需要 A/B 的取舍。 |
| **试用期内的价值引导** | 试用开始后，通过推送/应用内引导，确保用户在试用期内用到了 **2-3 个 Pro 核心功能**。用户只用过才能感知价值。 |
| **到期前提醒** | 试用到期前 24h 推送通知。不是恐吓（"马上要扣钱了"），而是价值提醒（"你的 Pro 试用还有 1 天，想继续享受高清导出吗？"）。 |
| **到期后的降级体验** | 试用结束后，降级效果要**明显可感知**。比如 Pro 的"智能增强"降级为普通增强，图片效果差距一眼可见 → 这就是最好的续费提醒。 |

#### 5.2.3 套餐与定价设计

| 定价策略 | 说明 |
|----------|------|
| **年付为主推** | 用月均价格锚定：年付 ¥198/年 = 月均 ¥16.5 vs 月付 ¥30/月。标注"省 45%"。 |
| **月付为低门槛入口** | 降低首次决策门槛，但流失率高。适合做"中间选项"衬托年付。 |
| **终身买断为高价锚** | ¥398 终身 vs ¥198/年。让年付看起来更"划算"。 |
| **价格分层（Good-Better-Best）** | 免费（Good）→ Pro（Better = 主推）→ Pro Max / 团队版（Best = 高价锚） |

**本地化定价要点：** 不要全球一个美元价直转。按目标市场的购买力调整。中国区 ¥198/年、美国区 $29.99/年、印度区 ₹999/年——价格因市场而异，但功能相同。

#### 5.2.4 购买恢复 & 跨平台权益

| 功能 | 必要性 | 说明 |
|------|--------|------|
| **恢复购买（Restore Purchase）** | 🔴 强制（Apple 审核要求） | 用户换手机/重装 App 后能恢复已购。没有这个功能过不了 Apple 审核。 |
| **跨平台权益同步** | 🟡 强烈推荐 | 用户在 iPhone 付了费，iPad/Mac 上也能用。提升感知性价比，降低取消意愿。 |
| **家庭共享** | 🟢 锦上添花 | 一个订阅，全家可用。边际成本为零，感知价值大幅提升。 |

#### 5.2.5 订阅生命周期管理

| 环节 | 功能设计 |
|------|----------|
| **续订成功** | 静默处理，不需要打扰用户 |
| **扣款失败（被动流失）** | Grace period（宽限期）+ billing retry（系统自动重试扣款）+ 推送提醒更新支付方式。这是最容易忽视但 ROI 最高的优化点。 |
| **主动取消** | 展示"取消挽留页"：提供降档优惠（如从月付降到季付、给折扣）、暂停订阅（而非取消）、强调"失去的功能" |
| **已流失用户召回** | Win-back offer："你的 Pro 文档还在云端，续费 ¥98/年（50% off）即可恢复访问" |

#### 5.2.6 转化层的关键指标

| 指标 | 公式 | 解读 |
|------|------|------|
| **付费墙→CTA 点击率** | 点击套餐按钮 / 付费墙曝光 | 付费墙的吸引力 |
| **CTA→购买完成率** | 完成购买 / 点击 CTA | 支付流程的顺畅度 |
| **试用→付费转化率** | 试用到期后付费 / 启动试用 | 试用价值的体现 |
| **首次续订率** | M2 续订 / M1 付费 | 最大的流失坎 |
| **被动流失挽回率** | grace period 内恢复扣款 / 进入宽限期 | dunning 效果 |
| **退款率** | 退款单数 / 总交易 | 过高 → 付费墙误导或价值不符 |

## 6. 用户路径设计与付费触点埋设

### 6.1 典型用户路径 × 付费触点映射

以下是一个扫描工具用户的典型路径，标注了每个环节的感知层和转化层触点：

```
用户下载 App
    │
    ▼
🔹 新手引导（Onboarding）
    ├── 引导完成首次扫描 → 体验 aha-moment
    └── 引导最后一步：【灰显展示】"Pro 功能一览"（可跳过）
    │
    ▼
🔹 日常免费使用
    ├── 扫描文档 → 基础编辑 → 导出
    ├── 【感知层触点】导出时展示"无水印高清 PDF（Pro）"
    ├── 【感知层触点】编辑工具栏中"智能增强🔒"灰显
    │
    ▼
🔹 触发限制（第 4 次扫描时）
    ├── 【感知层触点】"今日免费扫描次数已用完"
    └── 【转化层触点①】→ 弹出付费墙（情境触发）
    │
    ▼
🔹 用户点击灰显的"智能增强"
    ├── 【感知层触点】先展示"原图 vs Pro 增强"效果对比
    └── 【转化层触点②】→ 引导启动免费试用
    │
    ▼
🔹 试用期（3 天）
    ├── 推送引导使用 Pro 核心功能
    ├── 【转化层触点③】试用到期前 24h 推送提醒
    └── 到期 → 降级体验（普通增强 vs 智能增强差距明显）
    │
    ▼
🔹 转化为付费（或流失）
```

### 6.2 触点设计原则

| 原则 | 说明 |
|------|------|
| **不打断任务流** | 在"任务完成后"触发，而非"任务进行中"触发。用户正在扫描，突然弹付费墙 → 体验断裂。扫描完成、看到结果了 → 弹付费墙引导导出/保存 → 动机最强。 |
| **递进式触达** | 第一次触发限制 → 友好提醒 + 引导试用。第 N 次触发 → 付费墙。不要第一次就 hard sell。 |
| **多触点覆盖** | 同一个付费动机（如去水印），在导出环节、分享环节、设置页都有入口。用户在不同情境下都"看得到"。 |
| **频率控制** | 付费墙展示频率需要控制：同一用户 24h 内不超过 2-3 次。过度弹窗 → 卸载。 |

## 7. IAP vs IAA 功能设计差异

对于同时做 IAA（广告）和 IAP（内购）的混合变现工具，功能设计上需要统筹考虑两者的关系：

| 设计维度 | IAA 模式 | IAP 模式 | 混合设计策略 |
|----------|---------|---------|-------------|
| **广告位 vs 付费墙** | 广告位占核心页面 | 付费墙在关键时刻弹 | 免费用户 → 展示广告 + 引导付费去广告 |
| **功能限制粒度** | 一般不限制核心功能 | 限制高级功能/用量 | 免费版保留核心 + 展示广告；Pro 解锁全部 + 去广告 |
| **用户分群策略** | 所有免费用户一律变现 | 按付费意愿分群 | 高频用户 → 推 IAP（性价比）；低频用户 → 走 IAA |
| **"去广告"定价** | — | 去广告是核心付费卖点 | 定价需 ≥ 该用户 IAA LTV × 1.2~1.5，确保不亏 |
| **Geo 分层** | 低 eCPM 地区多展示广告 | 高 ARPU 地区主推 IAP | Tier 1 推订阅，Tier 3/4 走广告 |

**一个关键的产品决策：去广告定价锚点**

```
去广告月费 > 该用户预期月广告收入（ARPUDAU_adv × 30）
```

如果去广告定 ¥20/月，但该用户每月能贡献 ¥25 广告收入 → 用户付费后你反而亏了。需要通过用户分群和动态定价来避免这个"变现内耗"。

## 8. 案例深度拆解：扫描全能王（CamScanner）

扫描全能王是工具类 IAP 变现的标杆案例。以下从功能设计角度拆解其变现架构。

### 8.1 功能分层拆解

| 功能层 | 免费版 | Pro 版（¥198/年） | 设计逻辑 |
|--------|--------|-------------------|----------|
| **扫描识别** | 单张扫描 + 基础 OCR | 批量扫描 + 高精度 OCR + 自动切边 | 免费让用户"能扫"，但效率和质量受限 |
| **编辑增强** | 基础裁剪/旋转 | 智能增强、去阴影、滤镜、颜色校正 | 灰显展示所有高级功能，点击时先预览效果再引导付费 |
| **导出格式** | PDF/JPG + 带水印 | Word/Excel/PPT + 高清 + 无水印 + 可编辑文字层 | **核心转化点**：在导出环节锁住价值 + 水印获客 |
| **云存储** | 本地存储 | 云端同步 + 多端协作 + 自动备份 | 免费版数据在本地 → 换手机就没了 → 云同步的动机 |
| **共享协作** | 单文件分享（带水印） | 文档链接分享 + 团队协作 + 批注 | 个人用户的升级动机相对弱，企业/团队用户更愿意付费 |
| **证件照** | 基础模板浏览 | 高级模板 + 换底色 + 智能尺寸适配 | 高频场景（考证/办证），付费意愿高 |

### 8.2 付费触点路径

```
打开 App
  → 拍一张文档
    → 看到自动切边效果（免费） → aha-moment ✅
  → 点击编辑
    → 工具栏中"智能增强🔒"灰显
    → 点击 → 展示"原图 vs Pro 增强"对比 → "试用 7 天免费 Pro"
  → 点击导出
    → 格式选择："标准 PDF（免费，带水印）" vs "高清 PDF（Pro，无水印）"
    → 选 Pro → 弹出付费墙（年付 ¥198/年 = 日均 ¥0.54）
  → 点击分享
    → 分享出去的 PDF 带 CamScanner 水印 → 获客 ✅
    → 接收方看到水印 → 也下载 → 获客闭环 ✅
```

### 8.3 设计精髓总结

1. **水印是最强杠杆**：既是获客渠道、又是付费动机。每次免费分享都在帮 CamScanner 做广告。
2. **限制设在最后一步**：让你"扫完了、看到了"，在"拿走成果"时卡住。动机最强。
3. **订阅而非买断**：¥198/年，锁住长期用户，降低每年的重新决策成本。
4. **年付月均锚定**：¥198/年 = 月均 ¥16.5，对比月付 ¥30/月 → 年付"看起来太划算了"。
5. **证件照是隐藏的转化利器**：高频刚需场景，用户付费意愿远超"提高扫描精度"。

## 9. 常见工具类型的功能拆解模板

### 9.1 PDF / 文档工具

| 功能层 | 免费版 | 付费版 | 转化逻辑 |
|--------|--------|--------|----------|
| 阅读/标注 | 基础阅读 + 标注 | 高级标注 + 表单填写 | 免费够用，付费更专业 |
| 编辑 | 查看不能改 | 文字编辑/图片替换 | **核心转化点** |
| 转换 | PDF→图片（带水印） | PDF→Word/Excel/PPT（无水印）+ 批量 | 导出环节锁住 |
| 合并/拆分 | 限制页数/次数 | 无限 | 用量限制推动付费 |
| 签名 | 基础签名 | 高级签名 + 模板 + 多人签署 | 个人够用，企业需付费 |

### 9.2 图片 / 视频工具

| 功能层 | 免费版 | 付费版 | 转化逻辑 |
|--------|--------|--------|----------|
| 拍摄/录制 | 基础拍摄 | 高级参数（ISO/快门）+ RAW | 专业用户的核心需求 |
| 滤镜/特效 | 基础滤镜 | 高级滤镜 + AI 特效 | 灰显预览 + 对比驱动付费 |
| 导出 | 普通画质 + 带水印 | 高清/4K + 无水印 | **核心转化点** |
| 批量处理 | 单张 | 批量（100 张一键处理） | 效率提升驱动付费 |
| 云备份 | 本地 | 云端 + 自动备份 | 安全焦虑驱动付费 |

### 9.3 VPN / 网络工具

| 功能层 | 免费版 | 付费版 | 转化逻辑 |
|--------|--------|--------|----------|
| 节点数量 | 3-5 个基础节点 | 全球 100+ 节点 | 覆盖面限制 |
| 速度 | 限速 1-2MB/s | 不限速 | 体验降级驱动 |
| 流量/时长 | 每日 30min / 500MB | 无限 | 用量限制 |
| 设备数 | 1 台设备 | 5 台设备 | 多设备是刚需 |
| 高级协议 | 不支持 | WireGuard/专线 | 安全需求驱动 |

### 9.4 习惯 / 效率工具

| 功能层 | 免费版 | 付费版 | 转化逻辑 |
|--------|--------|--------|----------|

| 模板 | 基础模板 | 高级模板 + 自定义 | 模板库驱动付费 |
| 协作 | 单人 | 团队协作 + 权限管理 | 团队场景付费意愿高 |
| 跨平台同步 | — | iOS + Android + Web + Desktop | 多端同步是强刚需 |
| 数据导出 | 基础导出 | 高级导出 + API | 数据自由度驱动 |

## 10. 功能设计检查清单

在设计或评审一个 IAP 工具产品的功能架构时，逐项检查：

### 钩子层
- [ ] 免费核心功能是否足够好用？（用户能体验到 aha-moment）
- [ ] 免费功能是否好到"用户不需要付费"？（→ 如果是，收紧免费边界）
- [ ] 新手引导是否在 30 秒内让用户完成第一次核心操作？
- [ ] 引导中是否预埋了 Pro 功能的存在感（灰显/一览）？
- [ ] 是否有社交分享机制（水印/分享奖励）驱动零成本获客？

### 感知层
- [ ] Pro 功能是否在免费版的 UI 中可见（灰显 + 🔒）但不可用？
- [ ] 灰显功能的位置是否在主操作路径上（而非藏在三级菜单）？
- [ ] 灰显功能的数量是否适中（3-6 个，不滥不稀）？
- [ ] 点击灰显功能时，是否先展示效果预览而非直接弹付费墙？
- [ ] 用量限制是否设在"导出/保存"环节而非"使用/创作"环节？
- [ ] 是否有结果对比（原图 vs Pro 增强）的视觉展示？
- [ ] 升级入口是否嵌入核心操作路径（导出/分享/结果页）？
- [ ] 免费试用入口是否显眼且有吸引力？

### 转化层
- [ ] 付费墙是否在"价值时刻"触发（任务完成后、限制触发时）？
- [ ] 付费墙的核心文案是否用"结果语言"而非"功能语言"？
- [ ] 套餐是否精简（2-3 个）+ 年付是否 C 位高亮？
- [ ] 是否有"月均价格锚定"（年付折算月均 + 节省比例）？
- [ ] 是否有社会证明（评价/用户数）和信任要素（随时取消/隐私）？
- [ ] 是否提供"恢复购买"？（Apple 审核强制要求）
- [ ] 试用流程是否完整（时长合理、试用期内价值引导、到期提醒）？
- [ ] 是否接入了 Grace Period + Billing Retry（挽回被动流失）？
- [ ] 是否有取消挽留页（降档优惠/暂停订阅/强调失去的价值）？
- [ ] 是否有 win-back offer 召回已流失付费用户？

### 数据埋点
- [ ] 漏斗节点是否完整埋点（曝光→CTA→购买→试用→付费→续订→流失→退款）？
- [ ] 是否按渠道/地区/付费墙版本分队列分析？
- [ ] 是否配置了关键指标异常预警（转化率/退款率/MRR 日波动 >20%）？

## 11. 总结：IAP 工具功能设计的三大铁律

```
铁律一：先让用户"离不开"，再让用户"想更好"
   → 钩子层的免费功能必须好用，这是所有转化的土壤。
      土壤坏了，上面的一切都是白搭。

铁律二：在用户"最想要的时刻"展示付费价值
   → 限制设在任务完成前最后一刻（导出/保存/去水印），
      而非任务开始前或任务进行中。

铁律三：让付费"看起来不贵"
   → 年付月均锚定、免费试用降低门槛、家庭共享提升感知性价比。
      不是真的降价，而是让用户觉得"值"。
```
