# IAA 变现 · 工具应用广告收入运营 · 学习文档

> 面向已有基础商业化概念的工具类 App 商业化运营同学：默认你已知道 DAU、留存、ARPU、eCPM 的含义，本文从“如何经营广告收入”这一层开始讲。
> 本文不是广告平台手册，而是一条可从头读到尾的学习路径：先建立广告收益树，再学会用漏斗和口径定位问题。
> 读完你应该能：拆解 IAA 收入波动；判断广告位设计是否健康；看懂聚合平台数据；设计日常诊断 SOP。

## 0. 一句话理解

IAA 变现不是“多塞广告”，而是在用户还愿意继续使用产品的前提下，把每个活跃用户可贡献的广告收入做大。

```text
广告收入 = 展示次数 × eCPM / 1000
展示次数 = DAU × 人均可展示场景 × 请求率 × 填充率 × 展示成功率
```

> 🧭 **贯穿全文的一句话**：IAA 运营的诊断动作永远是先拆“展示次数”，再拆“eCPM”，最后回到留存判断这次优化是否值得。

## 1. 收益树：广告收入如何被拆开

```text
总广告收入
├─ DAU
└─ ARPDAU
   ├─ 人均展示次数
   │  ├─ 广告场景到达率
   │  ├─ 请求率
   │  ├─ 填充率
   │  └─ 展示成功率
   └─ eCPM
      ├─ 用户质量 / 地区 / 渠道
      ├─ 广告位质量
      ├─ 广告网络需求
      └─ 聚合排序 / 底价 / 竞价
```

这棵树决定了日常分析顺序：

1. 收入变了，先看 DAU 还是 ARPDAU 变了。
2. ARPDAU 变了，先拆人均展示次数，再拆 eCPM。
3. 人均展示变了，沿广告链路看“到达、请求、填充、展示”。
4. eCPM 变了，再看地区、渠道、广告位、网络、底价和季节性。

> 💡 为什么不先看 eCPM？因为 eCPM 是“价格”，收入是“价格 × 数量”。只让 eCPM 变高但展示量大跌，运营上可能是亏的。

## 2. 第一大坑：实时统计不是结算收入

广告平台和聚合平台通常同时存在两类数据：

| 口径 | 典型来源 | 运营用途 | 不能做什么 |
|---|---|---|---|
| 实时 / SDK 统计 | 客户端 SDK、聚合 SDK | 漏斗、频次、广告位表现、近实时排障 | 不能直接当财务结算 |
| API / 平台报表 | AdMob、MAX、广告网络后台、聚合平台 API | 对账、收入确认、ROI 复盘 | 有延迟，不适合分钟级排障 |

AdMob 支持展示级广告收入数据，用于更细的用户级 LTV 和分析 [[2]](https://developers.google.com/admob/android/impression-level-ad-revenue)。但这类数据仍要和平台最终报表、聚合平台拉取的网络 API 数据分清。TopOn 也明确区分三方 API 数据与 SDK 统计数据 [[6]](https://help.toponad.net/cn/docs/Z4zsF6)。

> ⚠️ 第一个大坑：用 SDK 估算收入做财务对账。正确做法是：实时诊断看 SDK / ILRD，收入确认看平台 API / 结算报表。

## 3. 广告形式：先按“用户任务阶段”选，不按 eCPM 排序

| 广告形式 | 适合位置 | 商业化角色 | 主要风险 |
|---|---|---|---|
| 开屏 | 冷启动或热启动前 | 捕捉进入流量的高价值曝光 | 首次体验受损、加载超时 |
| Banner | 常驻页面、结果页、列表页 | 提供稳定低打扰库存 | 遮挡内容、快速刷新稀释价值 |
| 插屏 | 任务完成、页面自然切换 | 在自然断点提高单次价值 | 操作中弹出会损害留存 |
| 激励视频 | 解锁次数、去等待、临时使用高级功能 | 用户主动选择，适合换取明确价值 | 奖励无价值则完成率低 |
| 原生 / 信息流 | 内容流、推荐流、工具首页卡片 | 与内容融合，补充广告库存 | 纯工具产品常缺少内容场景 |

穿山甲成长中心把收益优化拆成展示率、点击率、转化率等节点 [[4]](https://www.csjplatform.com/growthcenter/6101274400195d0046c2731d)。对工具产品来说，真正的产品问题通常不是“哪个形式 eCPM 最高”，而是“这个广告是否出现在用户能接受的任务阶段”。

> 💡 激励视频常被误用。它不是“高 eCPM 插屏”，而是一次价值交换：用户愿意看广告，是因为广告后能得到真实有用的功能或额度。

## 4. 广告位设计：工具产品只抓三个位置

### 4.1 任务完成后

这是工具类产品最稳的插屏位置：扫描完成、清理完成、转换完成、导出完成。用户目标已经达成，打断感最低。

### 4.2 结果页 / 列表页

适合 Banner、MREC、原生卡片。它们贡献稳定展示，不应遮挡结果和主操作按钮。

### 4.3 用户主动换取价值时

适合激励视频：额外转换次数、临时解锁高级节点、去水印一次、加速处理一次。

常见映射：

| 工具类型 | 主广告位 | 辅助广告位 | 不建议位置 |
|---|---|---|---|
| 清理 / 优化 | 清理完成插屏 | 结果页 Banner | 扫描中 |
| 扫描 / OCR | 导出后插屏 | 历史页 Banner | 相机启动前 |
| PDF / 转换 | 转换完成插屏 | 文件列表 Banner | 转换过程中 |
| VPN | 断开后插屏、节点激励 | 节点页 Banner | 连接中 |
| 图片 / 视频工具 | 导出后插屏 | 编辑页底部 Banner | 精细编辑中 |

## 5. 聚合：运营看的是“竞争效率”，不是后台配置项

AdMob Mediation 与 AppLovin MAX 都是常见广告聚合方案，核心目标是让多个广告需求方竞争同一次展示机会 [[1]](https://support.google.com/admob/answer/7378026) [[3]](https://developers.applovin.com/en/max)。运营上要理解三件事。

### 5.1 Waterfall：按预期价格从高到低请求

优点是可控；缺点是维护成本高、延迟高、底价容易过期。适合有历史数据后精细分层。

### 5.2 Bidding：同场竞价

优点是减少瀑布延迟，更接近实时出价；缺点是依赖网络支持，且不同网络的竞价能力不完全一致。

### 5.3 Hybrid：竞价池 + 瀑布兜底

这是多数工具产品的默认可行结构：让支持竞价的网络先竞争，再用瀑布尾部保证填充。

```text
[Bidding pool: AdMob / MAX / Pangle / Meta ...]
        ↓ 未填充或低竞争
[Waterfall tail: regional networks / no-floor backup]
        ↓
[house ad / cross promotion / no-fill handling]
```

> ⚠️ 底价不是越高越好。底价提高可能抬 eCPM，也可能直接损失填充；最终要看 ARPDAU 和留存，而不是单看 eCPM。

## 6. 漏斗分析：最适合运营日常排障的工具

TopOn 的漏斗分析文档把广告链路拆成从应用启动到展示、点击的一系列节点 [[5]](https://help.toponad.net/cn/docs/qlHqYM)。商业化运营可以把它抽象成：

```text
进入广告场景
→ 发起请求
→ 返回填充
→ 广告 ready
→ 触发展示
→ 展示成功
→ 点击 / 奖励 / 收入
```

每个节点对应一种问题：

| 掉点 | 运营判断 | 典型动作 |
|---|---|---|
| 场景到达低 | 广告位埋太深或功能路径变了 | 回到产品路径，检查入口曝光 |
| 请求低 | SDK 初始化、策略下发、代码路径问题 | 找研发看日志和版本差异 |
| 填充低 | 底价高、网络故障、地区配置不匹配 | 降底价、加兜底、分国家看 |
| ready 低 | 预加载时机不对或缓存过期 | 调整预加载和超时 |
| 展示低 | UI 遮挡、场景流失、展示失败 | 查错误码和场景时长 |
| 点击低 | 广告样式、场景不匹配 | 优化原生样式或换位置 |

## 7. 日常诊断：收入变动时怎么查

### 7.1 收入下跌

```text
收入下跌
├─ DAU 跌？
│  ├─ 买量减少
│  ├─ 自然量下降
│  └─ 留存下降
└─ ARPDAU 跌？
   ├─ 人均展示跌？
   │  ├─ 场景到达
   │  ├─ 请求率
   │  ├─ 填充率
   │  └─ 展示成功率
   └─ eCPM 跌？
      ├─ 地区 / 渠道结构
      ├─ 广告位结构
      ├─ 网络需求
      └─ 底价 / 竞价配置
```

### 7.2 eCPM 下跌但展示上涨

可能不是坏事。要看 ARPDAU 和留存：如果更多低价展示带来更高总收入且留存未伤害，可以接受。

### 7.3 eCPM 上涨但收入下跌

通常是底价过高、频控过紧、广告位减少，导致展示量损失大于单价提升。

### 7.4 新版本后收入异常

按版本拆：如果同渠道、同地区在新版本普遍下降，优先查 SDK、广告位触发、埋点、频控和远程配置。

## 8. A/B 测试：主指标用 ARPDAU / LTV，护栏用留存

可测试变量：广告位位置、插屏频次、Banner 是否开启、激励奖励、底价、聚合分层、并行请求、开屏兜底。

测试前写清：

```text
假设：为什么这个改动会提高收入
主指标：ARPDAU / LTV / 总收入
护栏：D1、D7 留存、卸载率、崩溃率、付费转化率
分层：国家、平台、渠道、新老用户、版本
停止条件：样本量、观察周期、异常阈值
```

> 💡 IAA 测试最容易“短期赢、长期输”。频次提高当天收入会上升，但如果留存下降，LTV 可能更低。

## 9. 商业化运营 SOP

### 每日看

- 总广告收入、ARPDAU、DAU。
- 分广告位：展示、eCPM、填充率、展示成功率。
- 分国家 / 平台 / 渠道 / 版本：是否有结构变化。
- 聚合平台：主要网络收入占比、异常 no-fill、API 数据是否已回传。
- 异常：收入、展示、eCPM、填充率是否超过团队预警阈值。

### 每周看

- 哪些广告位贡献收入，哪些只贡献打扰。
- 哪些国家 / 渠道的广告 LTV 高，是否能反馈给投放。
- 底价和瀑布是否过期。
- 新增广告网络是否有增量贡献。
- 广告频次与留存、付费转化是否冲突。

### 上线前验收

- 广告位是否只在自然断点触发。
- 首次会话是否克制。
- 聚合配置是否有默认兜底。
- 失败事件、错误码、展示级收入是否可查。
- API 口径和 SDK 口径是否在看板中分开。

## 10. 常见误区

1. **只追 eCPM。** eCPM 高但展示少，收入可能下降。
2. **广告位越多越好。** 广告位过多会稀释高价值位置，还会伤害留存。
3. **首 session 急着变现。** 新用户还没体验价值时弹插屏，通常透支长期收入。
4. **把填充率当唯一配置目标。** 低价全填满不等于收入最优。
5. **不分国家看。** 全球平均 eCPM 会掩盖地区结构变化。
6. **用实时估算对账。** SDK / ILRD 用于分析，结算看平台报表。
7. **只看广告，不看产品路径。** 展示下降可能是核心功能完成率下降，而不是广告问题。
8. **测试不看留存。** 广告变现优化必须有留存护栏。

## 附：一页速查表

```text
核心公式：
广告收入 = 展示次数 × eCPM / 1000
展示次数 = DAU × 人均场景到达 × 请求率 × 填充率 × 展示成功率
ARPDAU = 广告收入 / DAU

诊断顺序：
总收入 → DAU / ARPDAU → 人均展示 / eCPM → 场景到达 / 请求 / 填充 / 展示 → 国家 / 渠道 / 版本 / 广告位

广告位原则：
任务中不打断；任务后可插屏；结果页可 Banner；主动价值交换用激励视频。

口径原则：
SDK / ILRD = 实时分析
平台 API / 结算报表 = 对账收入

测试原则：
主指标 ARPDAU / LTV；护栏 D1/D7 留存、卸载、崩溃、付费转化。
```
