## 0. 一句话理解：广告是“任务结束后的下一步”，不是“任务进行中的障碍”

工具类 App 的用户通常带着明确目标而来：扫完码、压缩好文件、清理完成、连接上电视、算出结果。理想广告位不是“哪里能塞屏幕”，而是用户已经获得本次任务结果、准备开始下一步时，给出一次可预期的商业化承接。

> 🧭 **贯穿全文的一句话**：先保证用户完成任务，再在“结果已交付、下一步未开始、广告已准备好”的交集展示广告；所有不满足交集的广告请求都应被放弃。

这一定义解释了一个看似反直觉的结论：工具类 App 不应把“点击功能图标”当成插屏节点。点击只是任务开始，用户此时仍在追求结果；广告会让他把等待归因于产品本身。Google 也明确将插屏定位为内容之间的逻辑断点，禁止在加载应用、退出应用，或每一次点击/返回后反复触发。[[1]](https://support.google.com/admob/answer/6201362?hl=en)

## 1. 脊柱：用“任务完成漏斗”设计广告位

不要按页面逐屏塞广告。先为每项工具功能画同一条漏斗：

```text
进入功能
  -> 配置/选择输入
  -> 执行任务
  -> 结果成功
  -> 用户确认结果
  -> 下一步（保存、分享、继续、返回）
                  \
                   -> 可选的广告承接
```

广告只应从三个节点分叉：

1. **稳定停留页**：用户本来就会浏览、滚动或等待的页面，承载 Banner / 原生信息流。
2. **任务成功后的边界**：结果已可见、主操作已完成，承载插屏。
3. **用户想获得额外价值时**：高级功能、额外次数、临时去广告，承载激励视频。

TopOn 的广告漏斗把“到达广告场景”“广告 Ready”“触发展示”“展示”拆成独立节点，并建议按广告位、按 DAU 人均次数分析，而不是只看全局汇总。[[3]](https://help.toponad.net/cn/docs/qlHqYM) 因而，一个“理想广告位”不仅是 UI 位置，更是一组可被观测的漏斗事件。

### 1.1 广告位的合格判定

在上线前用四个问题筛选每一个候选节点：

| 判定维度 | 必须回答的问题 | 不满足时的处理 |
|---|---|---|
| 结果 | 用户是否已经拿到本次功能的可用结果？ | 后移到结果成功后，或改为信息流 |
| 断点 | 用户是否自然停下来，而不是连续输入、拍摄、编辑或等待？ | 不展示；继续预加载 |
| 预期 | 用户能否从固定流程学会“这里可能出现广告”？ | 固定在同一结果/页面，避免随机触发 |
| 价值 | 若为激励广告，奖励是否能立即兑现且用户确实想要？ | 不做激励入口；改为正常功能或 IAP |

> 💡 插屏的本质不是“奖励用户看广告”，而是利用任务完成后短暂的注意力切换。若任务尚未完成，这段注意力仍属于任务本身，打断造成的损失通常大于新增一次展示。

## 2. 第一大陷阱：把“点击事件”错当成“完成事件”

内部 PDF、清理和阅读器竞品中，常见做法是点击任意图标、点返回、从后台切回就以全屏广告承接；有的还没有冷却。[[4]](https://vimedia.feishu.cn/wiki/Xs9swNzvJi8kSUkXeJYcubCZnLg) 这会把三个完全不同的事件混为一谈：

- **意图事件**：点击“压缩”“扫描”“清理”。它表示用户要开始做事，不能触发插屏。
- **进度事件**：选文件、裁剪、编辑、扫描中、上传中。它表示用户正在做事，不能触发插屏。
- **完成事件**：处理成功且结果可见。它才可能成为插屏候选。

Google 的规则不仅要求插屏位于逻辑断点，也明确限制在每个用户动作后重复展示，并强调不能妨碍核心内容、导航或交互。[[1]](https://support.google.com/admob/answer/6201362?hl=en) 因而“返回键”不是天然广告位：只有它代表“用户已确认结果并离开结果页”时才是候选；从选择文件页返回、从编辑页返回都不成立。

### 可直接交给开发的事件命名

```text
feature_opened                 # 仅记录，不展示
task_started                   # 仅预加载
task_succeeded                 # 记录候选断点
result_rendered                # 结果真正可用
result_acknowledged            # 用户保存/分享/点击继续/停留后确认
ad_eligible                    # 频控、Ready、付费状态均通过
ad_show_requested / impression # 请求与真实展示必须分开
```

将 `task_succeeded` 和 `result_rendered` 分开很关键：后台处理成功不等于用户已经看见结果。若 UI 尚未渲染就展示广告，用户会以为“功能还没完成”。

## 3. 四种广告形式分别该放在哪里

### 3.1 Banner：留给“稳定页面”，不要压住结果和输入

适用：文件列表、历史记录、设置、结果页底部留白、Launcher 的应用列表或非系统工具页。

不适用：相机取景框、二维码扫描框、计算器按键区、表单底部主按钮、文件编辑画布、正在进行的 VPN 会话。

内部遥控器竞品把 Banner 放在连接电视、Apps、Cast、Settings 等次级页面，首页和主遥控页保持干净；这是低打扰方案。PDF 和清理类竞品的结果页 Banner 也说明：结果页能承接常驻广告，但前提是广告与“保存/分享/再次处理”按钮有清晰内容分区。[[4]](https://vimedia.feishu.cn/wiki/Xs9swNzvJi8kSUkXeJYcubCZnLg)

设计规则：

- Banner 只放在用户有停留预期的页面；进入即跳转的中转页不放。
- 结果页优先将 Banner 放在结果卡片和操作按钮之后，不遮挡文件名、结果数值、保存按钮或系统导航。
- 内容流（新闻、天气、负一屏、搜索结果）优先用原生/信息流，而不是硬贴底部 Banner。原生广告应以清晰广告标识与内容分隔来保持可辨识性。

### 3.2 信息流/原生：留给“内容流”，不是工具操作流

Launcher 是最适合信息流的工具类例外：负一屏的天气、新闻、邮箱、小游戏、搜索结果本身就有浏览节奏，广告可以作为一条内容单元出现。内部 Easy Homescreen 的主屏搜索、应用列表、负一屏天气/新闻及工具页均有常驻广告，其中负一屏信息流的匹配度明显高于“点击计算器即弹窗”。[[4]](https://vimedia.feishu.cn/wiki/Xs9swNzvJi8kSUkXeJYcubCZnLg)

信息流的正确触发不是某次点击，而是 `feed_item_index_reached` 或 `feed_rendered`：用户滚动到该位置才请求/展示，离屏后不把它算作有效展示。

### 3.3 插屏：只占“完成一次完整任务”的节点

适用的典型组合：

| 产品/流程 | 理想插屏节点 | 不应展示的节点 |
|---|---|---|
| PDF 转换、压缩、合并 | 结果已生成，用户完成保存/分享或点击“继续处理”前 | 选文件、授权、编辑、点击功能入口、每次返回 |
| 清理/优化 | 扫描或清理完成，结果页已显示并被确认后 | 扫描中、清理中、首次冷启动、进入清理页 |
| 扫码/扫描 | 识别结果稳定展示，用户完成复制/打开/保存后 | 相机打开前、相机取景期间、识别中 |
| 遥控/投屏 | 一次投屏会话结束并回到结果/历史页 | 连接设备、主动遥控、投屏播放期间 |
| 计算器/转换器 | 用户连续计算结束后离开结果页，且仅在长会话中 | 按“=”、输入数字、结果被广告覆盖 |

Google 还建议，若界面存在连续点按，应给用户一个停止点/缓冲，避免用户关闭上一页后误点进入广告。[[1]](https://support.google.com/admob/answer/6201362?hl=en) 因此，理想流程是“结果页出现 → 用户看到结果 → 点击继续/返回 → 系统判定展示”，而不是“结果刚渲染立即盖上广告”。

### 3.4 激励视频：用“付出广告换取额外效用”，不能换空气

工具 App 的高价值激励不必照搬游戏金币，而应是可感知、即时、不可转让的产品效用，例如：

- 单次无水印导出、单次高质量压缩、单次批量处理额度；
- 一次高级编辑/签名/OCR/远程投屏尝试；
- 本次会话或一段有限时长的去广告体验；
- 清理工具的一次深度扫描或额外清理建议。

激励入口应在用户点击了受限功能、看到明确奖励后出现，而非在流程中强塞。用户必须主动、明确地选择观看；奖励规则必须在播放前清楚披露，完成后必须兑现。[[2]](https://support.google.com/admob/answer/7313578?hl=en) 内部竞品也反复指出：PDF、遥控器等产品若只用强制广告或只推订阅，会漏掉“愿意看一次广告试用高级能力”的人群。[[4]](https://vimedia.feishu.cn/wiki/Xs9swNzvJi8kSUkXeJYcubCZnLg)

## 4. 推荐的触发状态机与频控

把频控做在服务端/统一广告控制器，不要由每个页面自行“点了就 show”。

```text
任务完成
  -> 结果已渲染？否 -> 不展示，继续等待
  -> 用户已确认结果/离开结果？否 -> 保留候选
  -> 本次会话首次价值已建立？否 -> 不展示
  -> 用户是会员、激励免广告期或合规受限？是 -> 不展示
  -> 全局冷却、功能冷却、日上限均通过？否 -> 不展示
  -> 广告 Ready 且缓存有效？否 -> 放弃本次，不阻塞任务
  -> 展示插屏；失败则直接进入下一步
```

建议同时维护三层上限：

1. **全局层**：防止不同功能位叠加。用户刚关闭插屏，任何页面都不能立刻再弹。
2. **功能层**：同一功能连续执行时，按“成功任务数”而非“每次点击”计数；高频工具的首次成功先免打扰。
3. **用户层**：会员、试用期、激励免广告期、未成年人/受限同意状态、崩溃恢复会话都要有明确豁免。

> ⚠️ 不要把“从后台回来”当成插屏兜底。内部 PDF 与清理竞品有这类做法，但它既不能证明用户完成了任务，也容易形成无冷却的连续打断。若确实要商业化唤回场景，应单独设计并测试 app-open 方案；不要复用任务完成插屏。

### 4.1 初始频控实验（示意，不是行业基准）

以“完成任务数”为单位建立三组实验，而不是预设一个绝对分钟数：

| 组别 | 插屏策略 | 目的 |
|---|---|---|
| 对照组 | 仅结果页 Banner/信息流，无插屏 | 测出广告的真实增量与体验基线 |
| 轻量组 | 在第 2 次及以后合格的任务完成节点尝试插屏 | 验证低打扰插屏能否提高人均收益 |
| 进取组 | 每个合格完成节点均可尝试，但仍受全局冷却与日上限约束 | 找到收益开始损害留存的拐点 |

“第 2 次”只是示意。最终阈值应由产品的任务频次、会话长度、国家、渠道、广告 Ready 率和留存曲线共同决定。无论策略如何，Google 明确不允许把插屏做成每次点击或返回后都出现，也不应紧接上一条插屏继续出现。[[1]](https://support.google.com/admob/answer/6201362?hl=en)

## 5. 各工具品类的理想广告蓝图

### PDF / 文档工具

**主路径**：选文件 → 设置参数 → 处理 → 结果 → 保存/分享/继续。

- 常驻：文件列表、历史记录、设置页可放 Banner；功能详情页可在非编辑区域放原生广告。
- 插屏：在结果确认后的“继续处理/返回列表”边界尝试；不要在授权、选文件、每个编辑步骤、每次返回触发。
- 激励：单次无水印、批量文件额度、OCR/签名/高压缩质量试用。
- IAP：高级功能先展示价值和差异，再在用户实际点击限制功能时给订阅或激励二选一。

内部 PDF 竞品的高频做法是从引导、图标点击、返回、后台恢复到工具中间不断以全屏广告打断，且存在短时间连续看到多条广告的记录。它能快速抬高展示次数，却是本报告明确不建议复用的模式。更可取的是把这些分散节点收敛为“结果确认”这一处高质量广告位。[[4]](https://vimedia.feishu.cn/wiki/Xs9swNzvJi8kSUkXeJYcubCZnLg)

### 清理 / 优化工具

**主路径**：扫描 → 显示可清理项 → 用户确认 → 清理执行 → 成果报告。

- 常驻：成果报告页的底部 Banner 或结果卡片后的原生广告。
- 插屏：用户看见“释放空间/处理完成”成果后，点击继续或返回首页时；重任务（扫描+清理）比轻任务（看电池信息）优先级高。
- 激励：一次深度扫描、额外大文件筛选、短时去广告或高级清理建议。
- 禁止：扫描/清理执行中、首次打开前、只为进入某个工具页而弹。

Phone Clean Sentry 与 Smart Clean Pro 的共性是“操作结果页承接 Banner/信息流”，这条值得保留；差异是部分版本仍在每次启动、核心操作或切回 App 时弹视频广告。理想方案应保留结果页承接，移除“启动和切回即弹”的强制触发。[[4]](https://vimedia.feishu.cn/wiki/Xs9swNzvJi8kSUkXeJYcubCZnLg)

### 扫码 / 相机 / 扫描工具

**主路径**：打开相机 → 对准 → 识别 → 展示结果 → 复制/打开/保存。

- 常驻：历史记录、已保存结果列表。
- 插屏：用户完成结果消费后离开结果页；不在打开相机、取景、识别或权限弹窗前后。
- 激励：高清导出、长文档 OCR、额外保存格式。

相机是强连续操作场景；广告加载慢导致晚到时，会在用户已开始下一步时“意外弹出”。因此要在进入扫描流程时预加载，在合格断点才调用展示；广告未 Ready 则放弃，而不是让用户等广告。TopOn 也将“到达广告场景时广告已 Ready”视为独立漏斗指标，Ready 偏低应先调整合适场景的预加载。[[3]](https://help.toponad.net/cn/docs/qlHqYM)

### 遥控 / 投屏 / VPN 等持续会话工具

这类产品的使用中段没有真正的“任务结束”。连接、播放、遥控、VPN 活跃期间都不应插屏。

- 常驻：设备选择、媒体历史、设置、非核心列表页。
- 插屏：投屏会话已经结束、用户回到历史/结果页后；不能放在连接中、遥控按键操作中、视频播放中。
- 激励：一次高级投屏、单次镜像、特定高阶遥控能力；要明确“看广告可体验一次”。
- IAP：去广告和连续/高级能力适合做主商业化；广告密度应低于一次性任务型工具。

内部 TV Remote 竞品提供了有价值的对照：它以主页面干净、次级页面 Banner 和高级能力订阅为主，未用高频插屏打断遥控，符合持续会话工具的使用节奏。[[4]](https://vimedia.feishu.cn/wiki/Xs9swNzvJi8kSUkXeJYcubCZnLg)

### Launcher / 桌面聚合工具

Launcher 的核心不是单次任务，而是高频浏览，因此应以信息流/原生和低侵入 Banner 为主。

- 主屏、负一屏：在天气、新闻、搜索、推荐内容之间放清晰标识的信息流广告。
- 工具页：非系统工具的稳定页面可放 Banner；计算器、扫码等仍遵循“操作后而非入口前”的规则。
- 插屏：只在用户完成一次设置、完成默认桌面切换、或结束一个独立工具任务之后审慎测试；不应在 Home 手势、主屏交互和应用启动上触发。

内部 Easy Homescreen 的负一屏信息流是可借鉴的形态；新手引导完成或点击工具入口即强制弹窗则不宜照搬，应移到完成核心设置、首次进入桌面并完成初步体验之后。[[4]](https://vimedia.feishu.cn/wiki/Xs9swNzvJi8kSUkXeJYcubCZnLg)

## 6. 预加载不是多请求：如何避免“广告晚到”与资源浪费

预加载的目标是让广告在合格断点已经 Ready，而不是尽可能早、尽可能多地请求。

- **启动后预加载**：仅适用于位置浅、首会话后可能出现的稳定场景；首屏本身不要因此延迟。
- **进入功能后预加载**：适合 PDF 转换、清理、扫码等。用户开始处理时拉取，处理成功后才有机会展示。
- **接近深层场景时预加载**：适合二级工具、设备连接成功后可能打开的特定功能；不要在首页把所有深层位都请求一遍。
- **缓存失效/未 Ready**：本次任务直接放行；不能把广告加载当作用户的等待步骤。

TopOn 的漏斗资料指出：填充高但 Ready 低，通常说明用户到达场景时广告还未准备好；填充和 Ready 都低，则优先检查瀑布流/兜底配置。[[3]](https://help.toponad.net/cn/docs/qlHqYM) 这也意味着：展示率下降不必然代表失败，若预加载增加了未被展示的缓存请求，应结合人均展示、ARPDAU 和体验指标判断，不能单看一个比率。

## 7. 广告位要用“收益树”诊断，而不是只看 eCPM

广告设计的最终目标是长期人均价值，而不是把单次展示单价做得最高。最实用的拆解是：

```text
ARPDAU = 人均展示次数 × eCPM / 1000

人均展示次数
  = 广告场景到达率 × 触发展示率 × 展示成功率
```

穿山甲的官方收益优化资料同样将展示、点击和转化作为收益链路的关键节点；产品侧能直接改善的，首先是让正确的广告在正确场景完成有效展示。[[5]](https://www.csjplatform.com/growthcenter/6101274400195d0046c2731d)

**示意演算**：某结果页广告位每天有 10,000 DAU，场景到达率为 40%，展示成功率为 80%，eCPM 为 $12。若该位是自动展示，则日收入约为：

```text
10,000 × 40% × 80% × $12 / 1000 = $38.4/天
```

若把广告从“点击入口”改到“结果确认”，场景到达率可能下降，但展示成功率、有效性和留存可能上升。假设到达率变为 30%、展示成功率升为 95%、eCPM 升为 $14，则示意日收入约为 $39.9；即使它略低，只要 D1/D7、评分或后续任务次数改善，长期 LTV 仍可能更高。这里的数字只用于展示计算关系，不是预测。

诊断顺序应沿脊柱走：

1. **场景到达率低**：广告位太深或任务本身价值不足；先移到主路径的结果边界，不要先加频次。
2. **广告 Ready 低**：预加载太晚；在任务开始或接近场景时加载。
3. **触发展示率低**：激励价值不够清楚，或自动插屏的频控过严；分别处理，不能混用指标。
4. **展示成功率低**：排查缓存、遮挡、生命周期、SDK 回调和广告源。
5. **eCPM 低或收益不涨**：按国家、广告位、版本和广告源拆分，再决定瀑布流、底价或样式调整。

按广告位查看这些转化，才能定位“是入口过深、广告没准备好，还是展示逻辑失败”。[[3]](https://help.toponad.net/cn/docs/qlHqYM)

## 8. 埋点与验收：让“广告位设计”可被复盘

每一个广告位需求至少应包含以下字段：

| 字段 | 示例 |
|---|---|
| ad_unit_id | `pdf_compress_result_interstitial` |
| 场景 ID | `pdf_compress_result_acknowledged` |
| 业务前置条件 | 压缩成功、结果已渲染、用户点击继续或返回 |
| 预加载节点 | 用户点击“开始压缩”后 |
| 展示格式 | 插屏 / Banner / 原生 / 激励 |
| 频控键 | 全局、功能、用户日上限、会员豁免 |
| 兜底 | 未 Ready/加载失败立即继续业务，不重试阻塞 |
| 成功回调 | 真实 impression，不以 show 请求代替 |
| 体验指标 | 任务成功率、任务耗时、返回率、下一任务率、D1/D7 |

验收用例必须覆盖：首次启动、连续完成两次任务、在广告后立即切换功能、后台恢复、广告加载失败、会员、激励完成/跳过、断网、低端设备。尤其要验证“关闭广告后不会误触下一按钮”，以及“广告未 Ready 时结果页仍可立即操作”。

## 9. 实验与决策：什么情况下该上、该后移、该下线

一次实验只改一个变量，例如“结果刚出现”对比“用户确认结果后”、“仅 Banner”对比“Banner + 结果插屏”，不要同时改频控、瀑布流和广告格式。

主指标用 **ARPDAU 或 LTV**，而非 eCPM；辅助指标至少包括：

- 任务成功率、任务中断率、结果页停留和下一任务率；
- D1/D7、卸载、评分/投诉、崩溃；
- 场景到达率、Ready 率、触发展示率、展示成功率；
- 广告位层面的收入与用户反馈。

保留一个广告位的条件是：收益增量能覆盖对任务完成、留存和用户价值的影响。若 eCPM 提升但人均展示下降、任务中断增加或留存变差，它不是“成功优化”。Google 同样强调插屏过多、妨碍使用或造成意外点击会伤害体验并可能影响广告服务。[[1]](https://support.google.com/admob/answer/6201362?hl=en)

## 全文总结

理想广告位的脊柱是“任务完成漏斗”：用户取得结果之前，不用插屏打断；结果交付并被确认之后，才用频控、Ready 和用户状态筛选出可展示的机会。Banner 与原生服务于稳定停留页和内容流，插屏服务于可预期的任务终点，激励视频服务于用户主动选择的额外效用。内部竞品验证了结果页 Banner、负一屏信息流、低打扰订阅/高级能力承接的可行性，也暴露出启动、返回、功能入口和任务中途频繁插屏的体验风险。最终以广告位粒度走“到达—Ready—触发—展示—ARPDAU/LTV”链路，保留真正提高长期人均价值的节点，后移或下线其余节点。
