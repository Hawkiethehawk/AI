## 三、已验证结论（实测，不是文档抄录）

- **主键不强制唯一**：同一 `contentId` 可写入两次 → 查重必须自建。
- **查重公式只有一种写法可用**：`COUNTIF([表名], CurrentValue.[字段] = [字段])`；裸 `[字段]` 恒为 1，`[表名].[字段]` 直接报错。公式按表名引用，**表改名即失效**。
- **906 尺寸按手册**：970×160 / 970×265 / 970×625 / 975×500（模板表里的 1080 那套作废）。
- **903 无按钮**；**906 纯图片**，不读 `content`/`btnText`。
- **列类型坑**：`content`/`btnText` 不能用 URL 列（值会被存成 `[文本](url)`）；布尔用 `true`/`false` 单选，不要勾选列（勾选转文本会得到 `yes`/`no`）。
- **Base 没有条件格式 API**：`+cond-format-*` 属 sheets 域，标红只能在界面按视图配置（视图级，两个视图各配一次）。
- **新增字段只能追加到表尾**，且会自动出现在所有视图可见列末尾；列顺序必须用 `+view-set-visible-fields` 显式设定。
- **字段 PUT 是全量覆盖**：改备注必须原样带回 `style`（否则 URL 列降级为纯文本）、`options`（否则清空单选选项）、`expression`；`formula` / `lookup` 要加 `--i-have-read-guide`。
- **「我的文档库」不在 `wiki +space-list` 结果里**：用 `wiki spaces get --params '{"space_id":"my_library"}'` 解析；迁入用 `wiki +move --obj-type bitable --obj-token <base> --target-space-id <space_id>`，搬后公式列不受影响（公式引用表名，与文档所在位置无关）。
- **从 Python 调 lark-cli**：npm 的 sh 包装在 `subprocess` 下报 `WinError 2`，改用包内原生程序 `.../@larksuite/cli/bin/lark-cli.exe`（Skill 脚本统一用它）。
