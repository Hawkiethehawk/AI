## 研究边界

市场数据和竞品案例用于形成假设，不证明目标产品应采用相同策略。只保留方法、结构和可验证模式，不保留具体应用、开发者、商店链接、排名、市场份额、设备、内部阈值或原始业务数值。

只有不可读取内容或空模板而没有可读取正文时，不从中提取事实。无法从文本确认的广告触发、价格和用户流程标记为待验证。

## 市场筛选

### 定义问题

先确定品类、平台、地区、时间范围和目标，例如增长品类、主要市场、产品结构参考或商业化案例池。

### 采集字段

使用 AppMagic 或同类工具时统一采集：

- 品类、核心功能、发布和更新时间。
- 下载、收入和排名的时间趋势。
- 主要地区及其变化。
- IAA、IAP 或混合变现信号。
- 数据覆盖、缺失和估算边界。

固定时间边界和去重规则，按周期追加历史快照，不覆盖旧数据。

### 筛选与复核

1. 用趋势而不是单日排名筛选。
2. 将下载增长和收入增长分开观察。
3. 检查增长是否集中在单一地区或短时活动。
4. 标记新应用、小样本和数据缺失。
5. 将市场信号与产品功能和变现路径结合复核。

市场工具提供方向，不提供目标产品的真实线上流量；线上分组必须用自有数据校正。

## 产品拆解

按以下顺序记录：

1. 定位：品类、核心用户、核心任务和使用频率。
2. 功能：主页、核心功能、次要功能、内容区、设置和付费入口。
3. 用户流程：首次启动、核心任务、结果页、返回、再次启动和异常分支。
4. 广告链路：形式、位置、触发、频率、冷却、关闭去向和失败表现。
5. 付费链路：入口、权益、套餐、购买触发和去广告关系。
6. 优点与问题：分别说明产品价值、变现覆盖和体验风险。
7. 假设与验证：只提出目标产品可验证的最小改动。

产品事件与广告事件放在同一时间线，但使用不同字段，以判断广告发生在任务开始前、执行中还是完成后。

## 广告场景审查

每个场景都回答：

- 用户此时要完成什么任务。
- 广告是否位于自然断点。
- 是否由用户主动选择，权益是否可理解和兑现。
- 是否可能遮挡、误触或重复触发。
- 首次使用和返回用户是否需要不同策略。
- 关闭后回到哪里，需要哪些事件验证触发、展示和任务结果。

## 匿名模式

| 产品模式 | 可验证的广告思路 | 主要护栏 |
|:---:|:---|:---|
| 高频入口或桌面 | 内容流用原生，稳定工具页评估横幅，完成或返回节点测试插屏 | 首次设置和默认入口避免过早强制广告 |
| 文件处理或效率工具 | 结果页承接原生/横幅，完成后测试插屏，额外次数用激励 | 连续处理需频率和冷却，权益必须真实 |
| 休闲游戏 | 教程后在关卡边界使用插屏，道具和额外机会使用激励 | 教程优先理解玩法，避免广告遮挡操作 |
| 内容或个性化产品 | 列表用原生/信息流，主题和高级内容用激励或付费解锁 | 语言、权限、关闭和预览控件保持可见 |
| 前后台恢复 | 区分冷启动、热启动、短切换和长时返回 | 冷却，避免覆盖未保存输入或结果 |

激励广告提供即时或短期权益，去广告 IAP 提供持续权益；拒绝激励广告后仍应能回到正常任务。

## 从案例形成建议

1. 提取任务阶段、广告形式和触发逻辑。
2. 判断目标产品是否存在同类任务和自然断点。
3. 列出适用与不适用条件。
4. 设计一个主要变量的测试版本。
5. 补齐场景到达、广告漏斗和任务完成事件。
6. 定义收益指标、体验护栏和回退条件。

案例中的广告数量、频率、价格、地区和收入表现不是默认参数，目标产品数据未验证前只能作为假设。

## 交付模板

| 模块 | 内容 |
|:---:|:---|
| 研究问题 | 品类、市场、产品结构或变现机会 |
| 证据范围 | 工具、时间、地区、文本拆解和缺失项 |
| 产品模式 | 核心任务、使用频率和功能结构 |
| 商业化模式 | 广告形式、场景、付费入口和相互关系 |
| 体验风险 | 首次任务、连续操作、遮挡、误触和重复触发 |
| 可迁移假设 | 适用条件明确的设计或配置思路 |
| 验证方案 | 单一变量、事件、指标、护栏和回退 |

输出使用品类和场景描述，不引用具体产品名称或原始市场数值。
