## 总体阶段

| 阶段 | 主要操作 | 交付 |
|:---:|:---|:---|
| 发行前准备 | 评估产品、规模、地区、场景和埋点 | 场景清单、分组方案、埋点口径 |
| 需求确认 | 核对产品、广告范围、平台和限制 | 配置清单、参数字段、验收条件 |
| 平台配置 | 创建对象，配置广告源、分组、价格和兜底 | 对象映射、流量规则、配置版本 |
| 参数回填与验收 | 回填参数，用测试包验证链路和规则 | 回填记录、测试证据、验收结论 |
| 正式启用 | 核对范围，观察真实首轮流量 | 启用记录、分组结果、首轮检查 |

上一阶段交付不完整时，不进入下一阶段。每一阶段都按输入、操作、检查、交付执行。

## 六阶段执行

### 阶段一：发行前准备

#### 输入

产品核心功能、目标用户、使用频率、预估规模、重点地区、候选广告场景和预计触发次数。

#### 操作

1. 还原核心功能和完整任务路径。
2. 用活跃用户与单用户请求或展示预估初始规模。
3. 形成地区、用户阶段、组合规则和默认组。
4. 标记广告位置、形式、触发时机、频率和命中分组。
5. 为产品节点、广告节点、频率条件和异常设计埋点。

#### 检查

- 产品定位、核心任务和广告策略一致。
- 规模预估能由用户数和单用户触发次数解释。
- 具体规则优先，默认组可承接未命中流量。
- 产品链路和广告链路分开记录，关键节点可还原。

#### 交付

初始产品方案、广告场景清单、请求量预估、流量分组方案和埋点口径。

### 阶段二：需求确认

#### 输入

结构化需求记录和阶段一交付。

#### 操作

1. 核对平台、配置环境、广告形式和广告源范围。
2. 核对聚合方式、地区、用户阶段、命名要求和限制。
3. 核对优先级、时间、当前状态和阻塞项。
4. 检查字段一致性；缺失或冲突时退回补充，不猜测配置。
5. 明确参数回填位置和验收方式。

#### 检查

- 产品信息能唯一对应目标应用，但交付不暴露真实标识。
- 广告范围与候选场景一致。
- 环境、聚合方式、分组和广告源范围无冲突。
- 执行顺序和阻塞项明确。

#### 交付

确认后的配置清单、参数字段清单和验收条件。

### 阶段三：平台配置

#### 输入

已确认的配置清单、广告场景清单和流量分组方案。

#### 配置对象

| 对象 | 作用 | 关系 |
|:---:|:---|:---|
| 应用对象 | 代表应用和平台环境 | 关联广告位或广告单元 |
| 广告位/广告单元 | 承载一种形式和一组广告源 | 映射产品广告场景 |
| 广告场景 | 表示具体触发位置 | 记录触发、频率和所属广告位 |
| 广告源 | 提供需求和价格 | 进入竞价、Waterfall 或兜底 |
| 流量分组 | 按地区、用户阶段等条件分流 | 决定广告源和价格组合 |
| 配置版本 | 记录一次可回溯状态 | 关联启用、测试和复盘 |

#### 操作

1. 创建应用对象、广告位或广告单元。
2. 将产品场景与广告位一一映射；新场景使用唯一且可追踪编号。
3. 接入广告源，记录参数类型和启用状态。
4. 配置地区、用户阶段、组合规则和默认组。
5. 配置 Bidding、Waterfall、价格层级和兜底。
6. 保存配置版本和参数映射，不保存真实凭据。

推荐顺序（GEN-WORKFLOW，具体字段以平台当前页面为准）：

1. 创建应用对象。
2. 按广告形式和产品场景创建广告位或广告单元。
3. 为新场景分配唯一且可追踪的编号。
4. 接入广告源并记录参数类型。
5. 配置地区、用户阶段、组合规则和默认组。
6. 为各组配置竞价、Waterfall、价格和兜底。
7. 回填参数、自检、测试，保存快照后启用。

#### 检查

- 应用、广告位、形式、场景和广告源无遗漏或重复。
- 分组优先级正确，默认组有有效广告源和兜底。
- 价格和覆盖同时存在，主链路失败仍有承接路径。

#### 交付

平台配置、对象映射、流量规则、广告源组合和配置版本记录。

### 阶段四：参数回填与验收

#### 输入

平台配置、参数映射、广告控制规则和测试条件。

#### 参数映射

| 类别 | 记录内容 | 验证方式 |
|:---:|:---|:---|
| 应用 | 平台、环境、配置版本 | 与需求和测试包一致 |
| 广告位 | 形式、用途、所属应用 | 与产品场景一一对应 |
| 场景 | 触发位置、进入方式、控制规则 | 用产品事件和广告事件还原 |
| 广告源 | 参数类型、来源平台、状态 | 平台侧与广告源侧交叉核对 |
| 流量规则 | 地区、用户阶段、优先级、默认组 | 用测试或首轮真实流量验证 |
| 加载控制 | 预加载、缓存、并发、超时、兜底 | 用链路事件和耗时验证 |

#### 操作

1. 将应用、广告位、广告单元、广告源和场景参数回填到配置系统。
2. 回填广告形式、并发、超时、频次、间隔和用户分层规则。
3. 完成录入侧自检，确认字段完整、映射一致。
4. 用测试包验证请求、响应、可展示、展示、形式和关闭行为。
5. 验证地区、用户阶段、频率、间隔和默认组规则。
6. 将异常按平台配置、广告源、请求返回和 SDK 状态分层。

#### 检查

- 测试包接收的配置与平台记录一致。
- 请求到展示链路完整，失败能定位到阶段。
- 控制规则按预期生效。
- 配置问题与 SDK 集成或版本兼容问题已经分开。

#### 交付

参数回填记录、测试证据、异常清单和验收结论。

### 阶段五：正式启用

#### 输入

通过验收的配置、测试结论和启用范围。

#### 操作

1. 核对应用版本、广告位、地区范围、配置状态和启用时间。
2. 记录启用范围与配置版本，保证后续可回溯。
3. 检查真实流量是否进入预期地区和用户阶段。
4. 检查默认组是否承接未命中特定规则的流量。
5. 确认请求、响应、展示和收入已经产生。
6. 按广告位、形式、平台、广告源、地区和版本拆分首轮数据。

#### 检查

- 启用范围、版本和配置状态准确。
- 分组生效由配置记录和真实流量共同证明。
- 首轮数据覆盖请求、展示和收益。

#### 交付

正式启用记录、分组生效结果和首轮数据检查结果。

### 阶段六：复盘与调整

#### 输入

启用记录、首轮数据、当前配置快照和版本变化记录。

#### 操作

1. 在统一口径下按应用、广告位、地区、用户阶段、流量组和广告源查看请求、展示、eCPM 和收益。
2. 先确认场景到达，再检查请求、响应、可展示、展示和耗时。
3. 链路正常后再分析 eCPM、价格层级和广告源结构。
4. 无请求、无展示、映射错误、广告源不可用或数据缺失时立即排查。
5. 调整前保存快照，一次只改变一个主要变量。
6. 记录影响范围、观察指标、体验护栏和回退条件。
7. 证据不足时记录继续观察项，不把假设写成结论。

#### 检查

- 不同平台保持各自数据口径，不直接混合。
- 调整变量与异常节点对应。
- 观察范围和回退条件在调整前已确定。
- 结论可追溯到数据、配置记录或观察依据。

#### 交付

复盘结论、异常定位、调整记录、观察结果和回退记录。

## 流量分组

- 先用少量、可解释的分组建立稳定配置，再根据真实数据增加粒度。
- 主要地区或表现差异明显的地区可独立成组；长尾地区按相近表现合并。
- 新用户和返回用户的判定字段必须统一，并能由产品事件验证。
- 地区与用户阶段的组合规则排在单维度规则之前。
- 默认组必须保留有效广告源和兜底，不能关闭或空置。
- 规则变化后检查流量占比，避免优先级错误把流量导入意外分组。

分组名称只是配置标签。规则、请求记录和真实流量共同证明是否生效。

## Bidding、Waterfall 和兜底

- Bidding 让支持竞价的广告源参与同次机会竞争。
- Waterfall 按价格或策略层级补充非竞价覆盖。
- 兜底在主链路没有可展示广告时承接剩余流量。

配置时检查竞价组是否正确、Waterfall 层级是否与地区和形式匹配、提价是否造成填充或展示下降、低价层和兜底是否覆盖未填充流量，以及新增或移除广告源的增量贡献；平台层级和竞价行为可对照 **[IAA-TOPON-02-价格和底价]** **[IAA-TOPON-05-Waterfall 结构]** **[IAA-TOPON-17-广告分层入门和优化技巧]**。

不要从单次 eCPM 上升推断总收益一定上升。价格调整必须同时观察展示量、填充和总收益。

## 加载控制

展示失败按以下顺序检查：

1. 场景前是否发起预加载。
2. 返回广告是否进入可展示状态。
3. 缓存是否过期、被消费或与页面生命周期不一致。
4. 单平台或整体超时是否过早放弃可用广告。
5. 并发请求是否导致结果覆盖、重复消耗或请求未展示。
6. 前后台切换、页面销毁和重复进入是否清理错误状态。

每个阶段记录事件和耗时。只有请求与展示两个事件时，无法区分响应、缓存、可展示状态和页面问题；报表延迟、时区和展示字段可对照 **[IAA-TOPON-09-数据来源]** **[IAA-TOPON-19-聚合管理（Waterfall）报表数据说明]**。

## 平台语义

| 统一语义 | TopOn 常见对象 | MAX 常见对象 | AdMob 常见对象 |
|:---:|:---|:---|:---|
| 应用 | App | App | App |
| 广告承载对象 | 广告位 | Ad Unit | Ad Unit |
| 广告源组合 | 广告源与 Waterfall | Network 与 Waterfall | Mediation group 与广告源 |
| 流量拆分 | 流量分组 | 国家或规则分组 | 中介组定向规则 |

对照只用于理解对象关系。实际字段、能力和回传口径以当前配置记录和用户提供的数据为准。

## 阶段门禁

| 门禁 | 通过条件 |
|:---:|:---|
| 设计 | 核心任务、广告场景、分组和埋点对齐 |
| 需求 | 字段完整一致，配置范围和验收方式明确 |
| 配置 | 平台对象、广告源、分组、价格和兜底完整 |
| 验收 | 参数映射一致，测试链路和控制规则符合预期 |
| 启用 | 真实流量进入预期分组，首轮数据已经产生 |
| 调整 | 异常范围、单一变量、护栏和回退条件明确 |

## 验收、整改和自动化边界

验收至少覆盖：参数映射、请求到展示事件、广告形式、频率、间隔、地区、用户阶段、默认组和兜底。配置问题、广告源状态问题和 SDK 集成问题要分层。

变更前保存快照，写明原因、影响广告位、观察指标、体验护栏和回退条件；一次只改变一个主要变量。

收到政策问题后，先整改真实展示行为并发布验证版本，再覆盖相关页面、关闭路径和目标广告场景，最后只陈述已完成且可证明的整改。复审文案不能代替整改。

自动化适合对象创建、字段映射、批量校验、配置差异和报表整理。场景选择、体验边界、价格和广告源调整、启用范围及回退条件仍需人工确认。任何写入平台的动作都先展示拟变更对象和影响范围。
