# 漏斗分析报表

## 1. 功能概述

您可以通过漏斗分析报表分析App在广告变现链路中各个核心环节的数据，

包括： **应用启用>获取策略>请求广告>缓存广告（到达广告场景）>展示广告>点击广告**

同时，通过广告变现链路各个核心环节之间的**转化率**，您可以分析和进一步优化App广告变现策略。

## 2. 操作指引

想要通过漏斗发现数据问题并解决，可以按照下列步骤进行：

**(1) 在漏斗报表页面选择应用和广告位**

   推荐区分广告位查看数据，所有广告位汇总的人均次数无法定位具体问题）。

**(2) 切换设备数或DAU查看人均次数**

   通过DAU计算人均数据，可以清晰看到各个流程的用户流失率。

**(3) 查看当前广告位各个流程的转化率**

   通过查看每个指标的说明和当前指标的数值，判断当前指标数值是否异常，按照参考的提升方案对后台配置进行修改/对SDK进行修改

**(4) 进行优化操作后，通过分天数据或趋势图查看指标的变化趋势，观察优化操作是否生效**

****



## 3. 相关数据说明

### 3.1 漏斗指标

漏斗分析报表包括两部分数据：**事件、转化率。**

- **事件：广告变现漏斗模型中的核心事件的数据指标，如：应用启动、流量请求、展示、点击等。**
- **转化率：核心事件之间的转化率，基于事件次数或设备数进行计算，如：流量填充率、展示率、点击率等。**



| 指标名称 | 类型 | 统计口径 | 说明及建议 |
| --- | --- | --- | --- |
| 应用启动 | 事件 | 应用启动并成功初始化TopOn SDK | 由于统计口径及数据上报逻辑的差异，TopOn应用启动数据跟第三方统计SDK数据存在差异 |
| 获取配置 | 事件 | 应用向TopOn服务器请求广告位策略 | 当获取策略设备数明细少于应用启动设备数时，建议您在适当场景增加广告预计加载逻辑（您也可考虑使用TopOn的全自动加载模式来简化代码接入逻辑，[查看接入说明](/cn/docs/Q82OTF)） |
| 流量请求 | 事件 | 应用向TopOn发送广告请求的次数 | - |
| 流量填充 | 事件 | 应用向TopOn发送广告请求后，TopOn返回广告请求填充成功 | 当流量填充数明显少于流量请求时，可以考虑在聚合管理的WaterFall配置增加无底价的广告源作为兜底 |
| 流量填充率 | 转化率 | **流量填充 / 流量请求** | 针对广告位或广告源无填充问题，您可以通过日志分析查询不填充的原因，[查看日志分析说明](/cn/docs/qX9b40) |
| 到达广告场景 | 事件 | 用户到达广告场景的次数 | 应用需要调用TopOn的**entryAdScenario**接口才可统计。[参考TopOn SDK文档说明添加到达广告场景代码](/cn/docs/1RWLAv#5._%E5%B9%BF%E5%91%8A%E5%9C%BA%E6%99%AF%E7%9A%84%E6%8E%A5%E5%85%A5%E4%BB%A3%E7%A0%81%E7%A4%BA%E4%BE%8B) |
| 广告场景到达率 | 转化率 | **到达广告场景的设备数 / 应用启动的设备数** | 1.用户到达广告场景时，应用需要调用TopOn的entryAdScenario方法才可统计。[参考TopOn SDK文档说明添加到达广告场景代码](/cn/docs/1RWLAv) 2. 不同广告场景的到达率可以反映出广告场景设计的合理性，通过横向对比广告场景到达率可以进一步优化应用的广告场景设计 |
| 广告Ready率 | 转化率 | **用户到达广告场景时，广告已经ready的占比** | 当广告Ready率偏低时，建议您在适当场景增加广告预计加载逻辑（您也可考虑使用TopOn的全自动加载模式来简化代码接入逻辑，[查看接入说明](/cn/docs/Q82OTF)） |
| 查询isReady | 事件 | 应用调用TopOn的isReady接口 | - |
| isReady成功率 | 转化率 | **TopOn isReady接口返回True的占比** | 针对isReady成功率低的问题可以从以下方式进行定位： 1. 确定调用isReady的场景是否合理，会不会过于频率 2. 在适当场景增加广告预计加载逻辑（您也可考虑使用TopOn的全自动加载模式来简化代码接入逻辑，[查看接入说明](/cn/docs/Q82OTF)） |
| 触发展示 | 事件 | 应用调用TopOn的Show接口(原生、横幅广告为触发TopOn展示逻辑) | 如果您使用广告场景，需要在调用Show方法时传入广告场景ID，[参考TopOn SDK文档说明添加广告场景ID](/cn/docs/1RWLAv#4._%E5%88%9B%E5%BB%BA%E5%B9%BF%E5%91%8A%E5%9C%BA%E6%99%AF%E5%8F%8A%E8%8E%B7%E5%8F%96%E5%B9%BF%E5%91%8A%E5%9C%BA%E6%99%AFID) |
| 广告触发率 | 转化率 | **触发展示的次数 / 到达广告场景的次数** | 1. 到达广告场景后，用户触发观看广告的占比。 2. 针对激励视频，如果广告触发率低可以考虑增加激励来刺激用户观看广告。其他广告类型的广告触发由应用处理，可以考虑优化触发广告展示的逻辑 |
| 触发展示成功 | 事件 |  | TopOn统计的成功调用三方广告平台展示 |
| 触发展示成功率 | 转化率 | **触发展示成功/触发展示\*100%** | 应用调用TopOn的Show接口后，TopOn成功调用三方广告平台展示的比例。 |
| 展示 | 事件 | 从2023年3月7日 0点（UTC+8）起，统计口径从“TopOn调用广告平台SDK开始展示的次数”调整为“TopOn收到广告平台SDK展示成功的回调次数” | - |
| 展示成功率 | 转化率 | **展示的次数 / 触发展示的次数** | 针对广告位或广告源展示失败问题，您可以通过日志分析查询展示失败的原因，[查看日志分析说明](/cn/docs/qX9b40) |
| 展示API | 转化率 | TopOn通过API向广告平台拉取到的广告曝光数。由于统计口径差异、网络丢包等因素，TopOn展示与广告平台展示可能存在一定差异。 | 展示API数据基于广告平台Report API 或 上传三方数据，建议您按文档[完成各个广告平台Report API对接](/cn/docs/2KR6QU)或[手动上传三方数据](/cn/docs/yU7A3C) |
| 展示gap | 转化率 | **(展示的次数-展示API)/ 展示API** | TopOn统计展示与广告平台统计展示的差异。可参考**2. 漏斗分析常见问题**进行排查 |
| 点击 | 事件 | TopOn统计的广告点击 | - |
| 点击率 | 转化率 | **点击的次数/展示的次数** | Topon统计的广告点击率 |

> **注：**
> 1. 应用启动数据为应用维度整体数据，不区分广告位、广告场景
> 2. 展示API不支持分广告场景、渠道、SDK版本、应用版本，不支持查看设备数和人均次数
> 3. 展示gap不支持分广告场景、渠道、SDK版本、应用版本，不支持查看设备数和人均次数

## 4. 常见问题

**(1) 应用启动数据偏少**

由于统计口径及数据上报逻辑的差异，TopOn应用启动数据跟第三方统计SDK数据存在差异。

**(2) 获取策略比应用启动多**

① 获取策略次数比应用启动次数多：正常现象。由于应用在启动会存在多个广告位，而不同广告位均会向TopOn独立请求广告位策略，所以获取策略次数会比应用启动次数多。

② 获取策略设备比应用启动设备多：应用在一次生命周期内存在跨天的情况会出现，但此类情况产生的数据Gap较少。当DAU较少而跨天用户较多时，数据Gap可能会比较明显。

**(3) 流量请求比获取配置多**

① 流量请求次数比获取配置次数多：正常现象。由于TopOn SDK会对策略进行缓存，在缓存有效期内，可以发起多次的流量请求，所以流量请求次数会比获取配置次数多。

② 流量请求设备数比获取配置设备数多：

- 针对开屏广告，如果使用首次兜底开屏配置会出现此情况。
- 其他广告类型出现此情况时，有可能是部分用户在断网状态下使用应用。

**(4) isReady调用设备数比流量请求设备数多**

当isReady调用设备数比流量请求设备数多时，说明有部分设备未触发广告请求，这时可以从以下两个方面进行优化：

① 确定调用isReady的场景是否合理，会不会过于频率，可以适当调整调用isReady的逻辑。

② 确定广告请求逻辑是否合理，您可以考虑在适当场景增加广告预计加载逻辑（您也可考虑使用TopOn的全自动加载模式来简化代码接入逻辑，查看接入说明）。

**(5) 广告场景到达率偏低**

广告场景到达率偏低一般是由于广告场景设计不合理或广告入口设置太深，用户无法到达相应的广告场景。同时，通过横向对比不同广告场景的到达率，您可以进一步优化应用的广告场景入口设计。

**(6) 流量填充率偏低**

针对流量填充率偏低的问题可以从以下方面进行优化：

**① 当流量填充数明显少于流量请求时，可以考虑在聚合管理的WaterFall配置增加无底价的广告源作为兜底。**

② 针对开屏广告，您可以考虑增加兜底广告源，查看开屏兜底说明。

③ 同时，您可以通过日志分析查询广告位或广告源不填充的原因，查看日志分析说明。

**(7) 广告Ready率偏低**

当广告Ready率偏低，您需要结合流量填充率一起分析：

① 流量填充率高，但广告Ready率低：说明用户到达广告场景时还没有广告可以展示，建议您在适当场景增加广告预计加载逻辑（您也可考虑使用TopOn的全自动加载模式来简化代码接入逻辑，查看接入说明）。

② 流量填充率低，同时广告Ready率低：说明WaterFall配置有问题，可以考虑在WaterFall配置增加无底价的广告源作为兜底。同时您可以通过日志分析查询广告位或广告源不填充的原因，查看日志分析说明。

③ 针对开屏广告，您可以考虑增加兜底广告源，查看开屏兜底说明。

**(8) 广告触发率偏低**

① 针对激励视频，如果广告触发率低可以考虑增加激励内容来刺激用户观看广告。

② 其他广告类型的广告触发由应用处理，可以考虑优化触发广告展示的逻辑。

**(9) 广告触发率超过100%**

**① 广告触发率=触发展示的次数 / 到达广告场景的次数**， 您需要确定应用是否正确添加了**到达广告场景、调用Show**的代码。

**② 到达广告场景：用户到达广告场景时，应用需要调用TopOn的entryAdScenario方法统计到达广告场景, 参考TopOn SDK文档说明添加到达广告场景代码。**

**③ 调用Show: 应用在展示广告时，需要在调用Show方法时传入广告场景ID，参考TopOn SDK文档说明添加广告场景ID。**

**(10)触发展示成功率偏低**

可通过日志分析查看详细展示错误的原因，请选择异常的广告位。可能存在缓存过期，或SDK接入问题导致广告展示失败的情况。

**(11) 展示成功率偏低**

**① 针对激励视频和插屏广告，您可以通过日志分析查询广告位或广告源展示失败的原因，查看日志分析说明。**

**② 针对原生、Banner、开屏广告，您需要检查展示广告代码逻辑是否有问题。**

**(12) 展示Gap超过15%**

展示Gap的问题通常有多种原因引起，您可以尝试从以下方面入手：

**① 展示API数据基于广告平台Report API对接或上传三方数据，建议您按文档完成各个广告平台Report API对接或手动上传三方数据。**

② Report API拉取展示API数据会存在时延问题，对于各天最新的数据您可以在以下时间节点查看数据：

- utc+8：延迟1天，下午18:00点（utc+8）更新
- utc+0：延迟1天，下午 18:00点（utc+8）更新
- utc-8：延迟2天，上午1:30点（utc+8）更新

**③ 如果已完成Report API对接或上传三方数据还有展示Gap，可以通过以下方法排查**

**展示API偏多：**

排查三方广告位ID是否有复用（同个三方广告平台的广告位ID配置在TopOn不同的广告源上）？

**展示API偏少：**

- **某广告平台某广告类型的全部广告源均存在展示Gap问题：有可能是代码集成问题，可参考10. 展示成功率低的方法，排查展示失败的原因。**
- 某广告平台某广告类型的个别广告源存在展示Gap问题：该广告源展示被广告平台判定为无效展示，可以尝试跟广告平台沟通。
