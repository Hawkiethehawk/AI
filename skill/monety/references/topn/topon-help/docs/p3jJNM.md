# 留存价值报表

## 1. 功能概述

数据报表下拉后可进入留存价值报表，留存价值报表支持从LTV、展示、留存和新老用户4个维度查看用户留存价值数据。

## 2. 操作指引

### 2.1 LTV报表

**(1) 内容概况**

LTV报表包括LTV趋势图和报表2部分，支持查看最长60天的LTV数据，支持的筛选维度包括应用、地区和渠道。报表可以切换TopOn统计的LTV数据和三方平台统计的LTV数据。



**(2) 相关数据说明**

报表涉及到的筛选项及指标说明如下：

| 筛选项 | 说明 |
| --- | --- |
| 日期 | 数据产生的时间段。**注意**：每次最多选择60天的日期。 |
| 应用 | 在TopOn创建的应用。 [>>更多](/cn/docs/pzi00q) |
| 地区 | 用户所在的国家/地区 |
| 渠道 | 开发者可将渠道字段传至TopOn,以便区分用户不同来源渠道的数据。 [>>如何通过自定义规则传渠道字段？](/cn/docs/KjVUSq#3._TopOn_SDK%E8%AE%BE%E7%BD%AE%E6%B5%81%E9%87%8F%E5%88%86%E7%BB%84%E8%87%AA%E5%AE%9A%E4%B9%89%E8%A7%84%E5%88%99) |

| 数据指标 | 说明 |
| --- | --- |
| 新增用户 | 首次使用应用的用户数（基于TopOn统计数据） |
| 新用户占比 | 首次使用应用的用户数（基于TopOn统计数据）占日活跃用户的比例。计算公式：新用户/DAU |
| LTV | LTV(life time value)生命周期总价值，在获得新用户后的一段时间内，平均每一位用户的收益价值。 **注意**：报表中显示的是平均每个新增用户产生的累计广告收益 |
| TopOn统计数据 | 竞价广告源以实时的广告展示价格汇总得的LTV，非竞价广告源以人工填写的eCPM价格 \* TopOn统计的展示汇总得出的LTV **注意**：人工填写的eCPM价格尽量接近实际的eCPM，则可以相对准确的预估当天的LTV数据表现。 |
| API统计数据 | 通过三方平台API接口拉取的LTV数据 |
| LTV n | 新用户在第n天内产生的人均收益价值 |

### 2.2 展示报表

**(1) 内容概况**

通过展示报表可查看不同维度展示的波动情况，支持的筛选维度包括时间、应用、广告类型、广告位、地区和渠道。展展示报表可以切换总展示和人均展示的数据。



**(2) 相关数据说明**

报表涉及到的筛选项及指标说明如下：

| 筛选项 | 说明 |
| --- | --- |
| 日期 | 数据产生的时间段。**注意**：每次最多选择60天的日期 |
| 应用 | 在TopOn创建的应用。 [>>更多](/cn/docs/pzi00q) |
| 广告位 | 在TopOn创建的广告位。 [>>更多](/cn/docs/pzi00q#2._%E5%B9%BF%E5%91%8A%E4%BD%8D%E7%AE%A1%E7%90%86) |
| 广告类型 | TopOn广告位的分类，包括激励视频、插屏、原生、Banner和开屏 |
| 地区 | 用户所在的国家/地区 |
| 渠道 | 开发者可将渠道字段传至TopOn,以便区分用户不同来源渠道的数据。 [>>如何通过自定义规则传渠道字段？](/cn/docs/KjVUSq#3._TopOn_SDK%E8%AE%BE%E7%BD%AE%E6%B5%81%E9%87%8F%E5%88%86%E7%BB%84%E8%87%AA%E5%AE%9A%E4%B9%89%E8%A7%84%E5%88%99) |

| 数据指标 | 说明 |
| --- | --- |
| 新增用户 | 首次使用应用的用户数（基于TopOn统计数据） |
| 总展示 | 第N日的新用户累计展示数 |
| 人均展示 | 第N日的新用户累计展示数/第N日的新用户 |

### 2.3 留存报表

**(1) 内容概况**

通过留存报表，可以查看每日新增用户和每日用户留存情况，支持查看最长60天的留存数据，支持的筛选维度包括应用、地区和渠道。



**(2) 相关数据说明**

报表涉及到的筛选项及指标说明如下

| 筛选项 | 说明 |
| --- | --- |
| 日期 | 数据产生的时间段。**注意**：每次最多选择60天的日期 |
| 应用 | 在TopOn创建的应用。 [>>更多](/cn/docs/pzi00q) |
| 地区 | 用户所在的国家/地区 |
| 渠道 | 开发者可将渠道字段传至TopOn，以便区分用户不同来源渠道的数据。 [>>如何通过自定义规则传渠道字段？](/cn/docs/KjVUSq) |

| 数据指标 | 说明 |
| --- | --- |
| 新增用户 | 首次使用应用的用户数（基于TopOn统计数据） |
| 留存 | 用户留存情况。用户在某段时间内开始使用应用产生网络请求，经过一段时间后，仍然在该应用中产生网络请求的用户。 计算公式：（某一天的新增用户在第N天继续打开应用的用户/某一天的新增用户）\*100%。 |

### 2.4 新老用户报表

**(1) 内容概况**

新老用户报表可以查看详细的新增用户和全部用户数据，覆盖了完整的广告指标链路，包括用户数、DEU、渗透率、预估收益、预估收益/用户数、预估eCPM、竞价、竞价响应率、流量请求、流量填充率、广告场景到达数、广告Ready率、展示、展示率、展示/DAU、点击和点击率。

支持的筛选维度，包括日期、应用、广告类型、广告位、地区、广告平台和渠道，支持切换数据预览图指标，支持报表导出。



**(2) 相关数据说明**

报表涉及到的筛选项及指标说明如下：

| 筛选项 | 说明 |

| 日期 | 数据产生的时间段。**注意**：每次最多选择60天的日期 |
| 应用 | 在TopOn创建的应用。 [>>更多](/cn/docs/pzi00q) |
| 广告位 | 在TopOn创建的广告位。 [>>更多](/cn/docs/pzi00q#2._%E5%B9%BF%E5%91%8A%E4%BD%8D%E7%AE%A1%E7%90%86) |
| 广告类型 | TopOn广告位的分类，包括激励视频、插屏、原生、Banner和开屏 |
| 地区 | 用户所在的国家/地区 |
| 广告平台 | 三方广告平台 |
| 渠道 | 开发者可将渠道字段传至TopOn,以便区分用户不同来源渠道的数据。 [>>如何通过自定义规则传渠道字段？](/cn/docs/KjVUSq#3._TopOn_SDK%E8%AE%BE%E7%BD%AE%E6%B5%81%E9%87%8F%E5%88%86%E7%BB%84%E8%87%AA%E5%AE%9A%E4%B9%89%E8%A7%84%E5%88%99) |

| 数据指标 | 说明 |
| --- | --- |
| 用户类型 | 区分新用户老用户（全部用户） |
| 用户数 | 日活跃用户(Daily Active User)，即初始化TopOn SDK的设备用户数。 **注意**：根据GDPR协议，欧盟地区需要用户同意后才会统计数据。[>>什么是GDPR？](/cn/docs/MWsWVm) |
| DEU | 每天观看过广告的独立用户数。2023年6月15日 0点（UTC+8）起修改用户统计口径。DEU支持应用、广告位、广告类型3种维度，不同筛选条件下，DEU的数据会有所变化。 |
| 渗透率 | 每天展示（曝光）过广告的设备用户数占日活跃用户的比例。计算公式：DEU/DAU\*100% |
| 预估收益 | 根据TopOn SDK统计的展示数和eCPM价格进行预估的收益。计算公式：①非竞价广告源：人工填写的eCPM价格 \* TopOn统计的展示汇总；②头部竞价广告源：实时的广告展示价格汇总。[>>头部竞价说明](/cn/docs/dfnwQG) |
| 预估收益/用户数 | 人均预估收益，预估收益/用户数 |
| 预估eCPM | 根据预估收益和TopOn统计的展示计算出预估eCPM，计算公式：（预估收益/TopOn统计的展示）\*1000。注：1、预估 eCPM当天提供；2、常规广告源基于手动填写的eCPM价格计算，竞价广告源基于实时竞价价格计算 |
| 竞价 | 头部竞价（Header Bidding）广告源发起的竞价次数。[>>头部竞价说明](/cn/docs/dfnwQG) |
| 竞价响应率 | 头部竞价（Header Bidding）广告源竞价响应率。计算公式：竞价相应次数/竞价次数\*100%。 [>>头部竞价说明](/cn/docs/dfnwQG) |
| 流量请求 | 应用（客户端）向TopOn SDK发起的请求（Load)次数 |
| 流量填充率 | 应用（客户端）向TopOn SDK发起请求（Load）后，广告返回成功的占比。计算公式：流量请求返回成功数（流量填充数）/流量请求\*100% |
| 广告场景到达 | 用户到达广告场景的次数，App需要调用entryAdScenario方法才可统计 |
| 广告Ready率 | 用户到达广告场景时，广告已经ready的占比 |
| 展示 | 从2023年3月7日 0点（UTC+8）起，统计口径从“TopOn调用广告平台SDK开始展示的次数”调整为“TopOn收到广告平台SDK展示成功的回调次数”。由于统计口径不一样，TopOn统计的展示与广告平台统计的展示（展示API）可能存在一定差异 |
| 展示率 | TopOn统计的广告曝光次数占流量请求返回成功数（流量填充数）的比例。计算公式：展示/流量填充数\*100% |
| 展示/DAU | 展示（曝光）过广告的设备用户的人均展示次数 |
| 点击 | TopOn统计的广告点击数。部分平台不提供点击回调（如Admob的激励视频），导致TopOn无法统计到用户的点击行为 |
| 点击率 | TopOn统计的广告点击数占TopOn统计的广告曝光次数的比例。计算公式：点击/展示\*100% |

## 3. 常见问题

**(1) LTV和预估LTV有什么区别**

**最大区别：LTV的eCPM是根据广告平台拉取回来的实际收益以及TopOn埋点统计的展示换算得出；预估LTV的eCPM是人工填写的eCPM价格。**

① LTV是根据从广告平台拉取回来的实际收益以及TopOn埋点统计的展示，按照公式拆分到设备维度换算出来的LTV。

② 预估LTV的eCPM为人工填写的eCPM价格，其他计算公式均与LTV一样。

③ 预估LTV报表支持显示当天的数据；LTV报表最快显示前一天的数据。
