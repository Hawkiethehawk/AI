# 配置建议与实验工作流

## 建议结构

| 字段 | 内容 |
|---|---|
| 观察 | 数据中发生了什么 |
| 证据 | 时间范围、对象、指标和贡献 |
| 假设 | 建议所依赖的机制 |
| 替代解释 | 仍未排除的其他原因 |
| 动作 | 要测试的 TopOn 对象和参数 |
| 范围 | 国家、应用、广告位、版本、流量比例 |
| 主要指标 | 收入、eCPM、展示或漏斗指标 |
| 护栏指标 | 留存、崩溃、启动时长、投诉或其他体验指标 |
| 决策条件 | 扩大、继续观察或回滚的规则 |

## 选择动作

根据数据定位到可操作层级：

- 请求量问题：检查产品触发、频控、场景覆盖和版本行为。
- 填充问题：检查广告源状态、国家覆盖、竞价参与、瀑布和底价。
- 展示转化问题：检查加载时机、缓存、超时、展示条件和用户离开。
- eCPM 问题：先控制流量结构，再检查同细分单元的广告源和竞价配置。
- 单一广告源问题：查看增量收入贡献和替代广告源承接，不只看该广告源 eCPM。

所有参数名称和平台限制先从本地 TopOn 文档确认。

## 实验设计

优先执行单变量、小流量、可回滚实验。保持对照组和实验组在日期、国家、版本、广告位和用户层级上可比。预先写明观察窗口，避免看到短期波动后改变成功标准。

如果 TopOn 的分流机制不能保证用户稳定分组，或者同一用户会跨组，先查平台文档并在结论中说明污染风险。

实验开始前处理：

- 使用完整自然日，覆盖可比较的星期结构和数据回补延迟。
- 预先定义主要指标、护栏指标、最小可接受变化和观察窗口。
- 根据基线方差与目标变化估算样本量；低流量时延长窗口，不靠单日涨跌决策。
- 检查实验组与对照组样本比例异常（SRM）和关键维度失衡。
- 避免持续窥视后提前结束；多组或多指标同时检验时说明多重比较风险。
- 同时保存配置前快照、实验版本、分组规则和实际生效时间。

## 禁止使用固定最优值

不要从行业经验直接给出通用最优底价、瀑布层数、并发请求数或广告频次。经验可以生成候选范围，但最终参数要由当前国家、广告样式、广告位和用户体验数据验证。

## 执行权限

默认输出建议和实验计划，不修改线上配置。用户要求执行时，重新确认环境、应用、广告位、流量组、参数旧值、参数新值、开始时间和回滚方法。高影响改动优先保存变更前快照。
