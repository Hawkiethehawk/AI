# 证据模型与分析护栏

## 信息角色

把输入分成五类，不允许相互替代。

| 标签 | 内容 | 可支持的结论 |
|---|---|---|
| `[文档]` | TopOn 帮助中心和接口说明 | 产品能力、字段含义、调用方法、平台约束 |
| `[观测]` | 上传文件、API 返回、用户确认事件 | 指定对象和时间范围内发生的事实 |
| `[计算]` | 从观测数据复算的指标和变化 | 变化规模、贡献维度、漏斗位置 |
| `[推断]` | 与证据一致但未排除其他解释的原因 | 调查方向和实验假设 |
| `[建议]` | 拟测试或执行的动作 | 后续决策，不构成已证实结论 |

## 必须执行的检查

在分析开始前确认：

1. 数据覆盖的日期、时区和币种。
2. 数据来自 TopOn SDK 统计、TopOn 三方 API、广告平台结算还是其他系统。
3. 每行粒度以及应用、国家、广告位、广告源、版本等维度是否互斥。
4. 收入是否为预估值、结算值或换算值。
5. 比率能否从原始分子和分母重算。
6. 对比期间是否包含版本发布、流量采购变化、节假日、合规弹窗或线上事故。

## 禁止推断

- 不根据帮助文档判断用户当前表现好坏。
- 不使用无来源的行业均值给具体底价、频控、瀑布层数或并发数。
- 不把相关性写成因果关系。
- 不把行级 eCPM、填充率或展示率直接求平均。
- 不把 DAU 等非可加指标跨国家、广告位或广告源求和。
- 不把 SDK 实时口径与广告平台结算口径混为同一事实。
- 不把缺失值默认为 0，除非数据定义明确说明。

## 处理口述信息

把用户口述转为结构化上下文：事件时间、影响对象、预期机制、可验证指标和可取得的数据。用户确认的发布记录可以标为 `[观测]`；“可能是某广告源降价”仍标为 `[推断]`。

口述缺少关键范围时，先采用最窄的合理假设并明确写出。若假设会改变配置对象或结论方向，向用户确认。

## 结论置信度

使用“高、中、低”描述证据完整性，不输出伪精确概率。

- 高：原始指标完整，前后周期可比，主要替代解释已排查。
- 中：方向稳定，但缺少一个重要维度或同期事件信息。
- 低：样本短、口径不明、只有聚合比率或依赖口述推断。
