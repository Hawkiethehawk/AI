## 核心指标

| 指标 | 定义或公式 | 用途 |
|:---:|:---|:---|
| 付费转化率 | 付费用户 / 新增用户，或 install 到 paid | 判断整体变现效率 |
| 试用启动率 | 启动试用 / 付费墙曝光 | 判断付费墙吸引力 |
| 试用转化率 | 转为付费 / 启动试用 | 判断试用期价值和到期承接 |
| ARPU | 总收入 / 全部用户 | 观察全体用户价值 |
| ARPPU | 总收入 / 付费用户 | 观察付费用户价值 |
| LTV / install | 用户净终身价值 / 新增用户 | 作为长期取舍依据 |
| MRR / ARR | 月度或年度经常性收入 | 观察订阅存量 |
| 净收入 | 收入减商店费用、退款、税费等 | 用于对账和净 LTV |

| 指标 | 定义或用途 |
|:---:|:---|
| 续订留存 | 第 N 期仍订阅 / 首期付费，按队列观察 |
| 流失率 | 1 - 对应周期续订留存 |
| 主动流失 | 用户主动取消或不再续订 |
| 被动流失 | 扣款失败导致的流失 |
| 挽回率 | 重试或宽限期内恢复扣款 / 进入挽回流程的订阅 |
| 退款率 | 退款金额或单数 / 对应收入或订单 |

## 结算与估算口径

商店结算数据用于确认最终净收入；订阅平台或 SDK 的实时数据用于漏斗、队列和趋势诊断。Apple、Google 的订阅后台和服务端状态机制分别参照 **[IAP-APPLE-01-App Store 订阅]** **[IAP-APPLE-02-启用 App Store 服务端通知]** **[IAP-GPLAY-01-关于订阅]** **[IAP-GPLAY-02-购买生命周期]**。两者会因退款、税费、汇率、延迟和口径不同产生差异。

LTV 使用净结算口径；实时估算只用于及时定位问题。对账时不要用实时估算替代结算数据。

## LTV 树和转化漏斗

订阅 LTV 可拆为：

LTV / install = 付费墙触达率 × 试用启动率 × 试用转化率 × Σ（各期续订留存 × 净单价）

| 叶子 | 主要杠杆 |
|:---:|:---|
| 付费墙触达率 | 位置、时机、功能墙和 onboarding 路径 |
| 试用启动率 | 价值呈现、试用门槛、是否需要支付方式 |
| 试用转化率 | 试用时长、价值送达、到期提醒和信任 |
| 续订留存 | 持续价值、再触达和被动流失挽回 |
| 净单价 | 价格、周期、地区、商店费用、退款和税费 |

转化漏斗：

安装 → 引导完成 → 付费墙曝光 → 套餐或 CTA → 发起购买 → 试用或直接购买 → 激活权益 → 首期付费 → 续订或流失

| 掉点 | 优先检查 |
|:---:|:---|
| 引导完成率低 | 引导长度、价值表达和首个任务 |
| 付费墙曝光率低 | 是否埋得太深、是否错过价值时刻 |
| CTA 点击低 | 收益表达、价格、套餐数量和信任 |
| 购买完成低 | 商品加载、支付流程和用户犹豫 |
| 试用转化低 | 价值是否送达、提醒、试用长度和价格 |
| 续订低 | 持续价值、队列构成和被动流失 |

按渠道、地区、价格、版本和付费墙版本拆队列，不能只看混合均值。

## 留存、流失与挽回

首次续订通常是重要观察节点，但具体留存基准取决于品类、周期、地区和用户质量，不能套用固定数字。

主动流失主要回到价值、价格、周期和取消挽留；被动流失主要检查支付失败、重试、宽限期、账户保留、服务端状态通知和支付方式提醒。

平台提供的宽限和重试机制应与应用内权益状态一致；Google 的生命周期状态参照 **[IAP-GPLAY-03-订阅生命周期]**，Apple 的服务端通知参照 **[IAP-APPLE-02-启用 App Store 服务端通知]**。恢复、暂停、失败、退款等状态必须进入服务端和数据漏斗，避免把被动流失误判为产品价值问题。

## 常见问题

| 现象 | 诊断路径 |
|:---:|:---|
| 付费转化下降 | 按队列检查渠道/地区、付费墙改动、漏斗掉点和商品加载 |
| 试用启动高但转化低 | 检查试用期价值、提醒、时长、价格和用户质量 |
| 续订下降 | 先区分主动与被动，再看持续价值、首期续订和周期 |
| 退款上升 | 检查误导或误触、价值不符、地区和支付方式 |
| 收入变化 | 沿新增、付费墙触达、试用、续订、净单价逐叶排查 |

前端问题优先看获量和用户质量，后端问题优先看产品、付费墙、定价、留存和平台状态；始终按版本和队列拆分。
