## 数据口径

| 来源 | 适合回答 | 限制 |
|:---:|:---|:---|
| 客户端事件 | 用户是否到达场景、链路停在哪一步 | 依赖埋点和版本覆盖 |
| 聚合 SDK/平台估算 | 请求、展示和分组的实时表现 | 可能有延迟或口径差异 |
| 广告源回传 | 广告源侧展示、价格和收益 | 不一定包含完整产品链路 |
| 结算数据 | 最终确认收入 | 时效较慢，可能含调整项 |
| 归因数据 | 渠道、地区和用户获取表现 | 受窗口和匹配规则影响 |

比较前记录时间、时区、币种、版本、去重、展示定义和回传延迟；TopOn 对 SDK 统计、网络回传、时区和延迟的区分参照 **[IAA-TOPON-09-数据来源]** **[IAA-TOPON-19-聚合管理（Waterfall）报表数据说明]**。不同口径不能直接相加，也不能用一张报表覆盖另一张。

## 三条漏斗和收益树

核心任务漏斗：

进入应用 → 到达功能 → 开始任务 → 完成任务 → 结果或返回节点

IAA 广告漏斗：

场景到达 → 条件满足 → 请求 → 响应/填充 → 可展示 → 实际展示 → 点击或关闭

IAP 付费漏斗：

付费入口曝光 → 付费墙 → 套餐选择 → 购买 → 权益生效 → 续订或流失

基础收益公式：

广告收益 = 展示量 × eCPM / 1000

展示量可拆为：

活跃用户 × 单用户场景到达次数 × 触发满足率 × 请求成功率 × 响应/填充率 × 可展示率 × 实际展示率

IPU 连接用户规模与展示量，eCPM 观察价格和流量结构，ARPDAU 同时反映展示和价格，总收益验证是否产生真实增量。缺少某个阶段字段时，明确记录证据缺口。

## 诊断顺序

1. 固定时间、版本、地区、用户阶段、广告位和数据口径。
2. 判断活跃用户、核心任务到达和广告场景触发是否变化。
3. 检查请求、响应、填充、可展示和实际展示。
4. 链路正常后再分析 eCPM、广告源结构和价格层级。
5. 用总收益、核心任务完成、留存和崩溃等护栏验证结论。

## 常见问题

| 现象 | 首要检查 |
|:---:|:---|
| 收益下降 | 先拆展示量下降与 eCPM 下降，分别沿任务漏斗和广告漏斗定位 |
| 请求下降或消失 | 场景到达、触发条件、频率、版本、参数映射和 SDK 初始化 |
| 填充下降 | 广告源状态、地区覆盖、价格层级、竞价返回、Waterfall 尾部和兜底 |
| 响应正常但展示下降 | 预加载、缓存、可展示状态、页面生命周期、超时、并发和重复请求 |
| eCPM 下降 | 固定地区、用户阶段、广告位和形式后比较广告源及价格层级 |
| 报表不一致 | 时区、币种、日期边界、去重、展示定义、延迟和结算调整 |

提高底价可能同时降低填充，eCPM 上升也不等于总收益上升；底价、填充和收益的联动可参照 **[IAA-TOPON-02-价格和底价]** **[IAA-TOPON-11-收益变动分解]**。任何判断都要回到同口径的总量和体验结果。

## 证据和对比

有效对比至少说明：

- 时间范围、应用版本和配置版本。
- 地区、用户阶段、流量组、广告位和广告源。
- 数据来源、时区、币种和指标定义。
- 样本量以及同期的发布、投放、渠道或产品变化。

输出分成四类：已观察事实、支持性解释、待验证假设、建议动作。数据不足时补事件、日志或测试流量，不补造结论。

## 实验和配置调整

### 调整前

1. 保存配置快照，写明目标指标和异常节点。
2. 选择一个主要变量，固定受影响范围和流量比例。
3. 定义收益、展示、任务完成、留存或崩溃护栏。
4. 写明观察窗口、生效检查和回退条件。

### 调整中

保持版本、流量和口径可识别。出现无请求、无展示、参数错误、广告源不可用或数据缺失时，立即按异常处理。A/B 分配和口径问题可参照 **[IAA-TOPON-13-A/B 测试]**。

### 调整后

1. 确认配置真实生效。
2. 先看漏斗节点，再看 eCPM 和收益。
3. 检查目标分组的增量是否转移了其他分组的收益。
4. 检查体验护栏，达到条件即恢复快照并记录原因。

| 回退 | 条件、快照和执行结果 |
