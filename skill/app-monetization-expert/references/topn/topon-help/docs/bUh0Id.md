# 聚合管理（Waterfall）报表数据说明

## **1. 查看聚合管理（Waterfall）报表数据**

调整Waterfall需要结合每层广告源的实际数据表现来进行，TopOn聚合管理页面直接提供**TopOn SDK统计的数据**和**广告平台的报表API数据**两份数据，无需切换到综合报表页面查看再切回进行调整，最大限度地为您提供便利，节省时间。



### 1.1 报告时区

数据报表支持修改报告时区。目前支持UTC+8中国标准时间、UTC+0格林威治标准时间、UTC-8太平洋标准时间，**默认为UTC+8时间**。

TopOn SDK统计数据及如下广告平台数据已按所选时区汇总（Facebook、Mintegral、Applovin、UnityAds、Tapjoy），其余广告平台数据则以API返回的时区为准。



**报告时区修改路径：** TopOn开发者后台-【账号管理】-【账号信息】-【基础信息】



### 1.2 数据更新时间

不同的数据指标更新时间会有差异，具体如下：

(1) eCPM：eCPM是按展示占比对api收益进行拆分计算，每天11点、17点30分会更新昨天数据；

(2) 除了eCPM以外的其他TopOn SDK统计数据：每5分钟更新；

(3) 广告平台的报表API数据（我们会在多个时间段拉取前一天的广告平台数据） ，详细请查看综合报表各个广告平台更新说明

(4) 填充耗时分位数数据次日更新

① UTC+8中国标准时间：每天6点更新

② UTC+0格林威治标准时间：每天11点更新

③ UTC-8太平洋标准时间：每天20点更新

### 1.3 报表指标

自定义指标支持勾选需要的数据维度内容显示至聚合管理报表。

聚合管理报表各指标说明：

| 报表指标 | 说明 |
| --- | --- |
| 优先级 | TopOn向各广告源发起请求的顺序。按阿拉伯数字从小到大，优先级从高到低依次请求。 **注意**：当数字一样时，优先级一样，每次请求时针对数字一样的广告源会随机优先级进行请求。 竞价广告源显示S2S和C2S图标 |
| 广告源 | 每个广告平台的广告位ID参数对应唯一的TopOn广告源，广告源可用于聚合管理中的瀑布流广告分层。[>>更多](/cn/docs/cXus5n) |
| 状态 | 开启或关闭广告源。蓝色为开启状态，灰色为关闭状态。 |
| 操作 | 对该广告源进行编辑或删除操作。 |
| 价格 | 即排序价格。该价格仅用于广告请求时的优先级排序：比如添加了ABCDE 5层广告源，需要对这5层广告源进行排序，这个排序会按照填写的价格从高到低排序，并不影响广告填充。 **注意**：①若多个广告源的排序价格一样，则优先级一样，每次请求时随机优先级请求； ②建议该价格与该广告源真实eCPM（即eCPM API）数值尽可能一致，可用于预估当天实时的收益和LTV。 |
| eCPM | eCPM（effective cost per mile）指的是每一千次展示可以获得的广告收入；若有多个流量分组，则为该流量分组拆分收益和展示后折算的eCPM。 计算公式：（收益/展示）×1000。 **注意**：假设该广告位有3个流量分组A B C，则流量分组A的收益=流量分组A的TopOn统计展示/TopOn统计总展示×收益；流量分组A的eCPM=流量分组A的收益/流量分组A的TopOn统计展示×1000。 |
| 预估收益 | 根据TopOn SDK统计的展示数和eCPM价格进行预估的收益。 计算公式：①常规广告源：人工填写的eCPM价格\*TopOn统计的展示/1000；②头部竞价广告源：实时的广告展示价格。[>>头部竞价说明](/cn/docs/dfnwQG) |
| 请求 | **汇总行**表示流量请求，即应用（客户端）向TopOn SDK发起的请求（Load)次数； **其余行**表示广告源请求，即TopOn按照聚合管理的瀑布流广告源排序向各广告源发起的请求次数。 **注意**：一次流量请求可能会对应多次广告源请求。当应用（客户端）向TopOn发起请求时，TopOn按照瀑布流广告源排序依次向各广告源发起请求，当高优先级的广告源没有填充、或者短超时（8s）内还没有广告返回，则会往下请求低优先级的广告源，此时一次流量请求会对应多次广告源请求。 |
| 填充率 | **汇总行**表示流量填充率，即应用（客户端）向TopOn SDK发起请求（Load）后，广告返回成功的占比； **其余行**表示广告填充率，即TopOn向各广告源发起请求后，广告返回成功的占比。 计算公式：流量填充率=流量请求返回成功数（流量填充数）/流量请求×100%；广告源填充率=广告源请求返回成功数（广告填充数）/广告源请求×100%。 |
| 填充耗时（秒） | 从发起请求到广告返回成功的平均耗时。 **注意**：①因UnityAds存在自填充行为，无法准确统计填充耗时，暂不显示UnityAds广告源的填充耗时数据。②从2020年12月16日开始有统计数据。 |
| 展示 | 从2023年3月7日 0点（UTC+8）起，统计口径从“TopOn调用广告平台SDK开始展示的次数”调整为“TopOn收到广告平台SDK展示成功的回调次数”。由于统计口径不一样，TopOn统计的展示与广告平台统计的展示（展示API）可能存在一定差异。 |
| 点击 | TopOn统计的广告点击数。部分平台不提供点击回调（如Admob的激励视频），导致TopOn无法统计到用户的点击行为。 |
| 点击率 | TopOn统计的广告点击数占TopOn统计的广告曝光次数的比例。计算公式：点击/展示\*100%。 |
| 展示率 | TopOn统计的广告曝光次数占流量请求返回成功数（流量填充数）的比例。计算公式：展示/流量填充数\*100%。 |
| 展示Gap | TopOn统计的广告曝光次数与广告平台统计的广告曝光次数的差异。计算公式：（展示-展示API）/展示API。 **注意**：由于统计口径不一样，TopOn统计的展示与广告平台统计的展示（展示API）可能存在一定差异，当展示Gap超过15%时，可以联系TopOn的AM一起排查一下原因。 |
| eCPM API | TopOn通过报表API向广告平台拉取到的eCPM（effective cost per mile）。 计算公式：（收益/展示API）×1000。 **注意**：若有多个分组（流量分组或AB测试），每个分组中的eCPM API均为从广告平台拉取的该广告ID总的eCPM，没有根据分组进行拆分。如果想查看该分组的真实eCPM，请查看**eCPM**指标，为拆分后的eCPM预估数据；或每个分组使用独立的一套广告源ID进行精确区分。 |
| 收益API | TopOn通过报表API向广告平台拉取到的实际收益。 **注意**：若有多个分组（流量分组或AB测试），每个分组中的收益均为从广告平台拉取的该广告ID总的收益，没有根据分组进行拆分。如果想查看该分组的真实收益，请查看**预估收益**指标，为拆分后的收益预估数据；或每个分组使用独立的一套广告源ID进行精确区分。 |
| 请求API | TopOn通过报表API向广告平台拉取到的广告请求数。 **注意**：部分广告平台不提供此数据。若有多个分组（流量分组或AB测试），每个分组中的请求均为从广告平台拉取的该广告ID总的请求，没有根据分组进行拆分。如果想查看该分组的真实请求，请查看**请求**指标，为TopOn统计的请求数据；或每个分组使用独立的一套广告源ID进行精确区分。 |
| 填充率API | TopOn通过报表API向广告平台拉取到的广告填充率。 **注意**：部分广告平台不提供此数据。若有多个分组（流量分组或AB测试），每个分组中的请求均为从广告平台拉取的该广告ID总的填充率，没有根据分组进行拆分。如果想查看该分组的真实填充率，请查看**填充率**指标，为TopOn统计的填充率数据；或每个分组使用独立的一套广告源ID进行精确区分。 |
| 展示API | TopOn通过报表API向广告平台拉取到的广告曝光次数。由于统计口径不一样，TopOn统计的展示与广告平台统计的展示（展示API）可能存在一定差异。 **注意**：若有多个分组（流量分组或AB测试），每个分组中的请求均为从广告平台拉取的该广告ID总的展示，没有根据分组进行拆分。如果想查看该分组的真实展示，请查看**展示**指标，为TopOn统计的展示数据；或每个分组使用独立的一套广告源ID进行精确区分。 |
| 点击API | TopOn通过报表API向广告平台拉取到的广告点击数。 **注意**：若有多个分组（流量分组或AB测试），每个分组中的请求均为从广告平台拉取的该广告ID总的点击，没有根据分组进行拆分。如果想查看该分组的真实点击，请查看**点击**指标，为TopOn统计的点击数据；或每个分组使用独立的一套广告源ID进行精确区分。 |
| 点击率API | TopOn通过报表API向广告平台拉取到的广告点击率。计算公式：点击API/展示API×100%。 **注意**：若有多个分组（流量分组或AB测试），每个分组中的请求均为从广告平台拉取的该广告ID总的点击率，没有根据分组进行拆分。如果想查看该分组的真实点击率，请查看**点击率**指标，为TopOn统计的点击率数据；或每个分组使用独立的一套广告源ID进行精确区分。 |

### 1.4 常见问题

**(1) 填充耗时有什么作用？**

填充耗时，是指从发起广告请求到广告返回成功的平均耗时。 可以用来查看每一个广告分层的加载耗时，结合广告分层的填充率和ecpm及时优化瀑布流。

**注意：**

① 填充耗时长不一定就表明广告效果差，需要结合其他数据一起评估。

② 一般视频类广告加载时长10秒以内都不算很慢。
