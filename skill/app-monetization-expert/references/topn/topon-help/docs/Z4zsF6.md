# 数据GAP排查

## 1. 排查须知

**(1) TopOn的数据指标来源分两种：三方API 和 TopOn统计**

| 数据类型 | 数据来源 |
| --- | --- |
| 三方A PI | 数据指标来源于三方广告平台API。 前提：需要在TopOn后台【广告平台】模块中开启对应广告平台的报表API授权才能看到数据。 TopOn后台收益以及带有API后缀的数据指标均属于三方API数据。  **注意！：**  **1、需要开通报表API授权，TopOn才能拉到API数据。三方广告平台以此与开发者结算。所有带API的数据都是平台的结算数据。**  **2、不论是否开通API授权，所有结算数据都以三方平台后台为准。TopOn后台统计数据仅供参考。** |
| TopOn统计 | 数据指标来源于TopOn埋点。 前提：对接好TopOn的SDK才能看到数据。 TopOn后台除收益外所有没有API后缀的数据指标均属于TopOn统计数据。  **注意！：不带API的指标都是TopOn统计的。仅供参考。和平台实际结算金额无关。** |

**(2) TopOn报表各项数据更新时间**

不同的数据指标更新时间会有差异，具体如下：

**● 首页**、**综合报表**、**分小时报表**、**聚合管理**、**流量管理**、**广告平台**：

① DAU、新增用户、留存率：每2-3小时更新。

② 除了DAU、新增用户、留存率以外的其他TopOn SDK统计数据：每5分钟更新。

③ 广告平台的报表API数据（我们会在5个时间段拉取前一天的广告平台数据）：3:30，10:50，14:30，16:30，21:00。

**● 用户价值报表：**

① LTV：昨天的数据在今天13:00左右更新。

② 预估LTV：当天的数据在当天早上9:00左右更新，后续每4小时左右更新。

③ 留存：昨天的数据在今天上午8：00左右更新。

## 2. API数据与三方平台后台数据GAP排查

| 排查项 | 排查步骤 |
| --- | --- |
| 数据延迟 | TopOn会在以下 5 个时间段拉取前一天的广告平台数据： 3:30，10:50，14:30，16:30，21:00 |
| 时区 | 确认广告平台的时区和TopOn的时区是否一致。TopOn时区默认东八区。 •如排查以上因素后问题仍无法解决，请联系TopOn对接人协助解决。 |

## 3. TopOn数据与API数据GAP排查

### 3.1 数据指标的含义

更多数据指标释义[>>查看](/cn/docs/5e6DnV#3._%E5%9F%BA%E7%A1%80%E6%95%B0%E6%8D%AE%E6%8C%87%E6%A0%87%E8%A7%A3%E9%87%8A)

| 名称 | 释义 |
| --- | --- |
| eCPM | TopOn通过报表API向广告平台拉取到的实际收益和TopOn统计的展示计算出eCPM。 |
| eCPM API | TopOn通过报表API向广告平台拉取到的实际收益和展示API计算出。 |
| 预估eCPM | 根据预估收益和TopOn统计的展示计算出预估eCPM。 注： ①预估 eCPM当天提供； ②常规广告源基于手动填写的eCPM价格计算，竞价广告源基于实时竞价价格计算； ③Meta竞价广告源基于历史eCPM API预估。 |
| 展示 | TopOn收到广告平台SDK展示成功的回调次数。 |
| 展示 API | TopOn通过报表API向广告平台拉取到的广告曝光次数。 Tips：由于统计口径不一样，TopOn统计的展示与广告平台统计的展示（展示API）可能存在一定差异。 |
| 收益 | Topon通过API向广告平台拉取到的收益。 |
| 预估收益 | ①竞价广告源：以实时的广告展示价格汇总得出预估收益； ②非竞价广告源：人工填写的eCPM价格 \* TopOn统计的展示汇总出预估收益； ③Meta预估收益以Meta 历史的eCPM API\* TopOn统计的展示得出。 |

### 3.2 收益与预估收益差距排查

Tips：一般来说，若收益和预估收益GAP在15%以内，我们认为是可以接受的，这是因为eCPM和展示都可能有GAP。

| **名称** | **说明** |
| --- | --- |
| 收益 | Topon通过API向广告平台拉取到的收益 |
| 预估收益 | ①竞价广告源：以实时的广告展示价格汇总得出预估收益； ②非竞价广告源：人工填写的eCPM价格 \* TopOn统计的展示汇总出预估收益； ③Meta预估收益以Meta 历史的eCPM API\* TopOn统计的展示得出。 |

#### ● 收益和预估收益相等或者接近的前提

(1) 收益计算公式：收益=展示次数\*eCPM/1000

(2) 如果需要TopOn统计的预估收益，和三方平台的实际收益接近，就需要展示次数和eCPM次数都接近。

(3) 如果是展示有差距，展示相关问题请查阅步骤2.3.2。

(4) 如果是eCPM有差距，请查阅步骤2.3.3。

如果展示和eCPM差距都解决了，基本都不会再有差距。

#### ● 排查步骤

(1) 确认对比的数据，时区在三方后台和TopOn后台是一致的，如果时区不一致，肯定会有GAP。

(2) 先确认差距大的广告平台，是哪个广告平台，哪个时间范围。
建议先排查昨日各广告平台数据数据，确定了差距大的广告平台以后，再排查到更细维度的差距：应用、广告位以及广告源维度的收益差距。

**查看路径：**TopOn后台→【数据报表】-【综合报表】

#### ● 示例

**如何借助综合报表排查收益GAP？**

(1) 问题：Admob在日期为3月30日产生了预估收益和实际收益的差距

(2) 判断应用维度的差距GAP：TopOn后台→【数据报表】-【综合报表】，按以下步骤进行设置（参考下图1），判断实际差距大的应用。

① 维度选择：日期、广告平台。

② 筛选：日期为昨天（或者其他差距大的日期）。

③ 指标（点击笔进行编辑）：选择预估收益、收益API。

- **单个应用差距很大**继续深入排查广告位维度和广告源维度（同理，维度部分，增加筛选广告位、广告源即可）。
- **两个或多个应用差距很大：**区分应用，分别排查广告位维度和广告源维度。
- **全部应用差距很大并且展示API为空白：**基本可以判定为是收益暂时没有拉回来，即可能没有到数据更新时间，可以等当天稍晚再查看收益。

如果是历史收益数据没有拉回来，建议先确认已经绑定了报表API，然后联系TopOn运营，提供缺失数据的广告平台和时间范围，重新拉取历史数据。（报表API添加路径：TopOn后台→【广告平台】-【变现平台】→编辑广告平台→已开通报表API，参考下图2）





### 3.3 展示和展示API差距排查

| **名称** | **说明** |
| --- | --- |
| 展示 | TopOn收到广告平台SDK展示成功的回调次数。 |
| 展示API | TopOn通过报表API向广告平台拉取到的广告曝光次数。由于统计口径不一样，TopOn统计的展示与广告平台统计的展示（展示API）可能存在一定差异。 |
| 展示Gap | TopOn统计的收到广告平台SDK展示成功的回调次数，与广告平台统计的广告曝光次数的差异。 【计算公式：（展示-展示API）/展示API。 】 |

当展示Gap超过15%时，可以按以下步骤具体排查原因。如果还是无法定位到原因，可以联系TopOn的运营团队一起排查。

#### ● 若展示API＞展示

确认该三方广告平台的广告ID是否是旧的，是否有个别流量没有通过TopOn在请求广告；例如，是否有老版本没有使用TopOn SDK。

#### ● 若展示API＜展示

(1) 首先确认是什么广告类型、什么广告平台。

(2) 区分每个广告源的数据，排查具体是哪个广告源差异比较明显。

例如：

① A平台的广告源B，在2023年3月7日的展示API为700，展示为1000。这里的展示GAP较大。

这里的展示API为TopOn从平台拉取的实际展示数据，展示为TopOnSDK统计到的平台发回的展示回调，也就是说有300的展示损失，这300展示虽然已经回调给了TopOn，但是平台在结算数据中扣除了。建议开发者联系A广告平台进一步确认。

② A平台的广告源C，在2023年3月7日的展示API为930，展示为1000。这里的展示GAP较小，为由于统计口径和网络原因导致的差异，可接受。

#### ● 比较常见的广告有效展示优化方式

① 不要遮挡、扭曲和模糊广告图片和内容。

② 原生和banner广告的展示时长超过1秒，展示面积超过50%。

③ 开屏广告展示面积要超过屏幕的75%，以及播满5秒或者点击了跳过按钮。比如有些开发者在设计开屏的时候在页面底部需要加入自己应用的logo，这个面积不能太大，要保证广告展示面积超过手机屏幕的75%。

**注意：**

① 不同平台这个时长和面积要求会有差异，但一般都会有这两个指标的要求。这里的展示时长，指的是广告内容展示出来后，用户停留在广告页面的时间要超过1秒，例如某些信息流广告，用户在刷信息流的时候很快把这个广告刷走了，这种情况可能就不会算作一次有效展示了。

② 展示面积，这里要注意有时候即使用户已经完整看到了这个广告，也不代表展示面积大于50%了，因为可能在集成的时候有一层透明的蒙版覆盖在广告上面，尽管肉眼看不到，但广告平台也会认为展示面积不符合要求。

### 3.4 eCPM与eCPM API差距排查

| **名称** | **说明** |
| --- | --- |
| eCPM | TopOn通过报表API向广告平台拉取到的实际收益和TopOn统计的展示计算出eCPM。 |
| eCPM API | TopOn通过报表API向广告平台拉取到的实际收益和展示API计算出。 |

如果eCPM和eCPM API有差异，主要是TopOn统计的展示和展示API的差异，按照2.2的排查步骤即可

### 3.5 预估eCPM与eCPM API

| **名称** | **说明** |
| --- | --- |
| eCPM API | TopOn通过报表API向广告平台拉取到的实际收益和展示API计算出。 |
| 预估eCPM | 根据预估收益和TopOn统计的展示计算出预估eCPM（可理解为常规广告源手动填写的eCPM与竞价广告源基于实时竞价价格计算之平均） 注：①预估 eCPM当天提供；②常规广告源基于手动填写的eCPM价格计算，竞价广告源基于实时竞价价格计算；③Meta竞价广告源基于历史eCPM API预估 |

#### ● 预估eCPM和eCPM API一致的前提

排序价格和eCPM API价格需要修改为一致，且展示和展示API数据接近

修改路径：聚合管理-选择应用下的所有广告位

① 有底价的广告源：排序价格是否和eCPM API价格一致，将TopOn后台的排序价格调整为对应eCPM API价格。可以选择笔的符号进行手动修改。



② 无底价的广告源：

- 有报表API权限，建议配置上报表API，并打开自动价格，方便自动调整排序价格为与eCPM API一致。
- 无报表API权限，建议上传三方平台数据，待服务端处理完成后，比较eCPM API和排序价格，手动填写为和实际价格一致。[>>如何上传三方平台数据](/cn/docs/yU7A3C#2._%E6%93%8D%E4%BD%9C%E6%8C%87%E5%BC%95)

#### ● 排查步骤

(1) 利用综合报表，确认差距大的广告平台 → 有问题的广告位 → 出现问题的广告源，确定有问题的日期范围。建议先排查昨日各广告平台数据。

查看路径：TopOn后台-数据报表-综合报表，或TopOn后台-聚合管理，均可。

① 维度选择：日期、应用、广告平台、广告位、广告源。

② 筛选：日期为昨天（或者其他差距大的日期）、需要排查的应用或者广告位、广告平台（需要排查的广告平台）。

Tips：维度和筛选的部分，开发者可根据排查需求自定义选择。

③ 指标（选择笔的部分）：需要勾选到eCPM、eCPM API，其他根据自身需求即可。

④ 观察并比较差距大的广告平台和广告源，确定差距大的广告平台/广告源/广告位。



(2) 对比数据GAP，对应解决

如果是因为排序价格填写不正确-->修改排序价格和平台实际eCPM API一致。

修改路径：开发者后台→【聚合管理】

原因：TopOn后台预估收益的计算公式如下，预估收益的准确性受到排序eCPM准确性的影响。

如果修改一致【至少一周】后，仍然出现eCPM不一致、GAP较大（一般eCPM GAP在5%内为可以接受）的情况，请联系三方平台或者TopOn运营团队协助解决。
