# 综合报表

## 1. 功能概述

数据报表提供了丰富的广告变现侧的数据维度，以全面了解您的广告业务变现效果。数据报表包含综合报表、留存价值报表、用户行为报表、分小时报表、交叉推广报表、ROI报表等多维度的可视化内容。

> **注意事项**
> 为防止爬虫抓取数据造成TopOn服务器故障，请开发者不要使用爬虫抓取TopOn的数据报表。如有上述行为请立即停止，否则TopOn将暂停为您服务！请各位合作伙伴遵守。

## 2. 操作指引

**(1) 数据维度：**日期、应用、广告位、流量分组、渠道、地区、广告平台、广告源、广告场景、广告样式、SDK版本、应用版本。

**(2) 数据指标：**DAU、人均收益、新用户、新用户占比、次日留存、DEU、渗透率、展示/DAU、展示/DEU、竞价、竞价响应率、预估收益、预估、eCPM、流量请求、流量填充率 、展示、展示率、eCPM、点击、点击率、广告源请求、广告源填充率、展示Gap、点击Gap、收益、展示API、eCPM API、点击API、点击率API、请求API、填充率API、交叉推广统计数据。



## 3. 报告时区

数据报表支持修改报告时区。目前支持UTC+8中国标准时间、UTC+0格林威治标准时间、UTC-8太平洋标准时间，**默认为UTC+8时间**。 TopOn SDK统计数据及如下广告平台数据已按所选时区汇总（Mintegral、Applovin、UnityAds、Tapjoy、Bigo），其余广告平台数据则以API返回的时区为准。

**报告时区修改路径：** TopOn开发者后台→【账号管理】-【账号信息】-【基础信息】→报表时区。

## 4. 数据更新时间

不同的数据指标更新时间会有差异，具体如下：

(1) DAU、新增用户、留存率：每2小时更新；

(2) 除了DAU、新增用户、留存率以外的其他TopOn SDK统计数据：每5分钟更新；

(3) 广告平台的报表API数据（我们会在5个时间段拉取前一天的广告平台数据）：3:30,10:50,14:30,16:30,21:00。

### 5.2 数据指标

自定义指标支持勾选需要的数据维度内容显示至综合报表。



| 数据指标 | 说明 |
| --- | --- |
| 日期 | 数据产生的时间段。 |
| DAU | 每天打开应用的独立用户数。2025年9月1日起，DAU支持更多维度数据显示，不同筛选项和维度的DAU代表对应筛选项和维度的活跃用户数。汇总行仅为当前筛选项DAU的求和数，不去重。**注意**：根据GDPR协议，欧盟地区需要用户同意后才会统计数据。[>>什么是GDPR？](https://help.toponad.net/cn/docs/MWsWVm#%E2%97%8F%C2%A0GDPR) |
| 人均收益 (ARPDAU) | 每用户平均收入（Average Revenue Per User，简称ARPU）。 计算公式：收益/DAU |
| 新用户 | 近60天内首次初始化Topon SDK的设备用户数。 |
| 新用户占比 | 近60天内首次初始化Topon SDK的设备用户数占日活跃用户的比例。计算公式：新用户/DAU |
| DEU | 每天展示过广告的独立用户数。2025年9月1日起，DEU支持所有维度和筛选项显示，不同筛选项和维度的DEU代表对应筛选项和维度展示过广告的独立用户数。 |
| 渗透率 | 每天展示（曝光）过广告的设备用户数占日活跃用户的比例。计算公式：DEU/DAU\*100% |
| 展示/DAU | 日活跃用户人均展示次数。 |
| 展示/DEU | 展示（曝光）过广告的设备用户的人均展示次数。 |
| 竞价 | 头部竞价（Header Bidding）广告源发起的竞价次数。[>>头部竞价说明](https://help.toponad.net/cn/docs/dfnwQG) |
| 竞价响应率 | 头部竞价（Header Bidding）广告源竞价响应率。计算公式：竞价响应次数/竞价次数\*100%。 [>>头部竞价说明](https://help.toponad.net/cn/docs/dfnwQG) |
| 竞价响应eCPM | 头部竞价广告源在竞价响应时广告平台返回的平均eCPM。[>>头部竞价说明](https://help.toponad.net/cn/docs/dfnwQG) |
| 预估收益 | 根据Topon SDK统计的展示数和eCPM价格进行预估的收益。计算公式：①常规广告源：人工填写的eCPM价格\*Topon统计的展示/1000；②头部竞价广告源：实时的广告展示价格。[>>头部竞价说明](https://help.toponad.net/cn/docs/dfnwQG) |
| 预估人均收益  (预估ARPDAU) | 计算公式：预估收益/DAU |
| 预估eCPM | 根据预估收益和Topon统计的展示计算出预估eCPM，计算公式：（预估收益/Topon统计的展示）\*1000。注：1、预估 eCPM当天提供；2、常规广告源基于手动填写的eCPM价格计算，竞价广告源基于实时竞价价格计算 |
| 流量请求 | 应用（客户端）向Topon SDK发起的请求（Load)次数。 |
| 流量填充率 | 应用（客户端）向Topon SDK发起请求（Load）后，广告返回成功的占比。计算公式：流量请求返回成功数（流量填充数）/流量请求\*100%。 |
| 展示 | 从2023年3月7日 0点（UTC+8）起，统计口径从“Topon调用广告平台SDK开始展示的次数”调整为“Topon收到广告平台SDK展示成功的回调次数”。由于统计口径不一样，Topon统计的展示与广告平台统计的展示（展示API）可能存在一定差异。 |
| 展示(旧) | 展示数据从2023年3月7日 0点（UTC+8）起修改为新的统计方法，展示（旧）数据为旧的展示统计方法数据，显示Topon统计的广告曝光次数，与展示数据可能存在一定差异。 |
| 展示率 | Topon统计的广告曝光次数占流量请求返回成功数（流量填充数）的比例。计算公式：展示/流量填充数\*100%。 |
| eCPM | Topon通过报表API向广告平台拉取到的实际收益和Topon统计的展示计算出eCPM，计算公式：（收益/Topon统计的展示）\*1000。注：eCPM延迟1天提供。 |
| eCPR | 千次广告请求收益，计算公式：预估收益/请求 \*1000。对于竞价广告源，请求为竞价指标；对于常规广告源，请求为广告源请求指标。 |
| eCPC | 从广告平台拉取到的实际API收益/聚合平台（Topon）统计点击次数\*1000 |
| 点击 | Topon统计的广告点击数。部分平台不提供点击回调（如Admob的激励视频），导致Topon无法统计到用户的点击行为。 |
| 点击率 | Topon统计的广告点击数占Topon统计的广告曝光次数的比例。计算公式：点击/展示\*100%。 |
| 广告源请求 | Topon按照聚合管理的瀑布流广告源排序向各广告平台（广告源）发起的请求次数。 **注意**：一次流量请求可能会对应多次广告源请求。当应用（客户端）向Topon发起请求时，Topon按照瀑布流广告源排序依次向各广告源发起请求，当高优先级的广告源没有填充、或者短超时（8s）内还没有广告返回，则会往下请求低优先级的广告源，此时一次流量请求会对应多次广告源请求。 |
| 广告源填充率 | Topon向各广告平台（广告源）发起请求后，广告返回成功的占比。计算公式：广告源请求返回成功数（广告源填充数）/广告源请求\*100%。 |
| eCPM GAP | TopOn统计的预估eCPM与广告平台统计eCPM的差异，计算公式：（预估eCPM-eCPM API）/ eCPM API |
| 收益GAP | TopOn统计的预估收益与广告平台统计收益的差异，计算公式：（预估收益-收益API）/收益API |
| 展示Gap | Topon统计的广告曝光次数与广告平台统计的广告曝光次数的差异。计算公式：（展示-展示API）/展示API。 **注意**：由于统计口径不一样，Topon统计的展示与广告平台统计的展示（展示API）可能存在一定差异，当展示Gap超过15%时，可以联系Topon的AM一起排查一下原因。 |
| 点击Gap | Topon统计的广告点击数与广告平台统计的广告点击数的差异。计算公式：（点击-点击API）/点击API。 |
| 查询isReady | 调用Topon isReady接口的次数。 **注意**：isAdReady接口，判断当前是否存在可展示的广告。（安卓的原生和横幅广告不支持isReady判断；双端Topon 5.7.6版本开始支持开屏的isReady判断） |
| isReady成功率 | Topon isReady接口返回为true的次数占调用Topon isReady接口的次数的比例。计算公式：Topon isReady接口返回为true的次数/调用Topon isReady接口的次数\*100%。 |
| 到达广告场景 | 用户到达广告场景的次数，App需要调用entryAdScenario方法才可统计。 |
| 广告Ready率 | 用户到达广告场景时，广告已经ready的占比 |
| API数据 | 以下指标为API数据，即：Topon通过报表API向广告平台拉取到的数据 |
| 收益API | Topon通过API向广告平台拉取到的收益 |
| 展示API | Topon通过报表API向广告平台拉取到的广告曝光次数。由于统计口径不一样，Topon统计的展示与广告平台统计的展示（展示API）可能存在一定差异。 |
| eCPM API | Topon通过报表API向广告平台拉取到的实际收益和展示API计算出eCPM API，计算公式：（收益/展示API）\*1000。注：eCPM API延迟1天提供。 |
| eCPR API | 计算公式：收益API/请求API \*1000。部分广告平台不支持请求API数据，请区分广告平台查看此指标。 |
| eCPC API | 媒体收益/媒体侧点击次数\*1000 |
| 点击API | Topon通过报表API向广告平台拉取到的广告点击数。 |
| 点击率API | Topon通过报表API向广告平台拉取到的广告点击率。计算公式：点击API/展示API\*100%。 |
| 请求API | Topon通过报表API向广告平台拉取到的广告源请求数。 **注意**：部分广告平台不提供此数据。 |
| 填充率API | Topon通过报表API向广告平台拉取到的广告填充率。 **注意**：部分广告平台不提供此数据。 |
| 交叉推广统计数据 | 交叉推广的预估收益和广告统计数据。[>>什么是交叉推广？](https://help.toponad.net/cn/docs/Popzgt) |

## 6. 离线报表中心

**导出报表**最多支持导出5千行数据。如需要导出5千行以上数据请使用**导出离线报表**(离线报表最多支持导出5万行数据)：



(1) 根据您的需求搜索数据。

**(2) 点击【导出报表】，提交生成离线报表的任务（建议不同的查询结果设置不同的报表名称）。**

**(3) 跳转到【数据报表】-【 离线报表中心】查看离线报表的生成结果（离线报表生成时间一般在5~15分钟）。**

## 7. 常见问题

**(1) 流量请求和广告请求的区别？**

应用向TopOn发起请求（流量请求）后，TopOn按瀑布流排序依次向各个广告平台发起请求（广告请求）。

**(2) TopOn 如何判断用户来自哪个国家？**

用户从客户端发起广告请求的时候，TopOn 会根据用户的IP信息来判断。
