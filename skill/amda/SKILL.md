# AppMagic市场分析

将固定的AppMagic周度数据表更新为固定的“AppMagic市场分析”飞书文档。分析全球市场和国家群组，不写周报；除US外，不以单一国家作为主线。

## 固定资源

- 每次调用首先读取并校验本地私有资源配置：默认路径由`scripts/verify-local-resource-config.ps1`解析到本机应用数据私有目录；如设置了`AM_MARKET_ANALYTICS_CONFIG`，则使用该环境变量指定的路径。
- 配置必须提供`data_workbook.url`和`formal_document.url`。前者是唯一的数据工作簿，读取其中全部日期命名且可见的周度工作表；后者是确认后的正式覆盖目标。
- 资源地址只允许保存在上述本地私有配置中，仅在运行时用于直接读取资源和生成原生表格链接对象；不得写入Skill正文、引用文件、日志、报告正文、提交或远程仓库。
- 配置缺失、字段缺失或地址无效时必须停止，不得搜索云文档、要求用户重新指定资源或自行补全地址。
- 常规更新必须先生成独立草稿文档。文档首段固定写为“基于AppMagic数据的全量历史周度数据整理，供审校确认。确认前不会覆盖正式市场分析文档。”其中“AppMagic数据”必须使用配置中`data_workbook.url`对应的原生表格链接对象，不得改成纯文本、普通超链接或其他文档链接。

## 隐私约束

- 固定资源地址、Wiki节点标识、账号标识、访问令牌、机器绝对路径和本地配置内容只保存在本机私有配置中，不得写入Skill、引用文件、示例、日志、报告正文、提交或远程仓库。
- 日志和验收反馈只输出校验状态、文件数量和提交范围，不输出实际资源地址、资源标识或配置内容。
- 发现历史文件、生成物或待提交内容出现上述信息时，先停止发布并完成清理；不得以当前工作区已清理代替历史和远程版本检查。

## 新建文档位置

- 涉及新建文档（包括更新草稿）时，如用户没有明确指定其他位置，严禁放入飞书云盘或任何文件夹；只能创建在“我的文档库”根目录。
- 使用 `lark-cli docs +create` 时，必须显式传入 `--parent-position my_library`。仅在用户明确指定目标文件夹、知识库或其他位置时，才可改用相应的 `--parent-token`。

## 必须先读

1. 读取`references/report-contract.md`和`references/analysis-framework.md`。
2. 执行`scripts/verify-local-resource-config.ps1`并读取本地私有资源配置，再直接读取配置绑定的AppMagic数据工作簿和固定目标文档；写入前不得使用未读取的资料。
3. 使用`lark-sheets`读取固定工作簿；仅在需要本地临时副本进行透视、聚合或公式核验时使用`spreadsheets`，不得写回来源工作簿。按`references/analysis-framework.md`进行分析推理，使用`lark-doc`创建和写入草稿文档，编辑已有画板时使用`lark-whiteboard`。
4. 整篇写作或重构前使用`doc-coauthoring`提交大纲和材料清单并等待确认；局部修改只改指定区块。
5. 每次更新先创建独立草稿文档；完成数据、图表、表格和可见渲染核验后，等待用户确认。仅在用户确认后，才覆盖固定目标文档并清理草稿文档。

## 工作流

1. 读取本地配置绑定的工作簿中全部日期命名且可见的周度工作表，并读取配置绑定的正式文档结构和样式。先创建独立草稿文档完成更新，不得直接覆盖固定目标文档。国家群组必须使用固定名单，不得自行增删、改名或重分层。
2. 统计“应用×周”记录、下载国和收入国的可用记录、Top5份额、缺失率和国家代码。
3. 按`US→T1→T2→T3`互斥归组；拉美、东南亚、IN是可重叠补充组。马来西亚归T3，美属萨摩亚仅保留一次。
4. 下载国Top5仅代表IAA用户规模与潜在广告库存偏好；收入国Top5仅代表IAP收入偏好。两项口径各说明一次。
5. 先执行分析框架：完成数据质量台账、趋势判断、异常归因假设、洞察和行动建议，并保存每条结论对应的指标证据。证据不足时只保留方向性观察或待验证动作。
6. 使用`doc-coauthoring`按已确认的结构组织数据、图表、分析和结论，并写入独立草稿文档；结论必须由本品类或群组数据支撑。
7. 在数据、口径和结论均已锁定后使用`deslop`检查分析文案。只删除空泛、重复或模板化表达，不得改动数字、固定术语、判断类型或行动建议。
8. 写入草稿前后都必须运行`scripts/verify-report-table-layout.ps1`：写入前校验待写XML，写入后用飞书回读的全文XML校验。校验失败仅作为内部修复信号，必须定位到具体表格、列或文本后自动调整，再次写入和回读；持续循环至全部通过。不得把校验失败直接反馈给用户，也不得在未通过时覆盖正式文档。仅当飞书接口不可用、资料缺失或约束相互冲突而无法继续时，才说明明确的阻塞原因。
9. 回读草稿全文，核对数据、7个一级章节、图表、画板、表格和空格规则，并等待用户确认。
10. 用户确认后再覆盖固定目标文档，复核正式文档可见渲染后清理草稿文档。

图表生成固定使用`templates/`中的批准版SVG模板、`references/chart-layout-contract.json`中的版式参数和`scripts/render-market-charts.ps1`渲染器。模型只提供结构化数据、日期和必要的文字，不得直接重新设计或手写四张图的SVG坐标；渲染器会依次运行字体归一化、布局归一化、顶部内容归一化和版式校验，任一校验失败都不得写入画板。

## 报告结构

1. 分析目的与分组边界：固定执行分组为US、T1、T2、T3、拉美、IN、东南亚；国家仅用于解释分组表现。
2. 数据范围、字段与计算口径：说明周期、品类、下载和收入字段、分组映射及覆盖率。
3. 全局分组概览：展示各分组的下载侧、收入侧、收入结构相对下载结构的差异、近期方向与可信度；全局结论仅作为品类判断的背景。
4. 品类×分组策略：每个品类明确分组优先级、目标类型（规模、收入或验证）、近期变化和建议动作。
5. 组内国家诊断：展示分组内国家构成、国家集中度、核心驱动国家和近期变化来源，用于判断分组结论的稳定性和泛化条件。
6. 执行规则与结论清单：汇总各品类应加码、维持、观察的流量组，并写明收入覆盖率或样本量不足时的使用限制。

## 固定表达与图表设计

除非用户明确要求改版，所有市场分析更新必须沿用以下术语、文字层级和图表版式；不得因单次更新自行更换设计风格、图表标题或指标命名。

以下规则是当前已确认的四张图表基准。后续更新只替换数据、日期和必要的说明文字，不重新设计图表结构、间距、对齐方式或视觉样式。

### 固定表达

- 统一使用“下载侧”“收入侧”“收入数据覆盖率”“Top5国家地区份额结构”“主分层”“可重叠观察组”。不得将Top5份额表述为实际下载量、广告结算收入、IAP结算额、eCPM或LTV。
- 数据范围统一写为“固定工作簿内全部日期命名且可见的周度工作表”，并同时写明实际周期、工作表数量和“应用×周”记录数。
- 趋势判断固定使用“方向稳定”“波动需结合收入数据覆盖率解读”“仅作为方向性观察”等边界表达；覆盖率偏低时，不作精确强弱排序。
- 分品类结论固定按“下载侧结构 → 收入侧结构 → 收入覆盖率 → 观察结论”的顺序表达；避免把单一品类结论泛化为全局规则。

### 统一视觉基础

- 所有图表当前批准版固定使用1600×980白色画布、浅灰分隔线、同一套中文字体和无衬线数字；根SVG固定为1640×1020，`viewBox`固定为`-20 -20 1640 1020`。确因新增周期或行数会裁切时，只允许沿Y轴增加高度，禁止增加画布、绘图区、根SVG宽度或任何横向坐标；四张图仍必须使用同一横向边界、边距和比例。禁止使用每张图不同的装饰背景、图标、圆角卡片风格或配色体系。
- 画布以信息密度优先：统一内容框上锚点距白色上边界36px、下锚点距白色下边界48px；普通内容不得超出白色边界，不得用压缩字体、上移内容或裁切文字解决溢出；折线图绘图区左右边距必须严格相同，不得保留无目的的大面积空白。
- 图表大标题左对齐并固定使用56px；标题、简介和首条上分隔线三者的绝对左边界统一为白色画布`x=50px`，标题下沿固定为绝对`Y=82.589px`，简介视觉中心固定为`Y=148.589px`，首条上分隔线固定为`Y=214.589px`，三者按`66px`等差距离定位，四张图均不得单独调整。图例单独一行并整体水平居中，相邻图例项间距不得小于24px。四张图必须沿用同一标题区、图例区、数据区和口径说明节奏。
- “下载侧”“收入侧”“品类”“收入覆盖率”等黑色分区标题固定使用36px。副标题、图例、注释、口径说明、坐标轴、刻度、普通分类标签和数据标签固定使用24px；图表内任何可见文字不得小于24px。
- 柱内数字固定使用24px常规字重，不得加粗；文字和文字框均以对应柱体或柱段为参照，在上下、左右两个方向严格居中。下载侧使用蓝色系，收入侧使用橙色系；主分层颜色固定为US紫蓝、T1青绿、T2浅蓝、T3深蓝、其他浅灰。
- 口径说明使用紧凑的浅色说明区，放在数据区下方；P2-P4的分隔线到注释文本框保持`18.0348px`固定间距，注释文本框底部统一落在白色画布下边界上方`48px`的固定内容锚点（绝对`Y=932px`）。P2口径说明固定使用“口径：收入数据覆盖率表示有收入国Top5信息的应用×周记录比例；覆盖率偏低时，收入侧仅作方向性观察。”不得删减或改写含义。P4必须联动调整数据区、四行边界和注释区，保持行高、行距和上下边界一致，不得只移动注释、压缩最后一行或让内容超出白色画布；不以单次图表的空白区域作为对齐基准，不得留下无目的的大面积空白。
- 四张SVG必须由`scripts/render-market-charts.ps1`从固定模板和结构化数据生成；渲染器内部依次运行`scripts/normalize-chart-typography.ps1`、`scripts/normalize-chart-layout.ps1`和`scripts/normalize-chart-top-content.ps1`，统一56/36/24字号、柱内字重、固定画布、标题间距、首条上分隔线到首个图例/内容锚点的49px间距和各图对齐方式；随后运行`scripts/verify-chart-layout.ps1`，通过后再完成PNG目视检查与远端回读检查。验收失败时不得写入画板或覆盖正式文档。示例数据结构见`examples/current-report-data.json`，后续只替换数据，不重新绘制SVG。

### 四张固定图表

1. **全球主分组结构**：标题固定为“全球主分组结构”，使用下载侧/收入侧两根100%堆叠柱，但图中不得显示“100%堆叠”文字。图例固定为“US、T1、T2、T3、其他”，整行居中且必须完整显示；柱内展示四个主分层数值，“其他”在柱外紧贴标注。“下载侧”“收入侧”的柱上标题和柱下标题均以对应柱体水平中心为准；上方标题至柱顶的距离必须与柱底至下方标题的距离相等；柱内数据必须按各柱段的实际矩形中心动态计算，文字和文字框上下、左右居中。
2. **全部周期重点分组变化**：标题固定为“全部周期重点分组变化”，使用固定工作簿内全部日期命名且可见的周度工作表，不得截取10周或任意短窗口；使用三条折线：下载侧T3、收入侧US+T1、收入数据覆盖率。副标题固定说明实际日期范围、按周统计和单位；不额外使用与图表内容重复或不完全匹配的概览卡片。横轴按统一间隔标注，绘图区距白色画布左右边缘必须相同。最新周只保留一组与曲线颜色、内容完全匹配的末端标签；横轴下方日期单独成行，下载侧T3、收入侧US+T1和收入数据覆盖率三组末端名称与数值共用同一水平中心线，并在各自文字框内水平、垂直居中；三组末端标签的文字可见边缘必须满足“日期文字底部→末端标签顶部”与“末端标签底部→口径说明上方分隔线”距离相等，不以文字中心点相等替代视觉距离相等；标签不得越过白色边界，不保留连接线。
3. **各品类主要分组方向**：标题固定为“各品类主要分组方向”，每个品类两条横向条形：下载T2+T3、收入US+T1；右侧固定显示收入覆盖率。“品类”标题与全部品类名在品类列内水平居中，列中心固定为版式坐标`X=136.5`；“收入覆盖率”标题与全部覆盖率数据在收入覆盖率列内水平居中，列中心固定为版式坐标`X=1354.5`。七个数据行必须等高；列标题与第一行数据的留白独立计算，不得计入Launcher行高。每个数据行必须以该行上下分隔线的中点为纵向中心，品类名、两根柱、柱末数据和收入覆盖率作为整体同步移动，不得只校正第一行。最后一行“超休闲”下方必须有一条贯穿品类、绘图区和收入覆盖率列的浅灰边界线。图例、列名、占比刻度与第一行数据必须留出独立行距；百分比刻度统一放在图表底部，数值仅保留柱末标签和右侧覆盖率，避免重复。
4. **补充地区组下载与收入偏好**：标题固定为“补充地区组下载与收入偏好”，下载侧与收入侧使用对称横向条形，固定展示US、IN、拉美、东南亚。四个地区行等高且上下等距，行间分隔线按相邻行中心中点定位，US行上方必须补充与行间线同样样式的首行上边界，内容与上下边界的间距统一；保留四行现有中心位置，不得通过整体上移压缩首行空间；最后一行下边界与注释上方分隔线重合，底部只向下扩展内容区，使四行上下留白一致；地区名在中间标签列内水平、垂直居中；下载侧柱内数值统一右对齐，收入侧柱内数值统一左对齐，均以原12px为基准向各自柱边界内增加5px，固定为17px内边距并垂直居中；口径说明固定采用P2、P3的上分隔线加左对齐普通注释格式，明确“IN、拉美、东南亚为可重叠观察组，不与主分层相加；US为主分层，仅为对照纳入此图”，不使用独立卡片或边框。

## 格式硬约束

- 使用平铺直叙、简明中文，按数据、解释、行动结论的顺序表达。
- 面向用户的进展说明先写已完成的结果，再用自然语言说明改动、验证范围和未执行的事项。避免“接入能力”“固化框架”“洞察合成”“证据台账”等抽象表述；需要提及文件或工具时，说明它解决的问题，不把文件路径或工具名当作句子的主语。
- 未读取实际数据或未更新飞书文档时，直接说明“本次未读取实际数据，未改动飞书文档”。不得用泛化的“未执行实际数据读取”替代。
- 验证说明只写已实际执行的检查和结果；不将格式检查、脚本通过或写入成功表述为已完成全部分析。
- 正文、列表和表格仅允许连续英文词组内部存在空格；中文与英文、代码、数字、百分号、日期单位或中文标点之间不得保留空格。图表中“分组代码+数值”必须保留一个空格，例如“US 9.5%”。
- 草稿写入后必须回读全篇，并对正文、列表和表格逐块扫描空格；发现不符合上述规则的空格时，必须在草稿中修正并再次回读，不能仅核对章节、图表和表格数量。
- 图表使用深色柱形或堆叠柱形；柱内文字使用24px常规字重并水平、垂直居中；图例色块和文字整体居中。
- 图表标签在空间足够时必须单行；所有可见文字最小24px；纵坐标刻度使用统一右对齐边界。
- 分析用浅蓝高亮块，结论用浅绿高亮块，各用2至3条有序项。
- 表格不额外加色、不做过宽；写入时逐列显式设置水平对齐，表头和品类列水平、垂直居中，分析和结论正文左对齐、垂直居中；写入后逐表回读核验，不能依赖编辑器默认样式。
- 五张固定表格总宽度统一为`820px`，与画板和高亮块一致。短标签、品类、分组、数值和百分比列必须单行且居中；仅“分组角色”“解读动作”“近期信号”“当前动作”“分组角色与国家诊断”“执行结论”等说明列可换行并左对齐。
- 固定列宽依次为：全球主分组表`100/115/115/115/115/260`；全部周期趋势表`150/95/95/95/110/275`；分品类决策表`150/100/100/130/150/190`；补充地区组表`120/105/105/105/105/280`；各品类重点群组表`150/110/110/130/320`。表头、标题列和所有短数据单元格不得插入换行符。
